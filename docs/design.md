# 빠지 타이쿤 — 상세 기획서 (v4)

## Context

가평 강변 리조트를 키우는 모바일 경영 시뮬레이션. 여름의 "빠지"(수상 구조물)가 주력이고 사계절 운영한다.

**이 문서가 필요한 이유.** v1(자유 배치 + 실시간 + 자유 스플라인 코스)로 Phase 0~2 를 구현했으나,
검증 과정에서 세 가지 근본 결함이 드러났다:

1. **소재가 너무 작다** — 게임 오브젝트가 11종. 타이쿤의 수명은 "다음에 뭐가 열리지"가 만드는데 한 시간이면 동난다.
2. **실시간이 폰에 안 맞는다** — 지속적 주의를 요구해 2분 세션에서 성립하지 않는다.
3. **깊이가 얕다** — 자유 배치의 결정은 사실상 *거리*뿐, 자유 스플라인은 *얼마나 급하게 돌릴지*뿐.
   실측에서 대충 그린 작은 사각형에 **스릴 100(만점)** 이 찍혔다. 설계할 여지가 없다는 신호.

**v2 에서 방향을 바꿨고(소재 확장·주 단위·연결식 구조물), 이 v3 는 그것을 구현 가능한 수준까지 상세화한다.**
코스는 v3 작업 중 다시 한 번 바꿨다 — 조각 조합은 폰에서 탭이 너무 많아 **프리셋 + 터닝포인트**로 (§7.1).
v2 는 개요 수준이라 실제로 만들 수 없었다 — 첫 한 시간, 시설 수치, 콤보 목록, 연구 트리,
경제 공식, 화면 상태 전이가 전부 비어 있었다.

**전제**
- 코드·에셋 전부 AI 제작. Claude Code 로 세션을 이어감
- 세로 모바일 최우선. 웹/PWA → Capacitor
- 아트: 지금은 절차적 스프라이트, 나중에 AI 픽셀아트로 일괄 교체 (경로 이미 구축됨)

**실측으로 확정된 것** (Phase 0~2)
- 손님 1,200명 = 0.6ms/frame · 200명 = tick당 0.024ms → **게임 내 1주 = 0.6초**
- 코스 실측 처리량이 예측 지표의 ±20% 이내 (지표가 거짓말하지 않음)
- 모바일 자동 검증 전 항목 통과 (부팅·WebGL·터치 타깃·배치·핀치줌)

# 1. 개요

## 1.1 한 줄 정의

> **한정된 강변에서 리조트를 키우는 경영 시뮬. 구조물을 이어 붙여 확장하고, 여름 성수기에 처리량과 안전을 조율한다.**

## 1.2 핵심 루프 (30초)

```
[한 주 진행] ──0.6초──▶ [주간 결산]
      ▲                     │
      │                     ├─ 병목 확인 (매점 대기 12명)
      │                     ├─ 발견 (🎉 새 콤보)
      │                     └─ 해금 알림 (연구P +48)
      │                     ▼
      └──────────── [구조물을 키우거나 붙임]
```

## 1.3 세 기둥

| 기둥 | 무엇 | 어디서 |
|---|---|---|
| **구조물 성장** (깊이) | 데크·건물을 이어 붙여 키운다 | 건설 모드 |
| **발견·수집** (훅) | 콤보 도감, 연구 해금 | 결산 → 도감 |
| **처리량 조율** (긴장) | 여름 성수기의 대기줄·안전 | 결산 리포트 → 조정 |

## 1.4 핵심 긴장

> **한정된 강폭 안에서 처리량 ↔ 안전 ↔ 만족의 삼각 트레이드오프**

- 데크를 넓히면 수용력↑ 이지만 **부력 하중** 한도와 **수면 면적**이 제약
- 장비를 늘리면 처리량↑ 이지만 **코스 밀도**로 안전도↓
- 코스를 험하게 그리면 스릴↑ 이지만 안전↓, 멀미로 일부 손님 이탈

## 1.5 게임플레이 동사 (⚠ 콘텐츠를 시설 수로 세지 않는다)

**v3 의 오류:** "시설 11종 → 81종"을 성과처럼 적었다. 그러나 화장실·샤워실·탈의실·락커·수유실은
플레이어 입장에서 **같은 동사 하나**다. 콘텐츠는 시설 수가 아니라 **동사 수**로 센다.

| 동사 | 무엇 | 깊이의 출처 |
|---|---|---|
| **짓는다** | 시설·모듈 배치 | 지형·경관·콤보·동선 |
| **잇는다** | 데크 확장 · 건물 증축 · 통로 연결 | 연결 규칙 · 허가 면적 · 하중 |
| **코스를 그린다** | 프리셋 + 터닝포인트 | 장비×프리셋 적합도 · 지형 |
| **의뢰를 받는다** ★신규 | 단체·행사·특수 손님 | 조건 충족이 곧 목표가 됨 |
| **값을 매긴다** | 가격 조정 | 탄력성 · 손님층 |
| **사람을 쓴다** | 직원 고용·배치 | 고정비 · 커버리지 |

**총 6개. 여기서 더 늘리지 않는다.**
Kairosoft 계열의 검증된 동사 수는 3~4개다. 동사는 적고 깊은 편이 낫다.

> 재고관리 · 식자재 · 직원 스킬트리 · 대출 · 세금 · 차량 물류는 **넣지 않는다.**
> 혼자 만드는 게임에서 즉시 과해진다.

# 2. 첫 한 시간 (분 단위)

이 절이 이 문서에서 가장 중요하다. **이게 안 써지면 시스템을 아무리 잘 만들어도 안 된다.**

## 0:00 — 0:03 · 물려받은 빠지

- 봄 1주차. 자금 ₩30,000,000. **아버지가 하던 작은 빠지**를 물려받았다.
- 화면에 이미 있는 것: 주차장 · 진입로 · 낡은 매표소 · **데크 2칸 + 선착장 + 땅콩튜브 1대**
- `▶ 한 주 진행` → 0.6초 → **결산**
  ```
  봄 1주차 결산
  방문객 38명   매출 ₩520,000   만족도 47%
  ⚠ 화장실이 없어 불만 (만족 −14)
  ⚠ 코스가 너무 밋밋하다 (재미 −8)
  🔬 연구P +6
  ```
- **문제를 결산이 지목한다.** 튜토리얼 화면이 아니라 결산이 가르친다.

## 0:03 — 0:08 · 첫 코스 조정 ★ 시그니처

- 결산의 `코스가 너무 밋밋하다` 를 탭 → 바로 코스 편집으로 진입
- 물려받은 **왕복** 코스에 핸들 ◉ 2개가 보인다
- 핸들을 **좁게 끌어본다** → 지표가 즉시 반응:
  ```
  처리량 24 → 22명/h   스릴 18 → 41   안전도 94 → 71
  ```
- **트레이드오프를 손가락으로 배운다.** 5분 지점에 이 게임의 핵심을 만졌다.
- 형태를 **[원형]** 으로 바꿔보면 길어지고 스릴이 오르지만 처리량이 떨어진다

## 0:08 — 0:15 · 첫 건물, 첫 콤보

- 화장실 설치 → 다음 주 만족 47% → 61%, 방문객 38 → 52명
- **인과가 한 사이클 안에서 닫힌다**
- 샤워실을 놓으려 하면 **화장실 옆 초록 ⊕** → *"기존 동에 증축 (40% 저렴)"*
- 붙이는 순간: **🎯 「물놀이 후」 발동 — 만족 +9** (소형 콤보)
- 결산에서: **🎉 새 콤보 발견** → 도감 3/70

## 0:15 — 0:25 · 빠지를 키운다

- 결산: *"선착장 대기 9명 — 데크가 좁다"*
- 데크 옆 ⊕ 를 탭 두 번 → 2칸 → 4칸
- **수면 사용 허가 18/40 타일** 게이지가 처음 등장 — 무한히 못 늘린다는 걸 안다
- 데크 위에 **그늘막** 을 얹으면 **「그늘 한 자락」** 콤보

## 0:25 — 0:35 · 첫 이벤트 카드

- 주 진행 직전 카드가 뜬다:
  ```
  📋 단체 예약 문의 (40인)
  [받는다]  매출 +₩1,200,000, 이번 주 혼잡 +35%
  [거절]    만족 유지, 평판 −3
  ```
- 받으면 결산이 붉어진다: *"토요일 선착장 대기 28명"*
- **선택에 결과가 따라온다는 걸 배운다**

## 0:35 — 0:45 · 여름이 온다

- 봄 13주가 지나며 자금이 쌓이고, **여름 1주차** 진입 연출
- 방문객이 **3배**로 뛴다. 결산이 갑자기 붉어진다:
  ```
  여름 1주차
  방문객 620명 (▲340)   매출 ₩8,200,000
  ⚠ 토요일 선착장 대기 34명 — 처리량 부족
  ⚠ 매점 앞 대기 21명
  만족도 58% (▼9)
  ```
- **성수기가 진짜 시험이라는 걸 배운다.**

## 0:45 — 1:00 · 첫 진짜 결정

플레이어 앞에 놓인 선택지 (돈은 ₩24,000,000, 전부는 못 함):

| 선택 | 효과 | 대가 |
|---|---|---|
| 장비 +2대 | 처리량 22 → 66명/h | 안전도 92 → 74. 사고 위험 |
| 데크 +4칸 | 수용 인원↑, 그늘막 얹을 자리 | 하중 62/100 → 여유 없음 |
| 매점 증축 | 대기 해소, 매출↑ | 코스 대기는 그대로 |
| 안전요원 고용 | 사고 확률 −60% | 주 ₩400,000 고정비 |

- **정답이 없다.** 무엇을 포기할지가 결정이다.
- 어느 쪽을 골라도 다음 주 결산이 결과를 알려준다.
- 1시간 지점에 **도감 11/70, 연구 5/42, ★1 → ★2 임박** — 남은 게 눈에 보인다.

## 왜 내일 또 켜는가

1. **도감이 11/70** — 59개가 미발견 상태로 힌트만 보인다
2. **★2 가 3주 남았다** — 등급이 오르면 대형 플랫폼이 열린다
3. **여름이 10주 남았다** — 이번 성수기 성적이 내년 규모를 정한다
4. **저 결정이 옳았는지** 다음 주 결산에서만 알 수 있다

# 3. 시간 · 계절 · 날씨

## 3.1 시간 단위

| 단위 | 값 | 비고 |
|---|---|---|
| tick | 0.1초 (10Hz) | 시뮬 최소 단위 |
| 게임 내 1일 | 3,600 tick | 영업 10시간 → 360 tick/시간 |
| **게임 내 1주** | **25,200 tick ≈ 0.6초 실시간** | **진행의 단위** |
| 1년 | 52주 | |

플레이어는 **주 단위로만** 시간을 움직인다. `▶ 한 주 진행` 한 번 = 0.6초 시뮬 + 결산.
`▶▶ 4주 진행` 도 제공 (겨울처럼 한가할 때).

## 3.2 계절

| 계절 | 주차 | 방문객 계수 | 주력 | 성격 |
|---|---|---|---|---|
| 봄 | 1~13 | **0.55** | 캠핑 · 낚시 · 산책 | 여름 대비 증설 |
| **여름** | **14~26** | **1.00** | **수상레저 · 빠지** | **매출 58%. 조율의 계절** |
| 가을 | 27~39 | 0.50 | 캠핑 · 단풍 · BBQ | 정비, 설계 |
| 겨울 | 40~52 | **0.15** | 펜션 · 빙어낚시 | **대규모 공사 시기** |

**⚠ 비수기는 콘텐츠가 아니라 압축 구간이다 (v4 수정)**

*"사계절을 다 만들면 캠핑 타이쿤·펜션 타이쿤·빙어낚시 타이쿤을 각각 만들어야 한다"* 는
지적이 절반 맞다. 다만 **연 단위를 없애면** 연말 등급 심사·성장 곡선·계절 리듬이 다 흔들린다.

> **MVP 는 여름을 완성하고, 비수기는 압축한다.** 사계절 콘텐츠는 검증 후 확장.

| 구간 | MVP 처리 |
|---|---|
| **여름 13주** | **완전 구현.** 주 단위 진행 + 압축 연출 + 이벤트 + 의뢰 |
| 봄·가을 각 13주 | 주 단위 진행하되 이벤트 빈도 낮음. 캠핑·낚시 시설은 있음 |
| **겨울 13주** | **`▶▶ 4주 진행` 이 기본.** 방문객 최소, 건설·연구·계약이 주 활동 |

- 겨울 전용 시설(빙어낚시·눈썰매·붕어빵·온수족욕)은 **데이터로만 넣어두고 Phase E 이후 활성화**
- 4주 진행 중 이벤트·의뢰가 뜨면 **자동 정지**
- 겨울 결산은 **4주 묶음**으로 표시

**MVP 범위 판정: 여름이 재미없으면 사계절을 만들어도 소용없다.**

**설계 의도:** 여름만 바쁘고 겨울은 한가한 구조가 "바쁠 때 조율 / 한가할 때 건설"의 리듬을 만든다.
겨울은 손님이 없어 공사로 인한 만족도 하락 부담이 없다.

## 3.3 요일 가중 (한 주 안에서)

| 요일 | 계수 |
|---|---|
| 월~목 | 0.55 |
| 금 | 0.90 |
| 토 | **1.75** |
| 일 | 1.35 |

주 평균 ≈ 0.88. **토요일 병목**이 결산 리포트의 단골 항목이 된다.

## 3.4 날씨

주간 예보를 **한 주 앞서** 보여준다. 대비 가능해야 선택이 된다.

| 날씨 | 확률(여름) | 방문객 | **수요가 어디로 몰리나** |
|---|---|---|---|
| 맑음 | 45% | ×1.00 | 고르게 |
| 폭염 | 20% | **×1.25** | **수상레저 ↑↑ · 아이스크림 ↑↑ · 그늘 ↑↑ · 샤워 ↑** |
| 흐림 | 20% | ×0.80 | **캠핑 ↑ · 낚시 ↑ · BBQ ↑** (더위가 없어 야외 활동 유리) |
| 비 | 12% | ×0.30 | **카페 ↑↑ · 사우나 ↑↑ · 온수풀 ↑ · 실내 모듈 ↑** |
| 호우·강풍 | 3% | ×0.05 | 전면 중단. 구조물 손상 확률 8% |

**⚠ 날씨는 벌칙이 아니라 수요 구성의 변화다 (v4 수정)**

v3 는 날씨를 **방문객 배수**로만 다뤘다. 그러면 비·호우가 그냥 **RNG 세금**이 된다.

> **모든 날씨에 돈 벌 방법이 있어야 한다.**

- **비 오는 날** — 수상은 죽지만 카페·사우나·온수풀이 산다.
  실내 연결 건물이 있으면 손님이 안 빠진다(이탈 −40%)
- **흐린 날** — 더위가 없어 캠핑·낚시·BBQ 가 오히려 유리
- **폭염** — 방문객은 최대지만 그늘·물이 부족하면 만족이 무너진다

→ **"어떤 날씨에도 대비된 리조트"** 를 만드는 게 목표가 된다.
한쪽으로만 특화하면 특정 날씨에 크게 흔들린다.

겨울은 눈·한파가 추가되며, 한파에는 온수풀·빙어낚시 수요가 폭증한다.

# 3.5 주간 의사결정 (⚠ 루프를 지탱하는 장치)

## 왜 필요한가

**적대적 검증에서 발견한 최대 결함:** 시설을 20개쯤 지으면 플레이어가 할 게 없어지고,
`한 주 진행` 이 **스킵 버튼**으로 전락한다. 방치형 게임의 전형적 붕괴다.

> **매주 1~2개의 선택을 강제한다.** 선택은 결산 직전에 카드로 뜬다.

# 3.6 주간 진행 연출 (⚠ v4 핵심 수정)

## 왜 바꾸나 — v3 의 논리 비약

v3 는 이렇게 썼다:

> "tick당 0.024ms로 측정됐다. 1주 = 0.6초. **즉 이 구조가 공짜로 가능하다.**"

**성능 측정을 UX 결정의 근거로 잘못 연결했다.**
"0.6초에 *계산*된다"가 "0.6초 동안 *보여준다*"가 되는 건 아니다.

그 결과 이 게임의 가장 강력한 시각적 보상 —
**내가 만든 공간에 손님이 우글거리고 보트가 달리는 광경** — 이
핵심 플레이가 아니라 선택형 리플레이(S10)로 밀려났다.

> **계산 0.6초 이하 / 연출 3~5초 로 분리한다.**

## 진행 흐름

```
[▶ 한 주 진행]
      ↓
  ① 계산      0.6초 (백그라운드, 화면엔 안 보임)
      ↓
  ② 하이라이트 선별   계산 결과에서 "볼 만한 순간" 3~5개 추출
      ↓
  ③ 압축 연출  3~5초  ← 여기가 새로 생긴 부분
      ↓
  ④ 결산
```

**계산을 먼저 끝내고 하이라이트를 뽑아 재생**한다. 실시간 시뮬을 보여주는 것이 아니다.
그래서 카메라 연출을 자유롭게 짤 수 있고, 지루한 구간을 건너뛸 수 있다.

## ③ 압축 연출의 내용

```
월화수목금  ─────  약 1초 (빠르게 흐름, 손님이 드문드문)

토요일     ─────  약 2.5초 (카메라가 사건으로 이동)
   ⚠ 선착장 A 대기 28명        ← 카메라 줌인
   🎉 수상놀이터 최고 기록      ← 카메라 이동
   💰 BBQ존 매출 신기록

일요일     ─────  약 1초

[결산으로]
```

- **카메라가 사건 지점으로 이동**하며 라벨이 뜬다
- 손님·보트는 **실제 시뮬 결과대로** 움직인다 (연출용 가짜가 아님)
- 화면 아무 곳이나 탭하면 **즉시 결산으로 스킵**
- 설정에서 `연출 끄기` 가능 (반복 플레이 배려)

## 하이라이트 선별 규칙

| 우선순위 | 사건 |
|---|---|
| 1 | 신기록 (매출·방문객·특정 시설) |
| 2 | 심각한 병목 (대기 20명 이상) |
| 3 | 사고·고장 |
| 4 | 새 콤보 발동 |
| 5 | 날씨 급변 (소나기·폭염) |
| 6 | (사건이 없으면) 가장 붐빈 구역을 한 바퀴 |

## ⚠ 이것만으로는 부족하다 (적대적 검증)

100주째에 플레이어는 연출을 스킵한다. 스킵하면 다시 결산표 게임이 된다.
따라서 **결산 화면 자체도 시각적이어야 한다** — §15.6 참조.

# 4. 맵 · 지형 · 토지

## 4.1 크기

**v1 의 64×64 는 폰에서 너무 컸다.** 전체가 안 보이면 배치 판단이 안 된다.

| 구획 | 크기 | 해금 |
|---|---|---|
| 시작 구획 | 24×32 타일 | 처음부터 |
| 확장 A (우측) | +16×32 | ★2 + ₩40,000,000 |
| 확장 B (좌측) | +16×32 | ★3 + ₩80,000,000 |
| 확장 C (상류) | +24×24 | ★4 + ₩150,000,000 |
| 최대 | 약 56×56 | |

타일 16px, 기본 줌 2× → 화면(393×852)에 **12×26 타일**이 보인다.
시작 구획(24×32)은 **세로로 스크롤 한 번**이면 전부 본다.

## 4.3 맵 생성

시드 기반 결정론 생성(구현 완료). 구획마다 강폭·수심 분포·경사지 비율이 다르다.
→ **"이 맵은 강이 넓으니 제트스키 중심"** 같은 판단이 생긴다.

## 4.4 시작 상태

플레이어는 **완전히 빈 땅**에서 시작하지 않는다. 손님이 어디서 오는지 모르면 동선 판단이 안 된다.

**설정: 아버지가 하던 작은 빠지를 물려받았다.**

| 미리 놓여 있는 것 | 이유 |
|---|---|
| **도로** (맵 상단 가장자리 지형) | 접근 방향을 고정 |
| **주차장** 1개 (도로 인접, 철거 불가) | **손님이 여기서 걸어 들어온다.** 동선의 출발점 |
| **진입로** 길 3~4칸 | 주차장에서 부지 안쪽으로 |
| **매표소** (낡음) | 최소한의 영업이 이미 돌아간다 |
| **데크 2칸 + 선착장** | ⚠ **시그니처 메커닉을 5분 안에 만나게 하려고** |
| **낡은 땅콩튜브 1대** | 코스가 이미 하나 있다 (형태: 왕복) |

> **왜 빠지를 미리 주나 (적대적 검증 결과):** v3 초안은 코스를 **25분**에 만나게 했다.
> 10분 하고 끄는 사람은 이 게임의 시그니처를 아예 못 본다.
> 작은 빠지를 미리 주면 **5분 안에 코스를 그려보게** 되고, 2칸→12칸으로 키우는 성장감은 그대로다.

**첫 결정들**
1. 물려받은 코스의 **터닝포인트를 조정**해본다 (시그니처 체험)
2. 화장실이 없다 — 어디에 둘 것인가
3. 매표소가 주차장에서 먼가 가까운가

자금 **₩30,000,000**, 봄 1주차, 강변 1구획(24×32), 평판 ★1, 연구P 0.

**시작할 때 리조트 이름을 짓는다.** (기본값 제안: `○○ 썸머웨이브`, `강마을 빠지`)
이름은 최대 축소 화면·결산·공유 이미지에 계속 나온다 — **애착의 출발점**이다.

# 5. 연결식 구조물 — 수상 (빠지)

**이 게임의 코어.** 실제 빠지가 부잔교를 이어 붙여 만드는 것을 그대로 메커닉화한다.

## 5.1 데크

| 등급 | 칸당 비용 | 하중 | 해금 | 비고 |
|---|---|---|---|---|
| 기본 부잔교 | ₩1,200,000 | 100 | 연구 40P | |
| 강화 부잔교 | ₩2,600,000 | 180 | ★2 + 연구 120P | 강풍 손상 −60% |
| 대형 플랫폼 | ₩4,500,000 | 320 | ★4 + 연구 300P | 2층 구조 가능 |

**연결 규칙**
1. 데크는 **육지 워크웨이** 또는 **다른 데크**에 인접해야 설치 가능
2. 워크웨이는 강변(shore) 타일에서 시작
3. 데크 그룹이 육지와 끊기면 **고립 경고** → 손님이 못 옴
4. 부표 경계 밖 불가

**수면 사용 허가 (진짜 제약)**

강은 공유 자원이다. 지자체가 **사용 가능 수면 면적**을 등급별로 허가한다.

| 등급 | 허가 면적 | 대략 |
|---|---|---|
| ★1 | 40 타일 | 데크 6칸 + 고정시설 1~2개 |
| ★2 | 90 타일 | 데크 12칸 + 시설 3개 |

```
사용 면적 = Σ(데크 칸) + Σ(고정 수상시설 면적) + Σ(코스 점유 면적 × 0.3)
```

**돈으로 못 산다. 등급으로만 늘어난다.** → "한정된 강"이 진짜 제약이 되고, 등급이 실질 병목이 된다.

**부력 하중 (보조 제약)**
```
사용 하중 = Σ(적재물 하중) + Σ(부착물 하중) + (동시 인원 × 2)
한도    = Σ(데크 칸 × 등급별 하중)
사용률 100% 초과 → 침수 위험, 사고 확률 +40%/주
```
하중은 **한 데크에 시설을 몰아 얹는 것**만 막는다. 주 제약은 위의 허가 면적이다.

> **왜 바꿨나:** 적대적 검증에서 하중이 안 문다는 걸 발견했다. 데크 4칸(하중 400)이면
> 선착장+매점+그늘막+슬라이드(76)에 인원 162명까지 가능한데, 그만한 인원은 초반에 안 온다.
> 게다가 데크가 ₩1.2M 로 싸서 부족하면 그냥 더 깔면 그만이었다.

## 6.3 높이 표현 (그래픽 전용)

**로직에는 층 개념이 없다.** 바닥 면적(footprint)만 타일을 차지한다.
다만 스프라이트는 위로 더 클 수 있어서, **2~3층 건물을 그림으로 표현**한다.

```
      ▓▓▓▓      ← 3층 (스프라이트만, 타일 안 먹음)
      ▓▓▓▓      ← 2층
      ▓▓▓▓      ← 1층
      ████      ← 바닥 footprint = 실제 점유 타일
```

| 규칙 | 내용 |
|---|---|
| 앵커 | bottom-center. 바닥이 타일에 붙고 위로 자란다 |
| 스프라이트 높이 | `footprint높이 × 16px + 층수 × 14px` |
| 깊이 정렬 | **바닥 y 기준** (이미 구현됨) — 아래쪽 건물이 위쪽을 가린다 |
| 가림 처리 | 손님이 뒤에 가려도 그대로 둔다. 확대 시 앞 건물을 반투명 처리하지 않는다(폰에서 산만) |

**층수가 있는 시설**

| 시설 | 층수 | 비고 |
|---|---|---|
| 펜션 | 3 | 리조트의 랜드마크 |
| 카라반 | 1 | 낮고 길다 |
| 글램핑 | 1 | 텐트형 |
| 카페 | 2 | 2층 전망석 |
| 종합동(모듈 4개 이상) | 2 | 모듈이 늘면 자동으로 2층 표현 |
| 전망대 | 3 | 경사지 전용 |
| 매표소·화장실·샤워실 등 | 1 | |

**로직에 미치는 영향은 딱 하나 — 경관 점수.**

```
경관 점수 = Σ(시설 층수 × 2) + Σ(조형물·화단·나무) − Σ(창고·정화조 등 미관 감점)
```
경관 점수는 **커플·가족 만족도**와 **「포토존」·「리버뷰 펜션」 콤보 조건**에 쓰인다.
층을 올린다고 수용 인원이 늘지는 않는다 — 그래픽과 경관만이다.

> **설계 의도:** 높이를 로직에 넣으면 (계단·엘리베이터·층별 동선) 폰에서 감당이 안 된다.
> 그림으로만 표현해 **"리조트가 커 보이는"** 효과만 취한다.

# 7. 수상 코스 (프리셋 + 터닝포인트)

## 7.1 왜 조각 조합을 버렸나

v3 초안은 조각 8종을 이어 붙이는 방식이었다. 깊이는 있지만 **모바일에서 탭이 너무 많다** —
코스 하나에 조각 5~8개를 고르고, 순서를 바꾸고, 취소하고… 폰에서 할 짓이 아니다.

> **바꾼 방식: 형태 프리셋을 고르고, 물 위의 터닝포인트 2~4개를 손가락으로 끈다.**

- 조작이 **프리셋 탭 1번 + 핸들 드래그 2~4번**으로 끝난다
- 핸들이 크므로 손가락으로 정확하다
- **"물 위에 코스를 그린다"는 감각이 살아난다** (목록에서 고르는 것보다 이 소재에 맞다)
- 이미 구현된 스플라인·곡률 수학을 **그대로** 쓴다

깊이는 프리셋 종류 × 핸들 위치 × 장비 × 대수로 확보한다.

## 7.3 터닝포인트 조작

```
프리셋 선택 → 물 위에 핸들 2~4개가 자동 배치 (선착장 기준)
              ↓
        핸들을 드래그해 위치 조정
              ↓
        지표 4칸이 실시간 갱신
```

- 핸들은 **화면상 지름 36px** (터치 여유). 드래그 중 손가락에 가리지 않게 살짝 위로 오프셋
- 유효하지 않은 위치(육지·얕은 물·시설 위)로 끌면 **핸들이 빨개지고** 지표에 사유 표시

- 핸들을 좁히면 회전이 급해진다 → **곡률이 올라가 스릴↑ 안전↓** (기존 곡률 수학 그대로)

## 7.6 지표 공식

```
소요시간(cycle) = 코스길이 / 장비속도 + 승하차 tick
스릴           = clamp(프리셋기본 + 최대곡률×90×속도계수, 0, 100) × 장비 스릴계수
처리량(명/h)   = (360 / cycle) × 정원 × 장비대수
안전도         = clamp(100 − 급회전비율×55 − 밀도벌점 − 교차벌점 − 유속벌점, 0, 100)
  밀도벌점     = max(0, (장비대수 / (코스길이/12) − 1) × 28)
  교차벌점     = 다른 코스와 겹치는 비율 × 40
멀미도         = clamp((스릴 − 62) × 1.6, 0, 100)
```

**장비 대수가 처리량 vs 안전의 핵심 다이얼.** (실측 검증 완료: 대수 2배 → 실측 처리량 2배)

## 7.7 제약

- 시작점이 **선착장에 3타일 이내**
- 스플라인 전 구간이 장비의 최소 수심 충족
- 부표 경계 내
- 다른 수상 시설을 통과 불가 (선착장 제외)
- 프리셋별 **필요 수면**을 만족해야 선택 가능 (좁은 강에서는 8자·지그재그가 회색)

# 8. 콤보 도감

**Kairosoft 공식의 심장.** 인접·구성으로 발견되고 목록에 수집된다.
미발견은 **힌트만** 보인다 (`매점 + ? + ?`).

## 8.0 3티어 구조 (⚠ 발동 빈도가 훅을 만든다)

**적대적 검증 발견:** 시설 81종에 콤보 28종이면 **대부분의 배치가 아무 콤보도 안 낸다.**
"발견"이 훅인데 훅이 안 걸린다.

> **티어를 나눠 총 70종으로 늘린다.** 작은 건 자주 터지고, 큰 건 드물게 크게 터진다.

| 티어 | 개수 | 조건 | 효과 크기 | 발동 빈도 | 중복 |
|---|---|---|---|---|---|
| **소형** | 40 | 2개 인접 | +5 ~ +12% | 거의 매번 | 누적 가능 |
| **중형** | 20 | 3~4개 조합 | +15 ~ +30% | 몇 주에 한 번 | **체감** |
| **대형** | 10 | 까다로운 조건 | +30 ~ +60% | 게임당 몇 번 | **리조트당 1회** |

## 8.0.1 중복 제한 (⚠ 도배 방지)

**적대적 검증에서 발견한 결함:** 「평상 야식 세트 +30%」를 알게 된 순간부터
플레이어는 **그 조합을 10번 복사**하는 게 최적해가 된다.
그러면 공간 창작이 죽고 "공략표 도배 게임"이 된다.

| 티어 | 규칙 |
|---|---|
| 소형 | 누적 가능 (작은 효과라 도배해도 무해) |
| **중형** | **1회 30% → 2회 15% → 3회 5% → 4회부터 0%** |
| **대형** | **리조트당 1회만 적용** |

→ 콤보가 **"건축 퍼즐"** 로 남고 **"도배 전략"** 이 되지 않는다.
같은 걸 복사하는 것보다 **새로운 조합을 찾는 게 이득**이 되도록 만든다.

# 9. 해금 3축

세 축이 **서로 다른 자원**을 쓰므로 "돈은 있는데 못 짓는" 상황이 정상이다.

> **설계 원칙: 세 자원이 서로 다른 병목을 맡는다.**
>
> | 자원 | 역할 | 좋은 상태 |
> |---|---|---|
> | **자금** | **단기 의사결정** | 사고 싶은 게 3개인데 2개 살 돈만 있다 |
> | **연구P** | **콘텐츠 진행** | 다음에 뭐가 열릴지 기대된다 |
> | **평판·허가** | **장기 진행** | 규모의 상한을 정한다 |
>
> **자금이 남아도는 상태를 만들지 않는다.** 돈이 항상 조금 모자라야
> "무엇을 포기할까"라는 가장 직관적인 경영 고민이 살아난다.

# 12. 사고 · 리스크

## 12.1 안전 사고

**⚠ 순수 확률이 아니라 경고 누적형이다 (v4 수정)**

v3 는 순수 확률이었다. 그러면 **안전도 78인데 RNG 로 사고 → 3주 폐쇄**가 되어
플레이어가 억울해한다. 좋은 타이쿤의 실패는 **"내가 한 선택 때문"** 이어야 한다.

> **위험도를 4단계로 항상 보여준다. 플레이어가 알면서 감수하게 만든다.**

```
⚠ 선착장 A · 위험도  낮음 → [보통] → 높음 → 매우 높음

  · 장비 과밀        +2단계
  · 안전요원 부족     +1단계
  · 코스 위험도 높음   +1단계
  · 구명함 없음       +1단계
```

시설을 탭하면 이 패널이 뜨고, **원인이 항목별로 나온다.**
장비를 한 대 더 넣으면 게이지가 그 자리에서 올라간다 → 감수하는 선택이 된다.

| 위험도 | 주간 사고 확률 | 표시 |
|---|---|---|
| 낮음 | 0.2% | 초록 |
| 보통 | 1.5% | 노랑 |
| 높음 | 6% | 주황 + 결산에 경고 |
| **매우 높음** | **18%** | 빨강 + **매주 경고 카드** |

```
위험 단계 = 기본(낮음)
  + 혼잡도 100% 초과      → +2
  + 코스 안전도 60 미만    → +1  (40 미만이면 +2)
  + 안전요원 커버리지 50% 미만 → +1
  + 하중 100% 초과        → +2
  − 구명함·안전 콤보        → −1
```

**"매우 높음" 상태로 한 주를 넘기면 결산 직전에 경고 카드가 뜬다** —
`[장비 1대 빼기] / [안전요원 배치] / [그대로 간다]`.
그러고 사고가 나면 **플레이어가 선택한 결과**다.

**결과:** 해당 시설 1~3주 폐쇄 + **플레이어 선택** (순수 처벌은 기억에 안 남는다)

사고가 나면 결산 직전 카드가 뜬다:

| 선택 | 즉시 | 나중 |
|---|---|---|
| **즉시 보상 합의** | 보상금 ₩12,000,000 | 평판 −8 |
| **법적 대응** | 비용 0 | 평판 −28, 3주 뒤 소송 결과(50% 확률 벌금 ₩20,000,000) |
| **전면 안전 점검** | ₩18,000,000 + 2주 전체 휴업 | 평판 −4, 이후 1년간 사고율 −50% |

→ 사고가 **극적인 순간**이 된다. 어느 선택도 편하지 않다.

## 12.2 시설 고장

가동률 누적 → 고장. 정비공 없으면 방치. 고장 시설은 정지.

# 13.5 리조트 평가 5지표 (⚠ 경관 승격)

**v3 의 문제:** 거의 모든 시설이 `효율 +10%` `매출 +30%` 로 환원돼서
**미관·테마·공간 자체의 가치가 없었다.** 그래서 "여기 놓으면 예쁘겠다"는 결정이 안 생긴다.

> **경관을 표시 지표로 승격한다.** 단, **새 시스템을 만들지 않는다** (§아래 주의 참조).

```
리조트 평가

⭐ 만족   82   ████████░░
🌲 경관   67   ██████░░░░
🔥 스릴   91   █████████░
🛟 안전   74   ███████░░░
🧼 청결   88   █████████░
```

| 지표 | 무엇이 올리나 | 무엇에 영향 |
|---|---|---|
| 만족 | 욕구 해소·대기 짧음·콤보 | 평판, 재방문 |
| **경관** | 자연 인접·조형물·개방감·층수 | **커플·가족 유입, 숙박 요금, 사진 명소 콤보** |
| 스릴 | 코스·슬라이드·고스릴 장비 | 친구 그룹 유입 |
| 안전 | 안전요원·구명함·낮은 코스 위험 | 사고 확률, 가족 유입 |
| 청결 | 청소부·화장실 수·쓰레기통 | 만족, 평판 |

## 경관 계산

**시설마다 `viewScore` 필드 하나**를 두고, 인접 조건으로 가감한다.

| 상황 | 경관 |
|---|---|
| 나무·숲 인접 | +5 /개 (최대 +25) |
| 강변 5타일 이내 | +12 |
| 조형물·화단 | +6 /개 |
| 층수 있는 건물 (2·3층) | +층수 × 4 |
| 전망대·정자 | +15 |
| **시설 과밀** (반경 3에 시설 6개 이상) | **−15** |
| **창고·정화조·주차장 인접** | **−10** |
| **대형 시설 옆 숙박** | **−10** (조용해야 하는데 시끄럽다) |
| 청결 60 미만 | −20 |

→ **효율만 따지면 여기인데, 경관 때문에 저쪽이 낫다**는 결정이 생긴다.
특히 숙박(펜션·글램핑)은 경관이 요금에 직결되므로 **조용하고 경치 좋은 곳**에 몰게 된다.

## ⚠ 주의: 새 시스템이 아니다

"나무 옆 카페 +5"는 사실상 소형 콤보다.
**경관을 독립 시스템으로 만들면 콤보와 중복되고 구현이 두 배가 된다.**

따라서:
- 계산은 **시설별 `viewScore` 필드 + 기존 콤보 엔진**이 담당
- 화면에는 **5지표 중 하나로 표시**만
- 경관 전용 콤보(포토존·리버뷰 펜션)는 이미 §8 에 있다

| 사건 | 탭하면 |
|---|---|
| `토요일 매점 대기 12명` | 매점 증축 미리보기 + `[₩192만 지금 증축]` 버튼 |

| `안전사고 1건` | 안전요원 고용 시트 |
| `🔬 연구P +48 → 해금 가능` | 연구 트리에서 해당 노드로 |
| `선착장 대기 28명` | 데크 확장 모드 + ⊕ 표시 |

→ **결산이 "다음 할 일 목록"이 된다.** 폰에서 화면 이동 횟수가 절반으로 준다.

**설계 의도:** 이 화면이 **튜토리얼·피드백·도파민·할 일 목록을 전부 담당**한다.

# 15.13 신규 시스템의 모바일 대응 (⚠ 필수)

적대적 검증으로 추가된 시스템들이 **폰에서 성립하는지**를 하나씩 못 박는다.
"기획서에 표로 있다"는 것과 "폰에서 쓸 만하다"는 것은 다르다.

## A. 주간 의사결정 카드 — S11

```
┌─────────────────────────────┐
│                             │
│         📋                  │
│   단체 예약 문의 (40인)       │  ← 제목 16px
│                             │
│  주말에 회사 단체가 오고       │  ← 본문 2~3줄, 13px
│  싶다고 합니다.              │
│                             │
├─────────────────────────────┤
│ ┃  받는다                 ┃ │  ← 56px, 전폭
│ ┃  매출 +₩120만            ┃ │
│ ┃  이번 주 혼잡 +35%        ┃ │
├─────────────────────────────┤
│ ┃  거절한다               ┃ │  ← 56px
│ ┃  만족 유지 · 평판 −3      ┃ │
└─────────────────────────────┘
```
- **전면 카드. 선택지는 전폭 버튼 2~3개, 각 56px.** 오독이 없다
- 본문은 **3줄 이내** — 5초 안에 읽고 고를 분량
- 스크롤 없음. 선택지가 3개여도 화면에 들어간다
- 카드가 여러 장이면 **한 장씩** 순차 (동시에 안 띄운다)

## B. 장비 × 프리셋 적합도 — 표를 읽게 하지 않는다

**기획서의 13×6 표를 폰에 그대로 띄우면 재앙이다.**
장비를 고르면 **프리셋 탭에 배지가 붙는다.**

```
형태  [왕복 ✕][원형 △][타원 ○][8자 ◎][지그 ◎][급선회 ◎]
                                    ↑ 현재 선택
      ⓘ 하늘날기는 급회전이 있어야 뜹니다
```
- `✕` 는 탭 불가(회색), `◎` 는 금색 테두리로 강조
- 한 줄 설명이 **왜** 그런지 알려준다 → 표를 외울 필요가 없다
- 장비를 바꾸면 배지가 즉시 갱신

## C. 수면 사용 허가 게이지

```
🌊 수면 사용   ████████░░  32/40 타일   ★2 에서 90
```
- 데크 확장·수상시설 배치 **모든 화면 상단**에 고정 표시
- 80% 넘으면 노랑, 100% 도달 시 ⊕ 가 전부 회색 + `★2 필요`
- **탭하면** 무엇이 면적을 얼마나 쓰는지 목록

## D. 도감 70종 — 스크롤 지옥 방지

```
[전체] [소형 8/40] [중형 3/20] [대형 0/10]   ← 티어 탭
[🔍 미발견만]                                ← 필터
```
- 기본은 **미발견만** 보기 (할 일이 보이게)
- 발견한 것은 접힌 채로, 탭하면 펼침
- 한 항목 높이 **56px** — 스크롤이 빨리 지나간다

## E. 결산 사건 인라인 조치

- 사건 항목 자체가 **44px 이상 탭 영역**

# 19. 아트 디렉션 · 에셋 파이프라인

## 19.1 스타일

**탑다운 픽셀아트, 여름 한낮의 따뜻한 채광.** 광원은 좌상단 고정.
실루엣이 작은 화면에서도 읽히도록 형태를 단순하게, 색은 채도를 높게.

| 축 | 기준 |
|---|---|
| 타일 | 16×16 px |
| 시설 스프라이트 | 타일 배수 (2×2 시설 = 32×32 px 기준, 지붕은 위로 초과 허용) |
| 손님 | 12×17 px |
| 장비(보트) | 22~34 × 9~16 px, 우측을 향함 |
| 앵커 | 시설·손님 = bottom-center, 타일·데크 = top-left, 장비·이펙트 = center |
| **층수 표현** | 스프라이트 높이 = footprint×16px + 층수×14px. 위로만 자란다 (§6.3) |
| 외곽선 | 없음 (색 대비로 분리) |
| 그림자 | 코드가 그린다 (반투명 타원) |

## 19.2 팔레트

## 19.3 절차적 vs AI 생성

`manifest.json` 의 `source` 필드가 파이프라인을 가른다.

| 대상 | source | 이유 |
|---|---|---|
| 코스 핸들·경로선 | `procedural` | 동적 생성 |
| 지형 타일 (11종 × 3변주) | `procedural` | 경계 변형이 자동 처리되고 100% 일관 |
| 물결·항적·물보라·그림자 | `procedural` | 애니메이션이 공짜, 위치가 동적 |
| 부표·격자·고스트·코스선 | `procedural` | 경로를 따라 동적 생성 |
| 손님 (8팔레트 × 4방향 × 3프레임 = 96) | `procedural` (부품 조합) | 조각 몇 개에서 96장. Kairosoft 수법 |
| **시설·모듈 (62종)** | **`ai`** | 손맛이 필요한 유일한 영역 |
| **장비 (19종)** | **`ai`** | 동상 |
| 소품(나무·파라솔·벤치·조형물) | `ai` | 동상 |
| UI | 코드 (DOM/CSS) | 에셋 0장, 어느 해상도에서도 선명 |

→ **AI 로 뽑을 이미지가 약 110장.** 수백 장이 아니다. (v1 검증 시 상한을 테스트로 고정해 둠)

## 19.4 생성 워크플로우 (Phase G)

```
0. **우선순위 3차로 나눈다** (110장을 한 번에 뽑는 건 비현실적 — 적대적 검증)
   · 1차 40장: 시작~2년차 시설 (매표소·화장실·매점·데크·선착장·초반 장비)
   · 2차 40장: 3~5년차 (제트스키류·글램핑·유아풀·중형 장비)
   · 3차 30장: 후반·계절 (펜션·온수풀·겨울 시설·고급 장비)
   → 1차만 끝나도 **플레이 가능한 상태가 유지된다**
1. 스타일 레퍼런스 시트 1장 생성 · 확정   ← 이후 모든 생성의 기준
2. manifest.json 의 source==='ai' 항목을 우선순위 순으로 순회
3. 각 항목의 prompt + 레퍼런스 시트를 참조로 생성
4. 배경 제거 → 팔레트 양자화 → manifest 의 size 로 정규화
5. 아틀라스 패킹 → atlas.png + atlas.json
6. createAssetProvider() 가 자동으로 AtlasProvider 로 전환
```

**게임 코드는 0줄 바뀐다.** (구조 구현 완료, `src/assets/`)

## 19.5 계절 표현

에셋을 계절마다 다시 만들지 않는다. **틴트와 오버레이로 처리한다.**

| 계절 | 처리 |
|---|---|
| 봄 | 기본 + 화단 채도 ↑ |
| 여름 | 기본. 물 반짝임 강하게 |
| 가을 | 잔디·나무에 주황 틴트 (`#d89a4a` 25% 곱연산) |
| 겨울 | 밝기 −10%, 청색 틴트, 눈 오버레이 타일, 물 색 어둡게 |

## 19.6 UI 아트

DOM/CSS. 계획서 §15 의 화면 명세를 따른다.
- 터치 타깃 최소 44px (자동 검증이 강제)
- 안전영역(`env(safe-area-inset-*)`) 대응
- 배치·편집 중에는 팔레트·탭을 **접는다**(`display:none`) — 흐리게만 두면 화면 하단 360px 을 계속 먹는다

각 페이즈는 **폰에서 만질 수 있는 것**으로 끝난다. `npm run verify:mobile` 을 통과해야 완료.

## Phase A — 주 단위 루프 (토대)
- `season.ts` 계절·요일·날씨
- `report.ts` 주간 집계 + 사건 수집
- **`events.ts` 주간 의사결정 카드 (24종) + 의뢰 (16종)** ← 루프를 지탱하는 장치
- **`playback.ts` 압축 라이브 연출 (3~5초, 하이라이트 선별)** ★ v4 핵심
- `game.runWeek()`, 겨울 `runWeeks(4)` + 이벤트 시 자동 정지
- 맵 24×32 로 축소, 시작 상태(주차장·매표소·데크2칸·선착장·땅콩튜브) 구성
- S1 메인 개편(**최대 축소 = 감상 화면 + 공유**) + S5 결산(**히트맵·요일막대 + 사건 인라인 탭**)
- S11 이벤트/의뢰 카드
- 실시간 배속 UI 제거

**완료 조건:** `▶ 한 주 진행` → **3~5초 압축 연출** → 결산.
연출에서 사건 지점으로 카메라가 이동한다. 탭하면 스킵된다.
이벤트·의뢰 카드가 선택을 강제한다. 결산 사건을 탭하면 조치 시트가 올라온다.
**최대 축소하면 내 리조트 전체가 살아 움직이는 게 보인다.**

## Phase B — 연결식 구조물 ★코어
- `deck.ts` 데크 그래프·연결성 + **수면 사용 허가 면적**(주 제약) + 부력 하중(보조)

- `facility-store.ts` 확장 (모듈·부착점)
- S3 배치 개편 + S4 구조물 확장 UI (⊕)
- `data/deck.json`, `modules.json`

**완료 조건:** 폰에서 ⊕ 탭으로 데크를 키우고 선착장을 붙인다. **허가 게이지가 상한을 물린다.**
**이 페이즈가 재미없으면 여기서 멈추고 기획을 되돌린다.**

## Phase C — 콤보 · 해금 · 도감
- `combo.ts` 조건 DSL + 발견 기록 + 3티어 + **중복 체감(중형 30→15→5%, 대형 1회)**
- **`score.ts` 리조트 5지표 (만족·경관·스릴·안전·청결)** — 경관은 시설 `viewScore` + 콤보로 계산
- `research.ts`, `grade.ts`
- S3 콤보 미리보기 + S5 발견 연출 + S7 도감(**티어 탭 + 미발견 필터**)
- `data/combos.json` (70), `research.json` (42), `grades.json`

**완료 조건:** 콤보를 발견하고 도감이 찬다. 연구로 시설이 열린다.

## Phase D — 코스 (프리셋 + 터닝포인트)
- `presets.json` (6종) + 프리셋→핸들 배치 → 스플라인 생성 (**기존 수학 재사용**)
- `course.ts` 지표 공식을 프리셋 기본값 + 곡률로
- S6 핸들 드래그 편집기 (36px 핸들, 스냅, 유효성 표시)
- `equipment.json` 19종 + **장비×프리셋 적합도 매트릭스** (프리셋 탭에 ◎○△✕ 배지)

**완료 조건:** 프리셋을 고르고 핸들을 끌면 지표가 즉시 바뀐다. **탭 5회 이내 완성.**
장비를 바꾸면 프리셋 배지가 갱신되어 **표를 읽지 않고도 궁합을 안다.**

## Phase E — 콘텐츠 (⚠ MVP 는 여름만)
- `facilities.json` 62종 + `equipment.json` 19종 채우기
- 그룹 유형 4종, 직원, **사고 위험도 4단계 패널**
- **맵 타입 3종(북한강형·계곡형·호수형)**
- S8 경영, S9 시설 상세
- 계절 시설은 데이터만 넣고 **비활성** (여름 검증 후 활성화)

**완료 조건:** 3년차까지 플레이가 끊기지 않는다. **여름 13주가 재미있다.**
비수기는 4주 단위로 넘어간다.

## Phase F — 밸런싱 + 재플레이
- 헤드리스 러너로 수백 시즌 (`npm run sim -- --years 10 --seeds 50`)
- 골든 시나리오 고정, §13 수치 조정
- **시나리오 6종** (3년 안에 ★3 / 절반 예산 / 좁은 강 / 사고 없이 / 관광지)
- **자금이 남아돌지 않는지** 확인 — 남으면 비용을 올린다

**완료 조건:** ★1→★5 가 12~18시간에 도달. 파산이 너무 쉽거나 어렵지 않다.

## Phase G — 에셋 · 포장
- 매니페스트 기반 AI 픽셀아트 **3차 분할 생성**(40/40/30) → `AtlasProvider` 전환
- S10 다시보기
- PWA → Capacitor

**완료 조건:** 게임 코드 변경 0줄로 룩이 바뀐다. 실기기 60fps.

# 23. 미결정 사항

## 결정됨 — 수익모델 (v4)

> **프리미엄(유료) 게임으로 간다. 광고·IAP 없음.**

**왜 지금 정하나:** 수익모델이 **세션 구조와 진행 속도를 결정**한다.
광고를 넣으면 "결산마다 광고" → 주간 루프가 광고 삽입 지점이 되고,
IAP 를 넣으면 "연구P 부족"이 인위적 게이트로 느껴진다.
Phase F 까지 미루면 그때 루프를 다시 짜야 한다.

| 항목 | 결정 |
|---|---|
| 가격 | 유료 (₩5,000~8,000 대) |
| 광고 | **없음** |
| IAP | **없음** |
| 확장 | 사계절·추가 맵을 무료 업데이트 또는 DLC |

**설계에 미치는 영향**
- 연구P·등급 게이트를 **인위적으로 느리게 만들지 않는다** (과금 유도가 없으므로)
- 한 판 12~18시간이면 유료 게임으로 충분한 분량
- 세션 길이를 **광고 노출에 맞춰 왜곡하지 않는다**
