# 가평 빠지 리조트, 픽셀화 3D — Gauntlet Prompt

한여름 강변 수상레저 리조트를 3D로 지어라. 단, 화면은 3D 렌더처럼 보이면 안 된다 —
첨부한 레퍼런스 이미지(도트 리조트 컨셉)와 같은 **픽셀아트 한 장면**처럼 보여야 한다.
방법은 정해져 있다: 씬 전체를 저해상 렌더타깃(가로 480px급)에 그리고 NEAREST 로 확대,
색은 제한 팔레트로 양자화, 픽셀 단위 외곽선 패스. 지오메트리는 3D, 화면은 도트.

Three.js 로 만들어라. 외부 에셋 0. 모든 지오메트리·텍스처·사운드는 코드로 절차 생성.
다운로드 이미지 없음, 모델 파일 없음, 오디오 파일 없음. 레퍼런스 이미지들은 오직
크리틱의 채점 기준으로만 쓴다 — 텍스처로 샘플링하지 마라.

카메라는 고정 3/4 부감 오소그래픽 하나. 회전 없음. 아주 느린 좌우 팬과 두 단계 줌만.
게임이 아니다. 조작은 팬·줌뿐인 **살아 움직이는 디오라마**다.

## 장면 구성 (위에서 아래로)

- 하늘: 여름 한낮, 뭉게구름 두어 개가 아주 느리게 흐른다.
- 원경: 겹겹의 산등성이. 뒤로 갈수록 하늘색으로 바래는 대기 원근. 능선마다 숲의 요철.
- 언덕: 계단식 석축 테라스 위에 3층 리조트 본관. 청록 지붕, 크림 벽, 테라스 난간에
  파라솔과 화분. 진입로에 승합차 한 대. 본관 뒤로 침엽수·활엽수 혼합림.
- 물가 서비스열: 나무 데크 산책로를 따라 구명조끼 대여 랙(주황 조끼가 줄줄이),
  매점 오두막, 안전요원 타워(빨간 십자), 천막 그늘. 손님들이 줄 서고 오간다.
- 선착장: 목재 잔교가 물로 뻗고, 제트스키·모터보트 대여섯 대가 색색으로 정박.
- 수상파크(화면의 주인공, 하단 60%): 파란 폰툰 큐브 둘레길이 큰 직사각형 수역을
  감싸고, 안에는 라임그린·노랑 인플레이터블 — 미끄럼틀, 클라임 산, 트램폴린, 롤러,
  아치 — 가 통로로 이어져 하나의 코스를 이룬다. 모서리마다 주황 부표 체인.
- 외곽 수역: 바나나보트가 손님을 태우고 곡선으로 달리며 항적을 남긴다. 구조 보트
  한 대 대기. 수영하는 손님 머리가 점점이.

## 물이 전부다

- 색은 띠로: 물가 에메랄드 → 얕은 청록 → 깊은 코발트. 띠 경계는 부드럽지만 뚜렷하게.
- 모래와 만나는 곳에 흰 거품선이 물결치며 천천히 밀려왔다 빠진다.
- 수면 전체에 햇빛 스파클이 자잘하게 반짝인다. 픽셀화를 거치면 도트 반짝임이 된다.
- 인플레이터블·폰툰·보트 주위에 얇은 흰 가장자리 물결. 바나나보트 뒤엔 V자 항적.
- 반사는 과하지 않게 — 레퍼런스는 거울 반사가 아니라 색과 하이라이트로 물을 그린다.

## 사람이 밀도다

손님 100명 이상. 전부 작은 복셀/캡슐 인형에 주황 구명조끼. 상태는 최소 다섯 가지 —
걷기, 줄서기, 수영(머리와 팔만), 인플레이터블 위에서 균형 잡기, 미끄럼 타고 떨어지기.
경로는 단순해도 된다. 멀리서 보면 "리조트가 붐빈다"로 읽히는 것이 목표다.
빈 수면·빈 데크가 화면에 크게 남으면 실패다. 레퍼런스는 모든 픽셀에 무언가 있다.

## 사운드

물 찰랑임, 멀리 매미, 손님들의 웅성거림과 간헐적 웃음·물장구, 확성기 안내방송 한
토막(뭉개진 톤), 바나나보트 모터가 가까워졌다 멀어지는 도플러. 전부 절차 합성.

## 빌드 순서 — 한 번에 한 시스템

병렬 서브에이전트 금지. 이 순서대로:

1. 픽셀화 파이프라인 먼저 — 저해상 타깃, NEAREST 확대, 팔레트 양자화, 외곽선.
   테스트 큐브 하나가 도트로 보일 때까지. 이게 안 되면 나머지는 전부 헛일이다.
2. 물 — 색 띠, 거품선, 스파클. 물만 있는 화면이 이미 예뻐야 한다.
3. 지형 — 산 겹, 언덕 테라스, 모래사장.
4. 수상파크 — 폰툰 둘레길, 인플레이터블 코스, 부표.
5. 건물·서비스열 — 본관, 오두막, 선착장, 정박 보트.
6. 손님 — 인형, 다섯 상태, 산포와 동선.
7. 움직임 — 구름, 거품선 왕복, 바나나보트 주행, 스파클.
8. 사운드와 마감 — 그레이딩은 팔레트 안에서만.

각 시스템이 끝나면 **그 시스템을 만들지 않은 별도 에이전트 하나**를 크리틱으로 띄워라.
크리틱은 코드를 보지 못한다. 렌더 스크린샷과 레퍼런스 이미지 3장만 보고 두 가지를
채점한다: "레퍼런스와 같은 게임의 장면으로 보이는가", "3D 렌더 티가 나는 곳은 어디인가".
통과할 때까지 그 시스템에서 /loop. 통과 전에 다음 시스템으로 넘어가지 마라.

## 테스트

최종 스크린샷을 레퍼런스 이미지들 사이에 섞어서 맥락 없이 보여줬을 때, 어느 것이
렌더인지 바로 못 고르면 된다. "이것만 3D 게임 같다"는 말이 나오면 계속 간다.

## 기술 제약

- Vite + TypeScript + Three.js (R3F 없이 순수 three 여도 좋다)
- 오소그래픽 고정 카메라, 픽셀화 후 논리 해상도는 폭 480px 안팎
- 팔레트는 40색 이내로 시작해 필요하면 넓혀라 — 단 물·초목·지붕 계열이 레퍼런스의
  색상군을 벗어나면 안 된다
- 미드레인지 GPU에서 60fps. 손님 100+명은 인스턴싱으로
- 모바일 세로 화면(393×852)에서도 구도가 성립해야 한다 — 수상파크가 하단을 차지

3. CanvasTexture 의 colorSpace 미지정으로 산 전체가 창백하게 씻겼다 (SRGBColorSpace 지정).
