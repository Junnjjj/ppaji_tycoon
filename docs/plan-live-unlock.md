> 스펙: `docs/superpowers/specs/2026-08-19-kairo-live-unlock-design.md` (v1.2, 승인됨).
> 이 문서가 구현의 정본이다. §5 가 이 계획 자체의 검증 결과다 — 착수 전에 구멍 셋을
> 찾아 스펙에 반영했다.

## 0. 원칙 (전 단계 공통)

- **항등이 먼저다**: K39 의 첫 커밋은 기능이 아니라 `run() ≡ 분할 step` 검사다.
  이게 빨간불이면 흐름 모드 작업 금지
- **새 검사는 위반을 주입해 잡히는지 먼저 본다** (`seam --selftest` 패턴 —
  8건 실측 교훈). 대조군은 손이 아니라 **코드로** 남긴다 (`setRenderFaultForTest` 전례)
- 브라우저 검증은 **진짜 터치**로 (K33 교훈). `page.evaluate` 안에 이름 있는 함수 금지
- 밸런스 주장은 12시드 합계로 (한 시드 대조 금지)
- 커밋은 **밸런스가 움직이는 변경과 안 움직이는 변경을 섞지 않는다** (K36-B 규칙)

## 1. 슬롯 계약 — 에셋·이펙트·오디오가 나중에 들어올 자리

사용자 요구: 에셋·이펙트·음악은 **나중에 한 번에** 만든다. 그때 코드 고고학을 하지
않으려면, 지금 구현하는 모든 연출·소리 지점이 **논리 ID 로만** 참조돼야 한다.
기존 에셋 계약("게임 코드는 파일을 모른다, ID 만 안다")을 세 갈래로 확장한다.

### 1-1. 그림 (기존 계약의 확장)

- `kairo-render-contract.json` 에 네임스페이스 추가:
  `ui/*` (탭 아이콘·의뢰 칩 아이콘·캡슐 아이콘·캐러셀 화살표) ·
  `chara/*` (소원 인물 8 + 심사관 1 — 초상·이름표용)
- 시설 썸네일은 **기존 시설 스프라이트 ID 재사용** — 신규 계약 없음
- 지금은 전부 절차적 플레이스홀더 (`kairo-procedural.ts` 에 굽기 추가),
  `source: 'ai'` 표시 + `prompt` 필드 → **Phase G 가 이 목록만 보고 일괄 생산**
- 계약 불일치 검사(이미 있음)가 ui/chara 도 함께 지킨다

### 1-2. 이펙트 (신규 등록부 둘 — 캔버스와 CSS)

- **캔버스 FX**: `src/render/kairo/fx.ts` 신설. `playFx(scene, name, target)` 하나로만
  호출한다. 등록부 `FX_REGISTRY: Record<FxName, (scene, target) => void>`.
  지금 구현 = tween (`transform`/`opacity`, 불변식 준수). 나중 업그레이드 = 등록부
  항목 교체 (파티클·스프라이트 시트). **호출부 0줄 변경**
- **CSS FX**: 모달·칩의 반짝임은 `style.css` 의 `.fx-*` 클래스 (색·모션 소유권 규칙
  그대로). `prefers-reduced-motion` 가드 필수
- FX 이름 목록 (구현하며 늘면 여기 갱신): `unlock-burst`(셀레브레이션) ·
  `combo-flash`(콤보 발동) · `discover-glow`(숨은 콤보) · `grade-up` ·
  `wish-arrive`(인물 도착 강조) · `new-guest-first-use`(새 시설 첫 이용)

### 1-3. 오디오 (신규 — 무음 구현부터)

- `src/audio/` 신설. 인터페이스 `AudioBus { play(cue): void; music(id): void;
  setMuted(b): void }`. 지금 구현은 **`SilentAudio`** (전부 no-op)
- 큐는 유니언 타입으로 고정 (`src/audio/cues.ts`): `sfx/tap` · `sfx/place` ·
  `sfx/demolish` · `sfx/cash` · `sfx/unlock` · `sfx/grade-up` · `sfx/card` ·
  `sfx/day-end` · `sfx/exam-pass` · `sfx/exam-fail` · `bgm/summer` · `bgm/offseason`
- **호출부를 지금 심는다** — K39~K44 의 모든 사건 지점에 `audio.play(...)` 삽입.
  나중 오디오 작업 = `WebAudioBus` 구현 (파일 로드 + iOS 제스처 언락 + 음소거 설정)
  으로 교체 한 곳. **sim 은 오디오를 모른다** (불변식 1 — 호출은 render/ui 층에서만)

> 규칙: K39~K44 구현 중 연출·소리를 **등록부 밖에서 만들지 않는다.** 리뷰 체크리스트
> 항목이다. 이 규칙 덕에 "에셋·이펙트·음악을 한 번에"가 목록 채우기가 된다.

## 2. 단계별 계획

### K39 — 흐르는 낮

| # | 작업 | 파일 | 커밋 |
|---|---|---|---|
| 1 | `WeekRunner` 를 `begin/step(n)/finish` 로 분해, `run()` = 합성. **항등 테스트**: 12시드 × 26주, 분할 크기 퍼즈(1·7·120·840·소수) 결산 완전 일치 | `week.ts` + 신규 테스트 | ① sim 만 |
| 2 | 흐름 루프: `LiveClock` (프레임마다 경과 실시간 → tick 소비, 기본 0.4초/tick, 2× 토글). 멈춤 = PanelHost 열림 · `document.hidden` · 시트 | `main.ts` | ② |
| 3 | 하루 마디: 하루 끝 토스트(요일 포함) · 주말 진입 토스트 · 낮밤 틴트(렌더 전용, 캔버스 오버레이) · 상단 캡슐에 `N주 D일 (요일)` | `KairoScene.ts` `kairo-hud.ts` | ② |
| 4 | 주 마디 재배선: 7일째 → 결산 → 닫으면 흐름 재개, 카드는 월요일 아침 도착 큐로. ⏩ 이단 (기본 하루 · 주 스킵은 해금 플래그 뒤, 해금 연결은 K42) | `main.ts` `kairo-card.ts` | ③ |
| 5 | playback 제거: `playWeek` · `PlaybackFrame` · 결산 `다시 보기` | `week.ts` `KairoScene.ts` `kairo-report.ts` | ④ |
| 6 | 오디오 슬롯 심기: `SilentAudio` + `sfx/day-end` 등 | `src/audio/` | ②에 포함 |

검증: 항등(위반 주입 = step 안에서 상태 하나 비틀면 잡히는지) · 흐름 중 건설이 그 주
결산에 반영(헤드리스로 같은 시나리오 대조) · 멈춤/재개 브라우저(진짜 터치로 시트 열기) ·
밀도 계측(2× 30초 관측 → 분당 환산, 토스트 포함/제외 두 값 기록, 목표 ≥6/분) ·
버스가 흐름에서 움직임 · `verify:kairo` 전 항목.

### K40 — 초반 (K39 와 병행 가능)

| # | 작업 | 커밋 |
|---|---|---|
| 1 | 시작 킷 재조정: 놀이 1~2 + 동선 → 무행동 1주 만족도 ≥25 · 헛걸음 <입장의 30% | ① (밸런스 이동 기록) |
| 2 | **온보딩 검사 신설**: 새 판 무행동 8주 문턱 + "첫 의뢰 최단 경로" 실측 (5분 = 흐름 시간, tick 환산 6.25일분 = 750 tick 안에 봇이 첫 의뢰 완수→보상 도착) | ① |
| 3 | 건설 시트 = **카드 캐러셀**: 썸네일(시설 스프라이트) + 크기 + 가격, 서브탭, `◀ ▶` 페이지 버튼(44px) + 스와이프, 해금분만 + 티저 2줄 | ② |
| 4 | **좌측 의뢰 칩** 2~3 (아이콘 + 미니 진행바 + 심사 게이지) — 목표란 대체, 시나리오는 메뉴로 | ③ |
| 5 | 검사: 시트 항목 ≤24 · 칩 가로 예산 ≤22% · 진척이 실제 sim 값과 일치(위반 주입: 진척 +1 비틀기) | ③ |

## 3. 이후 (이 계획 밖 — 슬롯을 채우는 일)

- **Phase G 에셋 일괄**: 계약의 `ai` 항목 전부 + `ui/*` + `chara/*` — 목록이 곧 작업지시서
- **오디오**: `WebAudioBus` 구현 교체 + 파일 + 제스처 언락 + 음소거 UI — 호출부는 이미 있다
- 등급 5 이후 티어: K43 이후 실측으로 판단 (스펙 §9)

## 4. 순서

```
K39 (흐르는 낮) ─┐
                 ├─→ K41 (재배분+세이브 v7+셀레브레이션) → K42 (심사+이동) → K43 (소원+발견+입고) → K44 (스킨)
K40 (초반)     ─┘
```

K39·K40 은 병행 가능 (파일 겹침: `main.ts` 뿐 — 순차 병합으로 해소).
K44 를 마지막에 두는 이유: 구조(캐러셀·칩·모달)가 다 선 뒤에 입혀야 두 번 칠하지 않는다.

## 5. 계획 검증 결과 (착수 전 자체 검수)

**커버리지**: 스펙 v1.2 의 모든 조항이 단계에 매핑됨을 확인 — §2(K39) · §3.1~3.5(K41~K43) ·
§3.6(K41) · §4(K42) · §5(K40) · §5.5(K40 구조 + K44 스킨) · §6(K41) · §8(각 단계 검증란).

**찾은 구멍 셋 (스펙에 반영 완료):**
1. **세이브 v7 누락** — 사건 해금은 등급에서 파생 안 되는 상태다. 스펙 §6 에 추가
2. **봇이 심사에 응시해야 한다** — 안 하면 등급이 안 올라 골든·밸런싱이 1등급 세계를
   잰다 (K36 "봇과 골든은 실제 격자로"와 같은 종류의 함정). K42-4
3. **"첫 보상 5분"의 환산 정의 없음** — 5분 = 흐름 실시간 = 750 tick (6.25일분)으로 정의. K40-2

**불변식 대조**: 상시 컨트롤 3 유지(⏩가 자리 계승) · 색 소유권(스킨=토큰) · 패널
표면 셋(셀레브레이션=`.kover.dialog`) · sim 순수(오디오·FX 호출은 render/ui 만) ·
결산 순서 유지 · 카드 모달 유지 · 시설=데이터(해금은 JSON 필드) — 충돌 없음.
**재협상 예약 1건**: 결산 모달이 흐름과 7일마다 부딪히는 이음매 — K39 실플레이 후 판단.
