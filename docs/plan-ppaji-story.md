## 2. 게임 설계 — 「빠지 스토리」

### 2.1 한 줄 정의
가평 강변의 작은 빠지를 물려받아 8년 동안 **전국구 빠지**로 키운다. 여름 성수기가 주력이지만 **사계절**(봄 벚꽃 캠핑·낚시 → 여름 빠지 → 가을 단풍 바비큐 → 겨울 빙어·눈썰매·온수탕)이 실제로 바뀐다. 성장의 원동력은 **손님 소원 → SNS 후기·태그 → 출신지 개방(버스) → 심사·인증 → 랭크**(워터파크 루프 그대로).

### 2.2 수역 — 풀 상태의 빠지식 해석 (D3)
- **수역 치기**(= 풀 파기): 강은 지형이라 파지 않는다. **부표 줄**로 강 위에 구역을 치고(칸 단위, 4이웃 연결 = 한 수역), 뭍 쪽엔 **데크·폰툰**을 깐다(물 위 바닥 = 손님이 서는 곳). 수역 크기·모양이 곧 인기·정원이다.
- **수역 상태 8**(풀 상태 8의 1:1 대응): 크기 · 인기 · 유지비(부표·안전요원) · **물빛**(색 대응: 맑음/청록/노을/야간조명 — 낮·저녁·조명 소품이 정한다) · **분위기**(향 대응: 트로트/힙합/재즈/캠프파이어/조용함 — 스피커·모닥불·인접 시설 중 최강 1) · **물살**(신규 축: 잔잔~급류, 코스 스릴과 손님 취향 — 워터파크 강도(농도)는 물빛 농도로 그대로 남는다) · **수온**(그대로: 계절 기본 + 온수관·얼음 소품 + 인접 온수탕) · **SE/AB**(햇빛·좋아요·인접 물 뿌리는 시설·착수 슬라이드 그대로).
- **소품**(아이템 ≤20, 시간 뒤 소멸): 부표 색·LED 조명·스피커·물안개·온수관·얼음·꽃잎 띄우기·풍등·비치볼… — 「강에 딸기를 넣는다」 대신 「수역을 꾸민다」. 계절 보너스 표(`seasons.json`)는 물빛·분위기 축으로 다시 적는다. 좋아요 리셋(물빛이 바뀌면 후기 0)은 경고와 함께 유지.
- **코스 = RCT 식 루트**: 수역 위에 **견인 코스**를 그린다(빠지 `course.ts` 이식: 선착장 앵커 · 프리셋 6 · 핸들 · 겹침·물길 막힘 검사). 코스가 있는 수역은 「스릴」 을 얻고 손님이 **탄다**(워터파크 슬라이드의 climb/ride 문법을 보트 승선·활주로 재사용). 기구×프리셋 적합도(19×6)는 그대로.
- **기구 공방**(D5): 부품(엔진·튜브·로프·핸들·시트·안전바…) ≤5 → 새 견인 기구 **발견**(바나나보트·땅콩·디스코팡팡·플라이피시·블롭점프·수상스키·웨이크보드 … ~30종), 공방 Lv 소급(스릴·안전 배수), 실패작 = 웃긴 기구(「구멍 난 튜브」). 요리 창과 같은 창 문법. 기구 집합 = 빠지 19종(`kairo-equipment.json`, 시작 소유 둘 + 상점·투자·소원 해금)을 **그대로 승계**한 위에 공방 발견분 ~11 을 더해 ~30 — 에셋 계약 §6 ③ 의 「기구 8」은 첫 그림 묶음일 뿐이다.
- 소원·인증·랭크 조건 DSL: kind `pool`→`zone`, `poolTotalSize`→`zoneTotalSize`; `zone` kind 의 필드 `color`→`look`, `scent`→`mood`. ⚠ `intensity` 는 색 **농도**(`mixColor` 결과, 막대 5)라 물살이 아니다 — 물빛 농도로 그대로 남기고, 물살은 새 필드 `currentMin` 으로 **추가**. `courseThrill`·`gear` kind 추가.
- 물빛·분위기의 **종수는 워터파크 색 11·향 12 와 같게** 유지한다(소원 213·인증 24 조건이 이름을 참조 — 줄이면 조건 재작성 범위가 달라진다). 무지개(8색 등량)의 대응은 「오색 조명」.

## 4. 에셋 계약 (다른 세션의 아틀라스 작업이 겨냥할 것)

- **논리 ID** 그대로(`fac/<id>/<facing>`, `ground/<kind>`, `guest/...`, `boat/<id>`), 게임 코드는 파일을 모른다. `AtlasProvider` 가 있으면 ID 단위로 덮고, 계약과 크기가 다르면 그 ID 만 절차 도트로 떨어진다(빠지 Phase G 규칙).
- **타일** 32×16 텍셀, 정수 업스케일. 시설 캔버스는 발자국에서 유도: `w = (W+D)×16`, `h = (W+D)×8 + bodyH`(빠지 계약과 같은 식).
- **회전**: 데이터 `facings: 2 | 4`(기본 2). 2 는 뒤집기, 4 는 네 방향 그림. 회전은 발자국·입구·출구를 **같이** 돌린다(`footprintTileOf` 한 곳).
- **입구/출구**: 시설 데이터에 `entry: {i,j}[]`(손님이 들어서는 발자국 앞 칸, 기본 = 앞 두 면 파생) · `exit: {i,j} | null`(슬라이드·에어바운스·낚시터처럼 나오는 칸이 다른 것; 매점·평상은 `null` = 입구로 나온다). 그림의 문·활강로 끝이 이 칸과 맞아야 한다 — 게이트가 잰다(빠지 「슬라이드 exitTile↔그림 불일치」 재발 방지).
- **크기 표**: 1×1(자판기·화장실·파라솔) · 2×1(매점·샤워) · 2×2(평상 묶음·바비큐장·방갈로·카페) · 3×2(슬라이드 소형·에어바운스) · 4×2(대형 슬라이드·펜션) · 보트 1×1(견인 보트 4방향 + 기구 ~30 × 방향 2).
- **손님** 18×32(워터파크 계약) — 포즈 6(idle·walk·swim·sit·lie·ride) + float 변형 + (P4-C 에서) climb × 방향 2 × 팔레트 8, 표정 오버레이. 구명조끼·튜브 6색. ID 형식은 실물 `guest/body:{palette}[:{build}][:f{n}]/{pose}/{frame}[/{mood}]`.
- **부표·데크·강 지면**: `tile/river:a0~a2`(흐름 애니 3프레임) · `tile/shallow` · `tile/deck` · `buoy/<color>` 13(인증 보상). 접두사는 manifest 실물 `tile/`.
- 계약 파일: `ppaji/src/assets/manifest.json` + `docs/ppaji-asset-contract.md`(P0 에서 생성, 다른 세션이 읽는다).
