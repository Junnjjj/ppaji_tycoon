# P56-c 재고(U1) 수행 레포트 (2026-09-12)

> 사용자 결정 「재고 넣고」(2026-09-12) → `docs/plan-ppaji-picture-ui.md` §6 미결 ① 「넣는다」 · 결정 **D10**. 이 문서는 무엇을 넣었고 무엇이 움직였는지의 기록이다. 정본은 계획서(D10 · §5 P56-c · 이력)이고, 여기는 한 자리에서 읽는 요약.

## 1. 한 줄

재료·부품이 **열쇠(owned) + 재고(stock)** 가 됐다. 시작 재료는 무한, 장날에서 사면 +1, 보상은 ×3, 조합·개조는 슬롯당 −1, 한 번 얻은 보상 재료는 장날 값으로 다시 산다. 요리·공방·개조 창의 `×N` 이 진짜 재고를 가리킨다.

## 2. 규칙 (D10)

| 항목 | 규칙 | 근거 |
|---|---|---|
| 단위 | 재료·부품 1개 = 조합 1회분. 같은 재료를 두 슬롯에 넣으면 재고 2 | 원작 「×N 보유·쓰면 준다」 |
| 시작(`unlock:'start'`) | **무한** — 재고를 안 세고 카드에 `∞`. 안 판다 | 기본 재료가 바닥나면 첫 요리부터 막힌다 |
| 장날(`shop`) | 사면 **+1**, 몇 번이고 | 계획 §5 「상점 n+1」 |
| 보상(소원·인증·달력·연차) | **×3** (`REWARD_STOCK`). 인증 **재수상**은 3회 뽑기 × +1(없는 것부터, 다 있으면 아무 cert 재료) | 계획 「재료 ×3」 · 재수상 = 재료 3개(원작) |
| 소비 | 돈을 낸 시도만 −1 — 요리(실패작도)·공방 조합·개조 **발견**. 개조 「미발견」은 돈도 재고도 0 | 손해가 두 겹이면 억울하다 |
| 보상 재료 재구매 | 한 번 얻으면(열쇠) 장날 값으로 다시 산다 — 재료 46·부품 10 에 `price` 데이터(소원 500 · 인증 800 · 연차 500/600 + 100×연차) | 없으면 ×3 을 다 쓴 레시피가 영영 막힌다(소원 조건 `recipe` 4 건 교착) |
| 세이브 | `CookingSnapshot.stock?` optional 하나(요리·공방·개조 같은 모양). 없으면 보유마다 ×3(`LEGACY_STOCK`) · 버전 그대로 | 계획 「optional 하나」 |

## 6. 계획과 다른 것 · 주운 것

- **보상 재료 재구매**는 계획에 없었다(계획은 「상점 n+1 · 조합 n−1 · 보상 ×3」만). 넣은 이유는 §2 표 — 재구매가 없으면 소원 조건 `recipe`(4 건)와 도감 완성이 구조적으로 막힌다. 값은 데이터(불변식 3).
- **시작 재료 무한**도 계획에 없었다 — 시작 9종(얼음·물·설탕…)·부품 7종이 바닥나면 아무것도 못 만든다.
- 인증 재수상은 「재료 3개」를 **3회 × +1** 로 읽었다(새 재료 ×3 이 아니라).
- 주운 것: 봇이 재고 없이도 매일 조합하던 습관이 재고에 막히면 `recipes` 가 무너질 줄 알았는데 59 로 거의 그대로 — 발견의 병목은 재료 수가 아니라 「무엇을 섞을지」였다. · `p52a` 단일 시드 ×3 은 봇 지출 순서만 바뀌어도 깨진다.
