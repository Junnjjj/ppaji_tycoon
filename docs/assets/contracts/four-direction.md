# 고정 시설 물리 4방향 계약

최종 갱신 2026-08-27. 이 문서는 창구·문·입구·출구·탑승면처럼 방향 의미가 있는 **고정
시설**의 현행 d0–d3 정본이다. 제트스키·보트처럼 경로를 따라 움직이는 기구는
`docs/assets/pipelines/watercraft.md`를 사용한다.

## 전제

- 사용자가 승인한 하나의 콘셉트만 사용한다.
- 한 개의 실제 Meshy GLB 또는 검증된 Blender 모델 전체를 하나의 물리 root 아래 둔다.
- 카메라·게임축·월드 크기는 `docs/assets/contracts/camera-direction.md`를 따른다.
- ImageGen이 네 방향의 기하를 독립적으로 만들 수 없다. 채색은 물리 렌더를 참조하는 후속
  단계이며, 실루엣과 알파를 바꾸지 않는다.

## 방향 계약

카메라는 orthographic yaw 45°, optical pitch down 30°, roll 0°로 고정한다. Blender에서는
카메라 Euler XYZ `(60°, 0°, 45°)`를 사용한다. pitch/roll은 물체에 주지 않고 전체 root의
Z 회전만 바꾼다.

| 방향 | root yaw | 직사각 풋프린트 | 의미 |
|---|---:|---|---|
| `d0` | 0° | `w×d` | 정본 로컬 방향 |
| `d1` | 90° | `d×w` | 시계 방향 1/4회전 |
| `d2` | 180° | `w×d` | 반대면 |
| `d3` | 270° | `d×w` | 시계 방향 3/4회전 |

네 렌더는 같은 union framing과 같은 균일 스케일을 사용한다. 카메라 이동, 패널별 재프레이밍,
미러링, 방향 이름만 바꾸기는 금지한다.

## 입구·출구·NPC 이용면

문, 창구, 서비스면, 탑승구, 입구와 출구, NPC 슬롯은 시설 로컬 좌표로 저장한다. 풋프린트와
동일한 1/4회전 변환으로 좌표와 `facing`을 함께 회전한다. 그림의 이용면과 데이터의 슬롯
방향이 모든 d0–d3에서 일치해야 한다.

- 한 이용면: 상점, 자판기, 창구는 rear view에 앞면을 복제하지 않는다.
- 입구·출구 분리: 슬라이드와 탑승 시설은 두 지점의 순서와 기능을 보존한다.
- 양면 이용: 탁구대 같은 시설은 서로 반대인 두 이용면을 유지한다.
- 기본 시설 그림에는 NPC를 굽지 않는다. 점유 모습은 별도 상태·합성 증거로 다룬다.

## 필수 증거

진짜 4방향 PASS에는 최소한 다음이 필요하다.

- `physical-rotations.json`: root yaw, pitch, roll과 고정 카메라 기록
- `union-canvas.json`: 공통 framing과 스케일
- 물리 `d0.png`~`d3.png`와 서로 다른 네 해시
- 저장한 Blender 파일을 새 프로세스로 열어 다시 렌더한 decoded RGBA 동일성
- d0–d3에서 같은 구조 랜드마크가 순환 이동한다는 대응표·오버레이
- 입구·출구·서비스면·슬롯 방향 증거
- `visual-review.json`의 사용자 판정
- 읽은 계약·스킬·입력·산출물의 절대 경로와 SHA-256 provenance

점유율, 네 개의 서로 다른 해시, 미러 유사도만으로 물리 회전을 증명할 수 없다.

## 게이트 순서

1. 콘셉트 선택
2. 실제 메시와 d0 기준선 검토
3. 물리 d0–d3·재오픈·랜드마크 검증
4. 물리 방향을 참조한 채색과 알파 잠금
5. 풋프린트·캔버스·앵커·슬롯 검증
6. 사용자 외형·배치 승인
7. d0–d3와 데이터·아틀라스의 원자적 라이브 채택

사용자 거절은 앞선 패키지 PASS를 무효화한다. 새 대체본을 보여주고 명시적으로 승인받기
전에는 다음 게이트나 라이브 채택으로 진행하지 않는다.

## 라이브 채택

승인된 네 방향을 한 번에 복사하고 같은 변경에서 `src/data/kairo-facilities.json`의 `facings`,
`size`, 슬롯과 `src/assets/kairo-render-contract.json`의 캔버스·앵커를 갱신한다. 낡은 단일
base와 혼용하지 않는다. 아틀라스를 다시 굽고 gate, verify, 브라우저 배치, build를 모두
통과시킨다.

## 폐기된 방식

독립 프롬프트 4-up, 체인 참조, 미러 판정으로 방향을 만들던 2026-08-22 방식은 생산용으로
폐기됐다. 실패 원인과 재발 방지 자료는
`docs/assets/history/prompt-chain-4dir-retrospective.md`에만 보존한다.
