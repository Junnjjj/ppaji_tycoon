### 표 읽는 법

- **캔버스** — 이 종의 그림 크기(px). 발자국에서 파생된다: 가로 `(W+D)×16`
- **꼭짓점 이탈** — 접지 다이아몬드의 **가장 아래 꼭지점**이 계약 자리에서 몇 텍셀 빗나갔나
- **IoU (문턱)** — 접지 실루엣과 정본 다이아몬드의 겹침. 괄호가 그 발자국의 통과선이다
- **실패 축** — 게이트가 빨간불을 낸 축 (`꼭짓점` · `기울기` · `모양`)
- **기울기 L/R** — 접지 아래 두 변의 기울기. 정본은 **+0.500/−0.500** (2:1 다이메트릭)이고,
  `—` 는 변이 없어 **측정 자체가 불가**한 것이다 (파라솔처럼 접지가 점 몇 개인 종)
- **광원** — 접지선 바로 위 벽 띠의 **왼쪽 − 오른쪽** 휘도. 좌상단 광원이면 **양수**다.
  `측정불가` 는 한쪽에 벽 열이 4개도 안 뜬 것(`fishing` 이 오른쪽 1열) — "통과"가 아니라
  **잴 수 없다**이므로 실패로 센다
- **덮임** — 정본 다이아몬드 중 그림이 실제로 덮은 비율
- ⚠ **`여백 없음`** — 추출기가 평행이동으로 더 밀고 싶었지만 **캔버스에 빈 자리가 없어**
  (그림이 좌우 끝에 닿아 있어) 못 민 것이다. 자르는 것은 무손실이 아니므로 갈 수 있는
  만큼만 갔다 — 즉 **이 줄들은 위치가 아니라 그림 자체가 틀렸다**는 가장 강한 신호다
- **수리 이력** — `수리 불가` **23종**은 후처리 수리를 **실제로 해 보고 그림이 나빠져
  백업으로 되돌린** 것이고 (§5.1), `미러 전용` **3종**은 좌우 반전만 살리고 색판은 버린
  것이다. 둘 다 **후처리로는 끝났다.** 나머지 2종(`shade_net`·`photozone`)은 수리 대상이
  아니라 **면제가 잘못 걸려 있던** 종이다 (§5.2)
- ⚠ **`축뒤집힘` 표시가 붙은 종은 그냥 리롤하면 안 된다** — 발자국 두 축이 바뀐 그림이라
  프롬프트로 그 사실을 지목해야 한다 (§2, §4.1). **지금은 0종**이지만 재생성이 이 실패
  모드를 다시 만들 수 있다

## 2. 어떻게 뽑나

### 권한이 있는 세션 — 한 줄

```bash
npx tsx tools/regen-facility.ts --both --tries 3         # ← A군 8종. 여기부터
```

`tools/regen-facility.ts` 가 조각을 **사람이 26번 손으로 이어 붙일 필요 없이** 잇는다.
종당 루프는 **프롬프트 조립 → 생성 → 후처리(1종 추출) → 게이트 4·5 판정 → 채택 또는
리롤**이고, 통과할 때까지 `--tries` 만큼 돈다.

**A 가 끝나면** 남은 둘을 무리째 돌린다:

```bash
npx tsx tools/regen-facility.ts --light-only --tries 3   # C군 8종 (그림자만 반대)
npx tsx tools/regen-facility.ts --geom-only --tries 3    # B군 10종 (각도만)
```

⚠ **C 를 B 보다 먼저** 하기를 권한다. B 의 절반은 문턱 바로 뒤(`footvolley` 2.5tx ·
`sunbed_row` 0.833/0.872)라 화면에서 거의 안 보이는데, C 는 **그림자가 통째로 반대쪽**이라
옆 시설과 나란히 놓이는 순간 눈에 띈다. 다만 이건 취향이지 규칙이 아니다.

그 밖의 선택자:

```bash
npx tsx tools/regen-facility.ts --severe                 # 심각 2종만 (airbounce · jump_cushion)
npx tsx tools/regen-facility.ts --all                    # 26종 전부 (A∪B∪C)
npx tsx tools/regen-facility.ts --id ticket              # 한 종
npx tsx tools/regen-facility.ts --id ticket --dry-run    # 프롬프트만 찍고 안 돌린다
npx tsx tools/regen-facility.ts --verify-gate            # 판정 복제가 게이트와 같은지
```

**대상은 손으로 적지 않는다.** 위 표를 읽는 게 아니라 팩을 **그 자리에서 재서** 고른다.
그림이 바뀌면 목록도 같이 움직인다.

⚠ **`--all` 의 뜻이 2026-08-23 에 넓어졌다** — 예전에는 접지 위반만이었고 지금은 **접지
∪ 광원**이다. 그전에는 "각도는 맞고 그림자만 반대"인 8종이 `--all` 에 **한 번도 안
들어갔다.** 게이트가 둘이면 대상도 둘의 합집합이어야 한다.

### 권한이 없는 세션 — 붙여넣기

이 저장소의 codex 계정에는 `image_gen` 권한이 **없다** (실측). 그 상태로 `--all` 을 돌리면
실패 로그만 쌓이므로, 도구는 그 오류 문자열을 알아보고 **즉시 전부 중단**한다 (종료 코드 2):

```
❌ 생성 불가 — 이 세션에서는 더 돌려도 전부 같은 이유로 실패한다:
   codex-gen: the built-in image_gen tool never ran in this codex session — …
   → image_gen 을 제공하는 codex 계정의 세션에서 다시 돌릴 것.
```

그래서 **붙여넣기용 프롬프트를 파일로 떠 놓았다**: `regen-prompts/<id>.txt`.
각 파일의 머리에 **첨부 3장이 순서대로** 적혀 있다 — 그 순서를 지킬 것.
프롬프트 본문이 번호로 첫 장(발자국 가이드)을 가리키므로 순서가 바뀌면 재현이 안 된다.

```
  첨부(순서대로): art-reference/guides/kairo/facility__airbounce.png ·
                  art-reference/crops/iso-inflatable-a.png · art-reference/ref-1.png
                  [크로마 magenta]
```

**지금 `regen-prompts/` 에 있는 것은 A군 8종**이다 (2026-08-23 에 다시 떴다 — 광원 지적
문단이 들어 있다).

⚠ **`regen-prompts/` 는 스냅샷이라 낡는다.** 한 번이라도 그림이 바뀌면 수치가 거짓이 된다
(예전에 `airbounce` 가 `vertex 32.5tx` 로 적혀 있었는데 실제로는 16.5tx 였다).
붙여넣기 전에 **반드시 다시 뜰 것**:

```bash
# A군 (기본). --light-only / --geom-only / --all 로 바꾸면 그 무리가 나온다
rm -f regen-prompts/*.txt
for id in $(npx tsx tools/regen-facility.ts --both --dry-run | sed -n 's/^\[[0-9]*\/[0-9]*\] \([a-z_]*\) .*/\1/p'); do
  npx tsx tools/regen-facility.ts --id "$id" --dry-run --print > "regen-prompts/$id.txt"
done
```

### 실패 모드를 말해 준다 — 이게 리롤과 다른 점

그냥 다시 뽑으면 같은 실수가 반복된다. 도구는 **직전 시도가 무엇을 틀렸는지**를
프롬프트에 적는다. `cafe` 의 실제 출력:

```
WHAT WENT WRONG LAST TIME — do not repeat it:
  - The previous attempt had the two footprint axes SWAPPED. Its ground bottom vertex
    measured at 0.556 of the sprite width, which is where a 3x2 footprint would put it —
    this object is 2x3, so the vertex belongs at 0.400. Do not mirror the guide. The W axis
    (2 tiles) runs toward the LOWER RIGHT and the D axis (3 tiles) runs toward the LOWER
    LEFT. Follow the attached guide's diamond exactly.
  - The previous attempt's ground silhouette overlapped the contract diamond by only IoU
    0.554 (it must reach 0.839). The base is not the right shape: it must be one clean 80x40
    px diamond with the object standing on it, with nothing sticking out below or beside it.
  - The previous attempt still needed to move sideways to sit on its own tile, but it was
    already touching the edge of its canvas, so it could not be moved at all. …
```

축뒤집힘일 때도 **가이드는 그대로 붙이고 뒤집힘을 말로 지목한다** ("which is where a 3x2
footprint would put it"). 왜 가이드를 안 뒤집는지는 §4.1.

### 채택 규칙 — 통과한 것을 덮어쓰지 않는다

1. 원본을 **먼저** `assets/generated/kairo-regen/<id>/backup.png` 로 백업한다
2. 후보는 **팩 밖**(작업 폴더)에서 판정한다 — 재려고 팩에 먼저 쓰지 않는다
3. 통과했거나 **엄격하게 나아졌을 때만** 채택한다. 판정 순서는
   통과 여부 → 위반 축 수 → 꼭짓점 오차 → IoU 부족 → 기울기 오차이고, **동점은 안 바꾼다**
4. 쓴 **뒤에** 다시 재서, 그래도 나아지지 않았으면 백업으로 되돌린다
5. `--strict-adopt` 를 주면 **통과만** 채택한다 (개선은 무시)

작업 폴더는 종마다 `prompt-N.txt` · `gen-N.png` · `cand-N.png` · `backup.png` 를 남긴다
(`assets/generated/` 아래라 gitignore 다).

⚠ 크로마 키는 **그림의 모서리에서 읽는다**. 가이드는 시트가 초록을 쓰든 말든 언제나
마젠타라(`make-kairo-guide.ts` 의 `BG`), 시트 크로마로 키하면 `keyed_pixels 0` 이 되어
캔버스 전체가 피사체가 된다 — 그 상태로 파라솔(면제 종)이 **게이트를 통과했다** (실측).

## 3. 판정

```bash
npx tsx tools/kairo-gate.ts             # 요약 — 접지·광원·회전을 한 화면에
npx tsx tools/kairo-gate.ts --geom      # 게이트 4 실측 표 전체 (통과분 포함)
npx tsx tools/kairo-gate.ts --light     # 게이트 5 실측 표 전체
npx tsx tools/regen-facility.ts --verify-gate   # 도구의 판정 복제가 게이트와 같은지
```

배치마다 돌린다. 요약 줄이 정본이다:

```
접지 기하 108장 측정 · 위반 18 (심각 2 · 축뒤집힘 0)
광원 방향 75장 측정 · 좌상단 43 · 뒤집힘 15 · 평탄 16 · 측정불가 1
```

### 통과 기준 — **`평탄` 은 위반이 아니다**

게이트 5 가 findings 에 넣는 것은 **`뒤집힘` 과 `측정불가` 뿐**이다. `평탄`(방향을 읽을 수
없다)은 세기만 하고 실패로 안 친다.

⚠ **이 규칙을 스스로 조이지 말 것.** 4방향 1차 시도가 정확히 그렇게 실패했다 —
그 도구가 `좌상단` 만 통과로 쳐서 **8장을 버렸는데**, `arcade`·`slide_tube` 는 **자기
원본이 평탄**이라 애초에 만족 불가능한 조건이었다 (`docs/assets/history/prompt-chain-4dir-retrospective.md` §0-2).
지금은 `regen-facility.ts` 의 `passed()` 가 게이트와 같은 기준을 쓰고, 단위 검사가
그것을 고정한다 (`평탄은 위반이 아니다 — 게임 게이트와 같은 기준`).

`측정불가` 를 통과에 넣지 않는 이유는 반대다 — **"못 쟀음"과 "괜찮음"은 다르다.**
`fishing` 이 오른쪽 벽 **1열**로 측정불가인데, 그건 잔교가 납작해서 세울 벽이 없다는
뜻이라 실제로 고칠 대상이다.

### 채택 규칙에 광원이 들어간다

`isBetter` 의 사전식 순서는 **`통과 → 접지 축 개수 → 광원 벌점 → 꼭짓점 → IoU → 기울기`**다.

- 광원 벌점: 좌상단 **0** · 평탄 **1** · 뒤집힘/측정불가 **2**
- ⚠ 광원이 **접지 뒤**인 것이 규칙이다 — 앞에 두면 **기하를 망가뜨리고 명암만 고친
  후보가 이긴다** (단위 검사가 고정한다)
- ⚠ 평탄이 0 이 아닌 것도 규칙이다 — 원본이 `좌상단` 인데 후보가 `평탄` 이면 **진다.**
  셰이딩을 잃는 교환을 막는다. 원본이 이미 평탄이면 동점이라 기하로 넘어간다

### ⚠ 채택 규칙의 알려진 틈 — 광원이 IoU 를 밀어낼 수 있다 (2026-08-23 실측)

순서가 `… → 접지 축 **개수** → 광원 벌점 → 꼭짓점 → IoU → …` 이므로, **같은 축이 계속
빨간 채로 IoU 만 나빠지고 광원이 좋아진 후보**는 이긴다. 1차 재생성에서 실제로 넷 나왔다:

| 시설 | IoU | 광원 | 채택 이유 |
|---|---|---|---|
| `ticket` | 0.724 → **0.649** | 뒤집힘 −15.6 → 좌상단 +22.6 | 축 수 동일(2) · 광원 벌점 2 → 0 |
| `dock` | 0.702 → 0.689 | 뒤집힘 −20.1 → 좌상단 +11.3 | 같음 |
| `maple_walk` | **1.000** → 0.910 | 뒤집힘 −11.7 → 평탄 +4.1 | 첫 축(`통과`)이 false → true |
| `parasol` | 0.605 → 0.549 | 뒤집힘 −25.7 → 평탄 +5.8 | 같음 (IoU 는 이 종의 면제 축) |

**의도한 동작이다** — 게이트를 하나 통과하게 되는 것이 축 하나가 조금 나빠지는 것보다
낫다. `maple_walk`·`parasol` 은 IoU 가 내려가도 **여전히 문턱 위**라 결과가 두 게이트
모두 통과다.

⚠ 다만 `ticket` 처럼 **어차피 다시 뽑을 종**은 다음 판의 출발점이 나빠진다. 그래서:

- 이 틈을 **연속값 가드로 막지 않았다.** 막으면 "광원을 고치는 유일한 후보"가 IoU 0.01
  차이로 거절되어 그 종이 영영 안 고쳐진다. 대신 **다음 판에서 그 종을 계속 대상으로
  둔다** (`--geom-only` 가 `ticket` 을 잡는다)
- 판정 뒤 **전/후를 눈으로** 볼 것. 숫자는 "게이트 하나를 더 통과했다"만 말한다

### ⚠ 게이트는 그림을 안 본다

**위반 0 을 만드는 변경이 오면 그림을 먼저 볼 것.** `tools/kairo-gate.ts` 머리말과 같은
문장이고, 실제로 그렇게 당했다 (§5.1). 게이트 4 가 재는 것은 **실루엣 최하단 윤곽**뿐이라
정본 다이아몬드를 아무 색으로나 메우면 세 축이 전부 만점이 된다 — **게이트를 만족시키는
가장 싼 방법이 그림을 망치는 방법이다.**

게이트 5 에도 같은 구멍이 있다: 왼쪽 면을 통째로 밝게 칠하면 점수가 오른다. 그래서 판정
뒤에는 **전/후 확대 이미지를 눈으로** 본다.

게이트 4·5 는 **경고**다 (`WARN_GATES` — 종료 코드에 안 들어간다. `--strict` 로 승격).
곧바로 실패로 만들면 에셋과 무관한 작업까지 전부 막히기 때문이고, 그동안 게이트는
**목록을 내는 일**을 한다 — 그 목록이 위 §1 이다.

## 4. ⚠ 하면 안 되는 것

넷 다 **실제로 해 보고** 접은 것이다. 다음 사람이 같은 시도를 반복하지 않도록 숫자를 남긴다.

### 4.1 가이드를 뒤집지 마라

축뒤집힘을 봤을 때 가장 먼저 떠오르는 수인데, **틀렸다.** 가이드는 엔진 정본 접지 마스크에서
파생되어 **구조적으로 옳고**, 뒤집으면 틀린 발자국을 첨부하게 된다. 그리고 좌우 반전은
무손실인데도 **실측 통과 0종**이었다 (나아짐 4 · 나빠짐 5 — §5.4 ①).
옳은 가이드를 붙이고 **프롬프트로 "지난번엔 두 축이 바뀌었다"를 지목**할 것 —
`tools/regen-facility.ts` 가 그렇게 한다.

### 4.2 후처리로 단색 채우기 — **아웃라인 계약을 깨고 "가라앉아 보인다"**

`tools/repair-kairo-footprint.py` 의 **마스크 단색 채움 분기**는 위반을 **56 → 0** 으로
만들었지만, 사용자가 화면에서 회귀를 보고해 **26종을 되돌렸다** (§5.1).
스타일 계약은 *"every object carries a baked 1-pixel dark warm outline"* 인데 이 분기는
`material_colour()` 가 고른 **한 색**으로 정본 다이아몬드를 메우고 **아래 테두리 한 줄에만**
아웃라인을 긋는다 — 새 실루엣의 옆·윗 가장자리에는 아웃라인이 **없다**
(실측 34~100%, 중앙 61%).

⚠ **게이트에 아웃라인 축을 더한다고 이게 닫히지 않는다** — 도구가 아웃라인까지 그려도
"다리를 지우고 판을 깐 그림"인 것은 같다. **접지 모양은 그림이 책임진다.**

### 4.3 후처리로 확대하지 마라

접지 폭이 계약과 맞는 것이 **24/75** 뿐이고 나머지 **51종은 비정수 배율**이 필요하다
(`vending_in` 1.600 · `photozone` 1.524 · `snow_sled` 1.297 …).
이 저장소의 렌더 계약은 **정수 스캔라인 · AA 금지**가 기반이다 (CLAUDE.md — "AA `fill()` 은
1px 이음새와 가짜 아웃라인을 만든다"). 비정수 리샘플은 도트 경계를 뭉개므로 각도를
고치려다 **화면 밀도**를 잃는다.

### 4.4 통과 49종·지면 33장을 건드리지 마라

`--all` 은 **지금 위반인 종만** 고른다 (접지 ∪ 광원). 목록을 손으로 넓히지 말 것 —
채택 규칙(§3)이 "동점은 안 바꾼다"인 이유와 같다. 지면 33장은 후처리가 기하를 강제하므로
33/33 통과다.

### 4.5 ⚠ 광원을 좌우 반전으로 고치지 마라

`caravan` 이 −51.7 이라고 좌우를 뒤집으면 점수는 +51.7 이 되지만 **발자국도 같이
뒤집힌다** — 접지 기하가 통째로 깨지고, 비정사각 발자국은 `축뒤집힘` 이 된다.
좌우 반전을 75종에 다 적용해 재본 결과가 **접지 통과 0종**이다 (§5.4).
프롬프트도 그렇게 말한다 (*"Do not mirror the previous image to fix this"*).

고치는 방법은 **같은 시점을 다시 칠하는 것**뿐이다: 화면 왼쪽 아래로 물러나는 면이 밝고,
오른쪽 아래로 물러나는 면이 어둡다.

## 5. 참고 — 왜 이 상태인가

### 5.1 되돌리기 기록 (2026-08-22, 26종)

같은 날 앞선 작업이 `python3 tools/repair-kairo-footprint.py --all-failing --adopt` 로
55종을 한꺼번에 수선해서 접지 위반을 **56 → 0** 으로 만들었다. 그런데 사용자가 **실제
화면에서** 회귀를 보고했다:

> "평상연립이나 탁구대같은경우 각도는 제대로인데 **꺼져있다**"
> "**그늘막은 완전히 틀어졌다**"

전/후 확대 대조(`shots/footprint-repair-audit/`)로 재보니 맞는 지적이었다. **접지 게이트는
기하만 보고 사람은 그림을 본다** — 게이트 0 은 그림이 좋아졌다는 뜻이 아니었다.

**무엇이 그림을 망쳤나** (수리 도구의 세 분기 중 단색 채움 분기 — §4.2):

1. **다리 사이·들린 바닥 밑의 빈 공간이 메워진다** — 탁구대·평상연립·전망대·정자·잔교가
   그렇게 죽었다. 다리가 사라지고 물건이 어두운 판에 잠긴 것처럼 읽힌다 (= "꺼져있다")
2. **물건 밖으로 아웃라인 없는 색판이 삐져나온다** — `material_colour()` 가 물건의 재질색을
   고르면(오리보트의 흰색 · 눈썰매의 크림색) 배경 위에 찢어진 종이 같은 조각이 생긴다
3. 그리고 **잘라내기 분기**가 타일 밖으로 뻗은 부속을 지운다 — 캐러밴 바퀴 · 트램펄린 앞
   테두리 · 분수 앞면 석벽 · 매표소 개찰구 (실측 원본의 10~17.5%)

⚠ **좌우 반전 분기는 정당하다** — 화소를 하나도 안 바꾸고 축뒤집힘만 되돌린다
(9종 실측: `footprint-mirror.png` 이 뒤집은 백업과 **바이트 동일**).

**되돌린 기준.** **정본 다이아몬드 넓이 대비 채운 화소 비율**(`채운 화소 ÷ 정본 마스크`)을
1차 선별로 쓰고, **전/후 4배 확대를 눈으로 보고** 판정했다. 눈으로 나쁜 것은 전부
**10% 이상**이었고 (최대 `fishing` 37.2%), 괜찮은 것은 그 아래였다. ⚠ 다만 10% 를 넘어도
**이미 있던 받침대를 메운 경우**(`rent_sup` 10.4% · 빈 공간 채움 29%)는 멀쩡했다 —
**단일 문턱으로 자동 판정하면 안 된다.** 잘라내기(`잘린 화소 ÷ 원본`)도 같은 방식으로
10% 를 선별선으로 썼다.

⚠ **직전 작업의 "색 종수" 분류는 미러링을 재고 있었다.** 수리 도구는 **언제나 두 색만**
더한다 (채움색 + 아웃라인색) — "색 15~35종이 늘었다"로 보인 것은 좌우 반전 때문에 화소가
통째로 어긋나서지 색이 는 게 아니다. 그래서 **미러링과 단색 채움은 서로 독립**이고,
`airbounce`·`caravan`·`ticket` 은 **둘 다** 일어난 종이다 — 이 셋은 백업이 아니라
`footprint-mirror.png`(순수 반전)로 되돌려 **축 수리는 살리고 색판만 버렸다.**

| 되돌림 | id | 채움/마스크 | 잘림/원본 | 눈으로 본 것 |
|---|---|---|---|---|
| 낚시터 | `fishing` | 37.2% | 9.5% | 뗏목 옆면이 평판으로 바뀌고 낚싯대가 잘림 |
| 전망대 | `lookout` | 32.4% | 1.6% | 망루 아래 빈 공간이 통째로 메워져 기둥이 사라짐 |
| 붕어빵 | `bungeoppang` | 27.0% | 4.4% | 검붉은 색판이 왼쪽·앞으로 흘러나옴 |

### 5.5 표를 다시 뽑는 법

```bash
npx tsx tools/regen-table.ts          # §1 의 표 셋 (A·B·C)
npx tsx tools/regen-table.ts --pass   # 「건드리지 말 것」의 통과 목록
```

출력을 §1 에 그대로 덮어쓴다. 표 끝의 HTML 주석이 그 판의 개수를 담고 있으므로,
문서의 숫자와 실측이 갈라졌는지 눈으로 대조할 수 있다.

⚠ **예전에는 이 생성기가 문서 안의 코드블록이었다.** 그러면 (1) 아무도 안 돌리고
(2) 돌려도 문서의 사본과 실제 게이트가 갈라졌는지 알 방법이 없다. 도구로 옮겼다
(`tools/regen-table.ts`) — 게이트 함수를 **직접 부르므로** 판정이 갈라질 자리가 없다.

`수리 이력` 열만은 실측이 아니라 **이 문서 §5.1 의 되돌림 표를 되읽어** 만든다.
사람이 겪은 일의 기록이라 그림에서 유도할 수 없다.
