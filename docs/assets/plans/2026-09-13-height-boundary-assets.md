# 높낮이 지형의 길·부지·실내 경계 에셋 생성 계획

2026-09-13 사용자 수정: 실내에는 높이를 적용하지 않는다. 실내 기초 3종은 후속 제작/채택 범위에서 제외한다. 잔여 제작 목록은 9종(기본 36장)이며, 현재 우선 작업은 목재 경사 울타리 재검토다. 기존 기초 파일은 실험 기록으로만 보존한다.

상태: 경사로·계단·목재 경사 울타리의 실제 게임 연결 완료(2026-09-13). 기존 1칸 경사 시연 기준의 바닥 모듈이며 아래 초기 1×2 초안을 그대로 채택한 것은 아니다. 옹벽 3종·보도 턱 2종·독립 전환 기둥은 미완료. 실내 기초는 제외. 자세한 현재 범위는 `codex-output/height-live-integration-v1/README.md` 참조.

## 목표

가평 풍경의 기존 돌길·목재 울타리·유리 실내벽에 어울리는 단차 연결 부품을 만든다. 높은 평탄지에는 건물을 놓을 수 있고, 길은 NPC 이동을, 울타리는 공원 경계를, 보도 턱은 길과 시설 부지의 시각적 구분을 담당한다. 울타리 자체가 소유권이나 실내 판정을 만들지는 않는다.

## 확인한 현재 구현

- terrain.ts: 지형 높이 0~3, 물은 높이 0, 플레이어 지형 변형은 현재 설계에서 제외.
- iso.ts 기본 LEVEL_H=8과 달리 현재 기본 KairoTerrainV3SourceProvider.terrainLevelHeight()는 16. 제작 기준은 실제 라이브 16 logical px/단. 현재 환경 검토 맵의 기본 procedural provider 높이로 측정하면 안 된다.
- placement.ts: 기존 육상 시설은 footprint 전체 levelUniform 필수. 경사 연결 시설에만 명시적인 예외 계약이 필요하다.
- terrain.levelPassable: 높이 차이 <=1이면 현재 이동 허용. “계단/경사로 없으면 이동 불가”는 아직 구현되지 않았다.
- 실내 판정은 실내 바닥, 벽은 그 결과. 유리 소재 자체로 실내가 생기지 않는다. 연결된 실내 전체의 동일 높이 제한은 별도 검증/구현 대상이다.
- 기존 직선/모서리/끝 울타리, 돌담, 유리벽, 문, 보도/실내바닥은 재사용한다.

## 신규 제작 목록 — 12개 모듈, 기본 4방향 총 48장

| 묶음 | 모듈 | 수 | 배치 규격 초안 |
|---|---|---:|---|
| NPC 길 연결 | 낮은 석재 계단 / 돌포장 경사로 | 2 | 각각 폭 1칸 × 길이 2칸, 양 끝 1단 차이 |
| 경사 울타리 | 목재 경사 직선 / 평지-경사 전환 기둥 | 2 | 경사 직선 1칸 구간, 기둥은 연결부 공유 |
| 단차 옹벽 | 직선 / 안쪽 모서리 / 바깥쪽 모서리 | 3 | 한 단 높이, 지형 경계 부착 |
| 보도 구분 | 경사 보도 턱 / 평지-경사 전환 턱 | 2 | 길 가장자리 구간; 평지 직선은 기존 재질로 연결 |
| 실내 기초 | 직선 기초벽 / 안쪽 모서리 / 바깥쪽 모서리 | 3 | 평탄한 실내 아래에 붙는 경계 부품 |

12종은 원본 모듈 수다. 기본 색상 1세트 × d0~d3=48장은 빈 상태 전체 렌더 기준이다. 기둥·난간·앞쪽 벽 등의 가림 레이어, 검증 이미지, 최종 아틀라스 패킹 프레임은 별도이므로 총 파일 수를 48로 제한하지 않는다. 내·외 모서리는 별도 원본이고, 한 모델의 반사로 대체하지 않는다.

2~3단 높이용 옹벽은 한 단 모듈을 수직 결합하는 것을 우선 검증한다. 중복 테두리·틈·두꺼운 끝마감이 생기면 상단 캡/중간 부품을 추가 산정한다. 최초 12종에 무한 높이 대응을 약속하지 않는다. 계단·경사로는 첫 버전에서 1단 차이만 연결한다.

## 공통 제작 규격

- ppaji-kairo-assets의 authored Blender + 기존 shared B painted materials 방식.
- 기존 NPC 실루엣과 바닥 타일 비율 유지. 지면 32×16 logical px, 수직 1단 16 logical px를 실제 provider에서 검증.
- 같은 물리 원본을 고정 카메라 아래서 0/90/180/270도 회전. 상행/하행을 별도 창작하지 않는다.
- 목재는 기존 울타리, 석재는 기존 보도/돌담의 색과 질감에 맞춘다. 글자·브랜드·사람을 에셋에 굽지 않는다.
- 계단/경사로: 지면 접촉·지지 기초를 포함한 full-footprint-integral 구조를 우선한다. 경사지지 형상 검증은 평평한 시설 바닥 검사와 구별한다.
- 경계 부품: transparent-no-floor. 별도 바닥 다이아몬드 없이 기둥/옹벽 자체가 지형에 접촉해야 한다.
- 기둥·난간 등 사람이 앞뒤로 지나는 요소는 처음부터 분리 가능한 물리 그룹으로 작성한다. 기존 매표소의 단일 NPC 동적 깊이 시연을 여러 NPC용 구현으로 간주하지 않는다.
- 전환 기둥, 코너, 끝마감의 공유 규칙으로 중복 기둥 방지. 앞뒤 가림은 발 위치와 실제 부품 좌표로 검증한다.

## 단계별 제작

1. **현재 높이 맵에서 규격 고정**
   실제 라이브 provider로 평지/1단/2단/3단 검증 구역 구성. 길과 경계가 만나는 좌표·고저 방향·타일 점유·문 연결을 기록한다. 기존 시설/세이브를 덮지 않는 별도 검토 모드로 만든다.
2. **대표 3종 컨셉 및 d0 파일럿**
   계단, 경사 울타리, 실내 기초+기존 유리벽 조합을 사람 크기와 함께 비교. 기초+유리벽 조합에서는 기초만 신규 모델이다. 기존 재질 기준 시안과 동일 배율 Blender d0 후보를 순차로 제시하고 형태·경사·높이를 먼저 검토한다.
3. **대표 3종 네 방향·움직임 검증**
   실제 높이 맵에 올려 양방향 NPC, 계단 발 접촉, 기둥 가림, 실내 출입구를 확인한다. 통로가 막힌 경우, 측면 진입, 반대 방향 이동도 확인한다. 대표 3종은 기본 12장.
4. **나머지 9개 모듈 제작**
   승인된 재질/높이/접합 규격으로 경사로, 옹벽/기초 모서리, 보도 전환부를 제작한다. 기본 추가 36장. 방향별 원본 SHA·좌표·접합 증거를 보관한다.
5. **연결 테스트 맵 및 사용자 검토**
   긴 직선, 오목/볼록 코너, 평지-경사-평지, 옹벽 위 울타리, 높은 실내 바닥+유리벽+문, 매표소 연결, 여러 NPC의 앞뒤 통과를 한 검토 맵에서 보여준다.
6. **승인 후 게임 연결**
   에셋 채택과 이동/건설 규칙을 함께 연결한다. 전체 시설과 기존 지형의 픽셀/좌표를 보존한다. 저장 왕복, 네 방향 경로, 지형 고도 보정, 결정론, 관련 테스트/빌드 후 완료한다.

## 게임 연결 시 규칙 제안

- 일반 건물과 연결된 실내 바닥은 같은 높이의 평탄지에만 허용. 높은 지형 자체를 금지하지 않는다.
- 실내 기초는 원래 존재하는 높은 평탄지의 노출 측면을 마감한다. 기초 설치로 임의의 땅을 평탄화하거나 지형을 높이지 않는다.
- 평지 울타리는 같은 높이 구간, 경사 울타리는 1단 연결, 큰 단차는 옹벽+상단 울타리 조합으로 구분한다.
- 보도 턱은 시각적 구분이 기본이며 NPC 통행을 자동 차단하지 않는다. 통행 차단은 벽/울타리, 걸을 수 있는 칸은 길/실내 바닥, 건설 허용은 토지/지형/시설 규칙이 결정한다.
- 실내 외벽은 수직 유지. 경사 벽으로 방을 잇지 않는다. 다른 높이의 실내는 별도 구역으로 두고 실외 계단/경사로를 경유한다.
- 계단/경사로의 고저 끝과 이동 방향을 local 좌표로 선언하고 시설 회전과 같이 변환한다. 전체 시설에 levelUniform 예외를 주지 않는다.
- 연결부 없는 1단 이동 제한은 에셋만으로 해결되지 않는다. 기존 세이브의 단차 길을 검사해 연결부 보완/호환 방안을 먼저 검증한 다음 적용한다. 기존 손님·매표소·실내 출입 경로를 갑자기 끊는 변경은 채택하지 않는다.

## 완료 조건

- 동일 배율의 4방향 물리 회전, 부품 접합, 네 방향 높이 보정, 알파/클리핑 검사 통과.
- 모든 고저 방향의 양방향 이동과 차단이 그림과 일치. 여러 NPC에서도 기둥/벽/옹벽 가림이 유지됨.
- 높은 실내의 바닥/벽/문/기초가 같은 규칙을 사용하고 문 앞길이 연결됨.
- 스프라이트 위치를 임의로 움직여 단차 불일치를 숨기지 않음.
- 사용자 시각 검토를 통과한 후보만 라이브 채택. 제작 성공/자동 검사를 사용자 승인으로 기록하지 않음.

우선 착수 범위: 대표 3종. 매표소 v2 수정 후보의 최종 채택은 이 제작 묶음과 별도로 유지한다.
