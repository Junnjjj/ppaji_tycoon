## 벽 표시 방식

물리 원본은 지붕 없는 4면의 방과 실제 -Y 출입구를 가진다. 같은 루트의 네 방향을 그대로 렌더하고 저장본 재열기 비교로 검증한다. 별도 표시본에서는 `cutaway_side` 메쉬의 회전된 바깥 법선과 카메라 방향을 비교해 가까운 두 벽만 생략한다. 가구·입구·슬롯·기계는 회전 외 재배치하지 않는다. 벽에 붙은 장식은 해당 벽과 함께 숨긴다.

이것은 두 벽의 위치를 매번 바꾸는 물리 모델이 아니라 **하나의 물리 모델에 대한 방향별 벽 표시 규칙**이다. 시연의 `전체 벽 구조 보기`는 가림을 생략하지 않은 물리 원본과 비교한다(이 모드의 인물은 숨긴다). 출입 동선 검사에는 표시에서 숨긴 벽도 계속 장애물로 포함된다.

`integration/export-presentation.py`는 매번 저장 원본을 읽어 동일한 표시 마스크로 그림과 raycast depth를 만든다. 원본을 저장/수정하지 않는다. 두 번째 Blender 프로세스로 네 방향을 다시 렌더하고 RGBA 일치를 검사한다.

## 비율·상호작용

- 타일 32×16, T=sqrt(512), 카메라60/0/45, ortho/native192, density4, targetZ=.6tile 유지.
- 승인 V8 NPC 54외형 재사용, 불투명 서기 키22px. 시설별 NPC 크기 조절 없음.
- 기존 걷기/서기/착석/눕기 자세 사용. `stand`는 기존 `idle` 스프라이트의 의미상 별칭이다. 전용 착석/기립/계산/버튼조작 애니메이션을 새로 만든 것이 아니다.
- `interaction.json`이 중심 기준 Blender XY 타일 좌표의 입구/슬롯/경로 원본. 같은 회전을 적용한다. 각 시설의 접근 종류(portal/service-face/staff-only)를 구분한다.
- 서비스 시설의 손님은 외부 공용 통로에 서서 이용한다. 개방형이라고 모든 방향에 계산대나 기계 버튼을 복제하지 않는다. 매점 지붕·가구와 락커 후면의 자연스러운 가림은 남는다.
- 기존 크기와 제안 크기는 구분하며 메인 시설 데이터와 저장 배치를 변경하지 않는다. 크기 변경 채택 시 새 건설 항목으로 추가하고 기존 배치를 보존한다.

## 메인 연결 전 남은 경계

이 시연은 별도 Canvas 화면이며 실제 Phaser/GuestStore/직원/경제·정원·저장복원을 바꾸지 않는다. 시설별 슬롯 수는 물리 시연 자리 수이지 현재 게임 정원 변경이 아니다. 실제 적용 시 최신 메인 구조에 접근 계약·회전·상태 취소·철거·세이브 복원과 레이어를 연결해야 한다.

래스터 선 검출 FAIL/WARN은 각 원본 보고서에 유지한다. 저장된 실제 카메라/메시 투영 증거와 분리하며, 기술적 재현 검사가 사용자 미술 승인이나 실제 게임 검증을 대신하지 않는다.
