# K47 — HUD 재설계(뉴스 티커) + 카이로식 조준 배치

확정 설계. 근거는 `docs/research/pss-*.md` 3종(위키 수집 2 + 헤르메스 리서치)과
2026-08-20 병렬 정합성 조사 2건. **이 문서가 K47 의 정본이다.**

---

## 0. 왜

사용자 실플레이 지적 둘: ① 하단 버튼 위치·구조가 마음에 안 든다 ② 카이로에는
**뉴스 배너**가 있고 그것이 포인트다. 여기에 리서치가 붙었다 — PSS 부정 리뷰 1위가
**팝업 과다**이고, 처방이 "모달 대신 알림함 적재 · 강제 중단은 큰 사건만"이다.

우리 문제의 정체: 사건 채널이 **모달/토스트 둘뿐**이라 "내가 안 했는데 일어난 일"이
갈 곳이 없다. 그래서 소원 개시 같은 것이 시간을 멈추고, 의뢰 달성은 **아예 무음**이다.

## 1. 채널 계약 (K47 의 핵심 — 되돌리지 말 것)

| 채널 | 규칙 | 무엇이 가나 |
|---|---|---|
| **모달** (K41 그대로) | 시간 멈춤 · 큰 사건만 | 시설 해금 · 승급/탈락 · 새 도구 · 인물 등장 · 숨은 콤보 · 보상 시설 |
| **티커** (신규) | 비차단 · 띠에 흐르고 알림함에 쌓임 | 하루 마감 · 주말 · 강등 · 소원 개시/성사 · 콤보 발동 · 의뢰 달성 · 결산 도착 · 심사 D-day · 손님 마일스톤 |
| **토스트** (그대로) | 내 행동의 즉각 대답 | 거절 이유 · 확정 −N만 |

한 줄 요약: **모달 = 축하, 티커 = 뉴스, 토스트 = 대답.**
같은 사건이 두 채널에 가는 것은 승급/결산뿐 (모달 축하 + 알림함 기록).

⚠ 티커 띠는 **`div` + `role="button"`** 이다. `<button>` 으로 만들면 하네스가
`button,select,input` 을 세어 상시 컨트롤 수와 44px 터치 타깃을 판정하므로
26px 띠가 검사 4건을 확정 실패시킨다 (의뢰 칩 기둥이 div 인 것과 같은 이유).

⚠ 알림함 항목은 **저장하지 않는다** (세션 전용). 뉴스는 상태가 아니라 흐름이고,
세이브에 넣으면 마이그레이션 짐이 된다. 단 **손님 누적 카운터**는 마일스톤 판정에
필요하므로 세이브의 **optional 필드**로 둔다 (optional 이면 마이그레이션 불필요 —
`weekSkip` 선례).

## 2. 화면 배치 (전수 재설계 — 기존 배치를 전제하지 않았다)

원칙 둘: **읽는 것은 위, 누르는 것은 아래** (폰 상단은 엄지 사각지대) ·
**사건은 전용 채널로** (모달로 막으면 팝업 과다, 토스트로만 흘리면 놓침).

```
헤더 1줄: 🌤 날씨 · 주1 월·여름·10:24 · ◎500만        ← 읽기 전용
헤더 2줄: 😊72% · 👥128 · ⭐2등급 · 🟢안전            ← 위험도가 여기로 (버튼 0)
의뢰 칩:  (칩 머리 탭 = 접기, 칩 탭 = 메뉴)
             ── 지도 ──
티커:     📰 결산 도착 · 콤보 발동 …  (탭 = 알림함)
하단 바:  [메뉴]                [건설]                ← 상시 컨트롤 2개
```

- **제거**: 하루»/주 스킵 · 헤더 리포트 버튼 · 목표▾ 버튼 · 하단 위험도 칩 · 안내문
- **근거(스킵 제거)**: 시간은 흐르는 낮으로 이미 자동(하루 24초)이고, PSS 도 본편에
  스킵이 없다(빨리감기는 엔드게임 보상 하나). 스킵을 누르고 싶은 순간은 "할 게 없다"는
  신호이므로 스킵으로 가릴 게 아니라 원인(목표 밀도)을 고친다. 첫 심사 보상은
  **이동 붓만** 남는다. 배속 2× 는 메뉴에 유지.
- ⚠ 관찰 항목: 한 주 = 168초(2× 면 84초)가 "폰 2분 세션"과 맞는지. 실플레이에서
  스킵 요구가 다시 나오면 그때 "첫 심사 보상 ⏩"으로 복구한다 (복구 비용이 싸다).

## 3. 카이로식 조준 배치

지금은 "시설 선택 → 지도에서 칸을 탭 → 고스트 → 확정"이다. 바꿀 방식:
**시설 선택 → 고스트가 화면 중앙에 뜸 → 지도를 팬해서 정렬 → 확정.**
손가락이 고스트를 가리지 않는 것이 원작이 이 방식을 쓰는 이유다.

### ⚠ 가장 큰 함정 — 순진한 "중앙 고정"은 판의 32%를 배치 불가로 만든다

카메라 클램프(`range()` 가 뷰를 `worldBounds` 안에 가둔다) 때문에 **화면 중앙이
갈 수 있는 범위가 제한된다.** 실측: S=1 · 5등급 토지(96×64)에서 커버 **68%** —
남쪽 `i+j ≥ 120` 삼각형과 동서 끝이 영원히 중앙에 못 온다.

**처방: 고스트가 정본이고 레티클은 화면 표시일 뿐이다.**
팬은 "레티클 칸의 **증분**"만 고스트에 더한다. 클램프에 닿으면 고스트가 중앙에서
밀려나며 가장자리까지 따라간다. 필요한 최대 오프셋(S=1 에서 x 180.5 · y 378)이
반뷰(196.5 · 426)보다 항상 작으므로 **100% 커버가 수학적으로 보장**된다.

⚠ 클램프를 배치 모드에서 푸는 것은 **금지** — `BACKDROP 48` 은 "하늘이 어디서도
안 보인다" 검사의 근거이고, 지도 바깥 굽기 여백은 `SURROUND_PAD 128` 뿐이다.
반화면을 더 밀면 하늘이 샌다. PAD 를 키우면 구운 캔버스가 19MB → 32MB (폰에서 위험).

### 상태 기계

```
없음 ──(시트에서 픽)──▶ AIMING
AIMING: ghost = {i, j, facing}          ← 정본
  · 팬 → ghost += (지금 레티클 칸 − 직전 레티클 칸)   ※ 증분이라 오프셋 보존
  · ↻ → facing 토글 + 같은 자리 재판정   (⚠ tapTile 재호출 우회를 없앨 것)
  · 탭 → ghost = 탭한 칸 (성긴 조준. **확정 아님**)   ← 하네스 호환 다리
  · 배율 변경 후 → centerOn(tileCenter(ghost))       ← 고스트를 레티클 밑으로 되돌림
  · 칸이 바뀐 프레임에만 check() → setGhost(ok) + showConfirm
AIMING ──확정──▶ place()  (시설: 종료 / 바닥·건물: AIMING 유지 = 연속 배치)
AIMING ──취소·붓 교체·패널 열림·코스 편집──▶ 없음
```

판정 비용 실측(96×72 시작킷 판): 야외 0.054ms · 실내 0.325ms · 물 위 0.240ms
(`riverZones` flood 는 `wantsWater && permitArea !== undefined` 일 때만 돈다).
폰 3~5배로 잡아도 최악 1.6ms — **매 프레임은 위험, 칸이 바뀔 때만이면 무료.**

### 붓별 판정

| 붓 | 방식 | 근거 |
|---|---|---|
| 시설 | **조준 + ↻ + 확정** | 손가락 가림이 정확히 이 케이스 |
| 건물 블록 · 바닥 1/2/3칸 | **조준 + 확정** (확정 후 바 유지 = 연속 배치) | 4×4 = 48만원이 지금은 탭 한 번에 즉시 지출. 미리보기가 아예 없다. ⚠ 드래그 페인트는 안 넣는다 — 한 손가락 드래그 = 팬이 이미 확정이라 제스처 문법이 둘이 된다 |
| 철거 | **조준 + 확정으로 승격** | 지금은 탭 즉시 삭제 + 50% 환급, 되돌리기 없음, 하네스 동작 검사 0건 |
| 이동 | 1단계(대상)는 탭, 2단계(목적지)는 조준 + 확정 | 목적지는 시설과 같은 문제 |
| 출입구 · 코스 | **탭 유지** | 배치가 아니라 대상 지정 + 순환. 코스 핸들은 K33 계약대로 화면에서 끈다 |

### 십자 화살표는 넣지 않는다

확정 바 한 줄 예산(377px)에 44px 화살표 4개(176px)가 안 들어가고, 오프셋 방식이
커버를 보장하므로 기능적으로 불필요하다. 미세 조정도 팬 8~16텍셀이면 한 칸이다.

### ⚠ 같이 고치는 원버그 — 조준 중 시간이 흐른다

확정 바는 `PanelHost` 패널이 아니라서 `flowTick` 이 안 멈춘다. 지금도 **확정 바를
띄운 채 주가 마감 → 결산 위로 확정 클릭 → 옛 현금 기준 지출**이 가능하다. 조준
배치는 조준 시간을 수 초로 늘려 확률을 키우므로 `hud.confirming` 이면 tick 을
멈춘다. ⚠ 확정 바를 PanelHost 에 **등록하지는 말 것** — 스크림 없는 바라 배타
규칙이 시트/결산과 충돌한다. 대신 시트가 열릴 때 `hideConfirm()` 을 부른다.

### 신규 검사 (전부 ★ = 진짜 터치)
- 팬으로 정렬해 시설을 놓는다 · **음성**: 팬만 하고 확정을 안 누르면 안 놓인다
- **★ 지도 가장자리 칸에 놓을 수 있다** (5등급 토지의 `i+j` 최대 · `i−j` 양끝 3곳) —
  §3 의 32% 구멍을 잡는 **유일한** 검사. 음성 대조군은 코드에 심는다
  (`setRenderFaultForTest` 패턴: 오프셋 로직을 끄면 = 중앙 고정이면 실패해야 한다)
- 조준 중에는 시간이 안 흐른다 · 팬 중 판정이 갱신된다 · 배율을 바꿔도 고스트가 남는다
- 티커: 소식이 흐른다 · 탭 → 알림함 · 티커는 시간을 안 멈춘다(알림함은 멈춘다) ·
  붓 라벨을 받는다

### 갱신할 기존 검사
`#kairo-week` 참조 5곳(⚠ 4120 은 스크린샷 clip 이라 **null deref 로 런 전체가 죽는다**) ·
상시 컨트롤 5 → 2 · HUD 예산 재측정(전폭 티커가 가로 +6.6% — 초과 시 재협상) ·
목표 접기 검사 · 배치 검사 ~10건(조준 + 확정 클릭 한 줄 추가로 대부분 생존).
**호환 다리**: `__kairo.tapTile(i,j)` 를 "조준을 그 칸으로 옮긴다"로 재정의한다.

## 5. 하지 않을 것

- 티커에 버튼·칩 늘어놓기 (띠 전체 = 탭 대상 하나)
- 알림함 저장 · 뉴스별 개별 보상 수령
- PSS 식 SNS 좋아요 시스템 (뉴스 채널만 먼저 — SNS 는 별도 설계)
- 확정 바 2행화 (세로 예산 검사가 있다 — 계획 시점 ≤22%, ② 에서 **≤24%** 로 확정)
