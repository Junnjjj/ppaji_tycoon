## 1. 목표와 불변

**목표:** 공원이 살아 있는 낮을 기본 상태로 만들고, 해금을 "벽이 열림"에서
"선물이 도착함"으로 바꾼다. 타겟은 쉽게 하는 플레이어 — 구경이 유효한 플레이여야 한다.

**깨지 않는 것 (기존 불변식 전부 + 이 설계의 전제):**
- sim 결정론·렌더러 비의존·데이터 주도 (CLAUDE.md 불변식 1~3)
- 결산 순서 히트맵 → 요일 막대 → 숫자 · 카드는 모달 · 위험도 상시 표시
- 시설은 탭 → 고스트 → 확정 · 바닥은 사는 것 · 플레이어는 지형을 깎지 않는다
- 프리미엄 유료 — 방치(오프라인) 진행 없음, 광고·IAP 없음

## 2. 시간 — 흐르는 낮, 주 마디

### 2.1 상태 기계

```
[흐름]  지도만 보이는 동안 sim tick 이 실시간으로 소비된다
   │      기본 1×: 하루(120 tick) = 48초 (tick당 0.4초) ⚖ · 배속 2× 토글
   ├─ 멈춤: 시트·패널·카드·결산이 열리면, 앱이 백그라운드면
   ├─ 하루 끝: 토스트 한 줄 (모달 아님, 2초): "3일차 (수) · +32만 · 손님 41"
   ├─ 주말 진입: 토스트 "주말 — 손님이 몰립니다" (sim 의 1.6× 는 이미 있다, 표기만 추가)
   └─ 7일째 밤 → [주 마디]
[주 마디]  결산 (지금 그대로) → 닫으면 → [흐름] (카드는 월요일 아침에 — 아래)
[빨리 감기]  ⏩ 기본 = 하루 끝까지. 주말(결산)까지 스킵은 첫 심사 통과로 해금
```

- **⏩ 는 이단이다 (A2)** — 기본은 `하루 끝까지`, `결산까지` 는 **첫 심사 통과 보상**.
  PSS 가 배속을 엔드게임에 해금하는 이유와 같다: 구경이 핵심 보상인데 첫 주부터
  스킵을 주면 신규가 보상을 건너뛰고 엑셀 게임으로 회귀한다. 2× 토글은 관찰
  유지형이므로 처음부터 준다. 상시 컨트롤 3개 규칙 유지 (⏩ 가 `한 주 ▶` 자리)
- **결산 → 카드 순서** (지금은 카드가 먼저다). 카드의 적용 의미는 유지하되, **등장은
  월요일 아침 흐름 속에서** (A6) — 모달인 건 그대로다 (선택 전에 주가 넘어가면 안 된다).
  ⏩(결산까지) 경로에서는 지금처럼 선제시
- **사건은 낮에 도착한다 (A6)** — 주 경계 tick 에서 **판정**된 사건(소원 발생·해금
  확정·인물 등장)은 다음 날 아침 흐름 중에 **연출로 도착**한다 (인물이 걸어 들어와
  말풍선, 입고 토스트). 판정(sim·결정론)과 연출(도착 시각)의 분리가 핵심 — sim 은
  여전히 주 경계의 tick 함수이고, 렌더가 도착 큐를 하루에 걸쳐 풀어낸다
- **48초의 확정 기준은 화면 밀도다** — K39 에서 "분당 가시 사건 수"(도착·이모트·
  콤보 반짝·토스트)를 계측해 시작 판 기준 **분당 ≥ 6 ⚖** 이 되도록 48±12초 안에서
  맞춘다. 우리 하루는 PSS(1년=16일)보다 사건 밀도가 구조적으로 낮으므로, 길이가 아니라
  **도착 분산(A6)** 으로 보상한다
- 낮밤 톤: 하루 안에서 아침/낮/저녁 틴트 (렌더 전용 — sim 은 모른다).
  `prefers-reduced-motion` 이면 틴트 전환을 즉시로
- 압축 연출(`playWeek`)과 결산 `다시 보기`는 **제거** — 낮을 이미 봤다.
  `PlaybackFrame` 파이프는 걷어낸다 (세이브에 없으므로 마이그레이션 불요)

### 2.2 sim 구조 — WeekRunner 를 3단으로 쪼갠다

```ts
runner.begin(rng, opts)   // 주 상태 초기화 (카드 효과·날씨·버스 시계)
runner.step(n)            // tick n개 소비 — 흐름 모드가 프레임마다 부른다
runner.finish(): WeekReport
runner.run(rng, opts)     // = begin + step(840) + finish  ← 헤드리스·골든은 이것만
```

**항등 검사가 이 설계의 심장이다:** `run()` ≡ `begin + 임의 분할 step + finish`
(같은 시드에서 결산 완전 일치). 이게 성립하면 골든·밸런싱·결정론이 전부 보존된다.

- **주 중간 건설 허용** — 흐름 중에 지으면 그 주 결산에 섞인다. 이것이 "배치 직후
  피드백"의 절반이다 (놓자마자 손님이 몰리는 게 보인다)
- **봇·골든은 주 경계에서만 짓는다** (지금 그대로) — 골든 비교가 유효하게 남는다
- 흐름 모드의 렌더는 기존 손님 그리기(보간·`spanDepthKey`)를 그대로 쓴다 —
  재생 프레임이 아니라 **살아 있는 GuestStore** 에서 읽는다

## 3. 해금 — 다섯 갈래 사건

### 3.1 시설 73종 재배분 ⚖

| 갈래 | 개수 | 원칙 |
|---|---|---|
| 등급 골격 | 1등급 **18** + 2~5등급 각 4~5 = **36** | 시작 킷·첫 의뢰 수행에 필요한 것은 전부 1등급 |
| 의뢰 보상 | **14** | 의뢰 16종 중 14종의 보상을 현금 → 시설/장비로 (초반 자금용 2종만 현금 유지) |
| 소원 보상 | **12** | §3.3 |
| 숨은 콤보 발견 | **6** | §3.4 |
| 계절 입고 | **5** | §3.5 |

개별 배정표는 데이터 PR 에서 확정한다 (원칙: 상위 호환 시설은 골격에, 개성 시설은 사건에).

### 3.2 등급 = 심사 (수동 문턱 → 능동 시험)

```
응시 자격: 기존 reqExitSatisfaction (55/65/75/85) 충족  ← 데이터 재사용
신청: 목표란/메뉴에서. 수수료 ⚖ (등급×50만)
준비: 신청 시점부터 그 주 주말까지 — 요구조건 2~3개가 즉시 공개된다
      (조건은 의뢰 condition 풀 재사용: needSupply·facilityCount + 지표 조건 신설)
심사: 주말에 심사관(특별 손님 1명)이 게이트로 걸어 들어온다 — 흐르는 낮에 보인다.
      준비 기간은 **최소 2일 보장** — 목요일 이후 신청은 다음 주 주말 심사 (A2 부속)
채점: 조건당 10점 부분 점수. 커트라인 = 총점의 75% ⚖ — 만점을 요구하지 않는다
실패: 다음 계절 재응시 (수수료 재지불). 성공: 등급업 + 보상
첫 통과 보상: 이동 도구 (§4.1) — PSS 의 Move 선물 그대로
```

허가 면적·토지·정원·수요 배수는 지금처럼 등급에 딸린다. 바뀌는 건 **열리는 방식**뿐이다.

### 3.3 손님 소원 체인

- 인물 **8명** (친구·커플·가족·단체 × 각 2명 ⚖). `kairo-wishes.json` 신설
- **인물은 사슬로 등장한다 (A5)** — 시작은 2명뿐. 소원 완수 보상에 **다음 인물 등장**이
  포함된다 (PSS "rewards include new visitors"). 해금이 해금을 부르는 사슬의 복원
- 진행: 해당 유형 손님의 주간 퇴장 만족도·이용 횟수가 인물 EXP 로 쌓인다
  (개별 추적 아님 — 유형 집계에서 파생. sim 부담 최소)
- EXP 문턱마다 소원 (인당 3개, 조건은 의뢰 condition 풀): "가족이 쉴 그늘이 부족해요 —
  그늘막 2개" → 완료 보상 = 시설/장비 해금 (12개) · 다음 인물 · 현금/버프
- 화면: 인물은 이름표 달린 손님으로 등장 (에셋은 기존 스프라이트 + 이름표 — 에셋
  일괄 생산은 여전히 마지막). 소원 발생은 다음 날 아침 그 인물이 걸어 들어와
  말풍선으로 도착한다 (A6)
- **등급 5 이후에도 남은 소원은 계속 도착한다** — 후반 공백의 첫 번째 답

### 3.4 숨은 콤보 = 발견

- 콤보 70종 중 **~25종 ⚖** 에 `hidden: true` — 도감에 `???` 로 표시
- 처음 발동시키면: 반짝임 + 토스트 (`숨은 조합 발견!`) + 도감 기입 + 보상
  (6종은 시설 해금, 나머지는 현금 ⚖)
- 콤보 감지는 이미 돌고 있다 — "첫 발동" 이벤트와 도감 상태만 추가

### 3.5 계절 입고

- 주간 카드에 `shop` 유형 추가: 계절 한정 장비/시설 구매 제안 (5종)
- 숨은 콤보 **조합법 판매** 1~2건 포함 가능 ⚖ (A7 — MMS 는 조합법을 판다)
- 기존 카드 파이프라인 그대로 — 새 시스템 없음

### 3.6 해금 셀레브레이션 — 큰 사건은 모달로 축하한다

카이로는 해금·개장을 **모달 + 이펙트**로 띄운다 (사용자 확인). 사건 연출을 두 급으로 나눈다:

- **모달 급** (`.kover.dialog`, `PanelHost` modal — 카드와 같은 전례):
  시설/장비 해금 · 등급 승급 · 새 인물 등장 · 숨은 콤보 발견.
  스프라이트 크게 + 이름 + 반짝 이펙트, 탭으로 닫음. 연속 해금은 **큐로 하나씩**
- **토스트 급**: 소원 진척 · 의뢰 진척 · 하루 결산 · 주말 진입 — 흐름을 끊지 않는다
- 이펙트는 `transform`/`opacity` 만 (불변식) · `prefers-reduced-motion` 가드 ·
  오디오가 생기면(다음 할 일 1번) 팡파레가 여기 붙는다
- A6 과 결합: 인물이 걸어 들어오는 **도착 연출 → 모달** 순서. 모달이 열리면 시간은
  멈춘다 (§2.1 멈춤 규칙 그대로)

## 4. 설치 — 다듬기 회로

### 4.1 이동 도구

- 건설 시트 시설 탭에 `이동` 붓 (철거 옆). 시설 탭 → 이동 → 시설 탭 → 고스트 →
  확정. 기존 고스트·판정(`placement.check`) 재사용
- 비용: 건설비의 **10%** ⚖ (공짜면 배치 결정이 무의미, 비싸면 벌금과 같다)
- **첫 심사 통과로 해금** (§3.2) — 그 전에는 붓이 아예 안 보인다
- 코스·바닥은 대상 아님 (코스는 핸들 편집이 이미 있고, 바닥은 덧칠이 이동이다)

### 4.2 발견·반응 연출

- 콤보 발동(숨은 것 아니어도): 해당 시설들 1회 반짝 + 얇은 토스트 — 배치가 결과를
  만드는 순간을 보여 준다
- 흐르는 낮 자체가 배치 피드백이다 — 새 시설에 손님이 처음 도착하면 이모트

## 5. 초반 — UX 검수 3건의 처방

1. **목표란 교체**: 1줄 = 다음 의뢰(진척 포함, `첫 손님 6/10`), 2줄 = **심사 자격
   진척** (`심사까지 만족도 62/65`, 자격 충족 시 `심사 응시 가능`) — 구경(만족도 상승)이
   게이지로 쌓이는 게 보인다. 좋아요 1000=구역 해금의 우리식 번역 (A4).
   시나리오 이름은 메뉴로 이동. 탭하면 의뢰 목록
2. **시작 킷 재조정**: 결과 기준으로 강제한다 — 새 판 무행동 1주차에
   **퇴장 만족도 ≥ 25 · 헛걸음 < 입장의 30%** ⚖ (지금 0 / 만석 3배).
   놀이 시설 1~2개 + 동선을 시작 킷에 추가하는 방향으로 맞춘다.
   그리고 **첫 보상 5분 (A3)**: 무튜토리얼 기준, 새 판에서 첫 의뢰 완수 → 시설 선물
   도착까지 첫 세션 ~5분. 온보딩 검사에 항목으로 넣는다
3. **건설 시트 = 해금된 것만**: 잠긴 항목은 숨긴다. 대신 `다음에 올 것` 티저 최대 2줄
   (다음 심사 해금 1 + 진행 중인 의뢰 보상 1). 시작 시 항목 수 ~20 (지금 73)

## 5.5 UI 스킨 — 컨셉 시안 (`art-reference/ui-concept/`)

사용자 지정: concept-29 의 **선택(건설) 부분** 느낌. 스타일 언어 = 크림/양피지 패널 ·
진갈색 아웃라인 · 둥근 모서리 · 아이콘 우선 · 선택 = 노랑.

**채택 (구조):**
- **건설 시트 = 카드 캐러셀** — 카드마다 스프라이트 썸네일 + 이름 + 크기(`3×1`) + 가격.
  가로 스크롤 + 서브탭. 지금의 텍스트 목록(`.kitem.wide`)을 대체한다 (concept-29 지정)
- **좌측 의뢰 칩** (concept-28) — 아이콘 + 미니 진행바 2~3개 상시. §5-1 목표란의 시각
  구현체다 (A4 심사 게이지 포함). 화면 예산 가로 ≤22% 검사 안에서 ⚖
- **상단 캡슐 아이콘화** — 날짜·요일·날씨·시각(흐르는 낮과 정합) + 현금 + 지표.
  concept-29 의 `1년 7월 2주 ☀ 12:30` 이 §2.1 요일 표기(A1)의 답안이다
- **시설 이름표 · `대기 N명` 태그 · 손님 말풍선** — 지도 위 라벨. 말풍선(이모트)은
  이미 있다 (K29), 이름표·대기 태그가 신규

**채택하지 않는 것:**
- 6탭 하단바 — 직원·연구·경영이 우리에게 없다. **상시 컨트롤 3개** 불변식 유지,
  스타일(아이콘 사각 버튼)만 가져온다
- 보석(제2 화폐) — 프리미엄 유료 모델에 IAP 화폐는 없다

**규칙 (기존 불변식과의 관계):**
- 색은 여전히 `style.css` 토큰이 소유한다 — 스킨 전환 = 토큰 교체다 (그 설계의 존재 이유)
- 밝은 팔레트 불변식(K35)과 충돌 없음 (크림도 밝다). 단 **재질 레시피(`--sk-*`)와
  대비 14쌍은 재측정 필수** — 크림 위 진갈색 글씨의 실측으로 다시 잡는다
- 픽셀 아이콘·썸네일은 에셋이다 — Phase G 전까지 절차적 대체, 계약 ID 로 참조

## 8. 검증

- **K39 항등**: `run()` ≡ 임의 분할 step (12시드 × 26주 결산 완전 일치) — 이 검사 없이
  흐름 모드를 켜지 않는다. 멈춤·⏩·중간 건설은 브라우저 검사 (진짜 터치 규칙 유지).
  **밀도 계측**: 시작 판 흐름 1분에 가시 사건 ≥ 6 ⚖ (§2.1) — 미달이면 하루 길이를
  48±12초 안에서 조정하고 조정값을 기록한다
- **K40 온보딩 검사**: 새 판 무행동 8주 헤드리스 — 만족도·헛걸음 문턱 (§5-2).
  시트 항목 수 ≤ 24. 목표란이 의뢰·심사 진척을 비추는지 브라우저 검사.
  **첫 보상 5분** (A3): 봇이 첫 의뢰를 완수하는 최단 경로를 실측해 5분 안인지 잰다
- **K41 밸런스 재기준**: 의뢰 현금 총합 ~2,500만이 사라진다 — **26주 현금 곡선이 크게
  움직이는 것이 정상**이다. `sim:kairo` 12시드 합계로 새 기준을 잡고 골든을 다시 굽는다.
  움직인 폭을 커밋 메시지에 적는다 (K36-B 입장료 때의 규칙 그대로)
- **K42·K43**: 심사 결정론(같은 시드 같은 판정) · 소원 진행이 봇 26주에서 실제로
  도착하는지 (0건이면 문턱이 죽은 것) · 숨은 콤보 발견이 도감에 남는지
- 항상: `npm run verify` · `verify:kairo` · `sim:kairo` · 새 검사는 **위반 주입으로
  잡히는지 먼저** (`setRenderFaultForTest` 패턴)

## 9. 하지 않을 것

- **오프라인 진행** — 카이로도 안 한다. 프리미엄 모델과 충돌
- **개별 손님 영속 추적** — 소원은 유형 집계에서 파생. 1,200 에이전트에 개인사를
  붙이면 세이브·성능·밸런스가 다 커진다
- **인증의 별도 화면** — 심사는 카드·토스트·목표란 채널로 충분. 새 패널 금지 (표면 셋 규칙)
- **에셋 일괄 생산** — 인물 이름표·심사관은 기존 스프라이트로. Phase G 는 여전히 마지막
- **등급 5 초과의 새 티어** — 소원·숨은 콤보가 후반을 채우는 걸 먼저 실측하고 판단
