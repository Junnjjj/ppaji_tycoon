# Phase 0~7 최종 통합 계약

2026-08-25 기준 Phase 7은 새 경영 수치를 더하는 단계가 아니라, 이미 있는 기능을 한 장의
경영 정보 구조와 실행 가능한 첫 플레이 흐름으로 묶는 단계다. 운영 세이브와 장기 경력은
서로 다른 저장소를 쓰며, 결말은 플레이를 막는 종료 화면이 아니라 다음 선택을 여는 이정표다.

정본 우선순위는 **코드/데이터 → `CLAUDE.md` 불변식 → 이 문서 → 역사 계획/페이즈 로그**다.
`코드` 형태의 필드명·순서·수치는 각 모듈의 현재 공개 계약을 가리킨다.

## 현재 런타임·콘텐츠 스냅샷

- 시계: `TICKS_PER_DAY=120`, `TICKS_PER_WEEK=840`, 생산 1× `TICK_MS=200`.
  즉 24초/일·168초/주며 지도가 보이는 동안 자동으로 흐른다.
- 폐기: 10Hz/3,600 ticks/일/25,200 ticks/주, 0.6초 `한 주 진행`,
  겨울 `4주 진행`과 모든 생산 스킵 UI. `skipForward()`는 하네스에서만 하루를 전진한다.
- JSON 실측: 시설 75, 장비 19, 콤보 73(소 40/중 22/대 11),
  카드 27(일반 26/즉시 1), 재료 8, 레시피 8(매점 4/카페 4), 견인선 2,
  코스 프리셋 6, 인증 12, 직원 직군 5, 의뢰 16, 인물 8, 맵 3, 시나리오 6.
- `시설 75 + 장비 19 = 94`나 `콤보+시설+장비 = 167`은 UI 목록을 설명하는
  합성값일 뿐이며, 서로 다른 콘텐츠 축을 하나의 종수로 혼용하지 않는다.

## 코스·메뉴·카드·결산·UI 계약

### 코스

- 잠재 공급과 실제 탑승을 나눈다. 실제 탑승은 입장객 중 `thrill >= 0.35`인 수요와
  잠재 처리량의 최솟값이고, 수요 0이면 코스 매출도 0이다.
- `CourseStore.confirmEdit(edit, spend)`가 stale/invalid/결제/교체를 한 동기 경계에서 처리한다.
  stale/invalid는 결제 0회, 잔액 거절은 결제 시도 1회와 코스 snapshot 불변이다.
- 4초 시험의 `NEW`는 경력 기록 후보일 뿐이다. 취소하거나 변경비 결제가 거절되면
  `courseRecords`는 그대로고, 코스 생성/편집 적용이 성공한 뒤에만 후보를 한 번 기록한다.
- 편집 표면은 루트/장비/보트 세 섹션, 현재→예상 스릴·안전·처리량·실제 탑승·
  이익, 시작/방향/핸들/위험 오버레이, 4,000ms 시험 운행을 쓴다.

### 메뉴·단골

- 재료 조합은 순서가 없고, 실패도 후보 제거 힌트와 개발 진행을 남기며 같은 실패를
  재결제하지 않는다. 슬롯 상한과 시설 호환은 sim이 판정한다.
- 일반 손님은 장착 메뉴의 선호/기피 태그로 실제 구매하고, 단골은 현재 요청 메뉴를 우선한다.
  실제 입장·이용·구매 사건이 없으면 친밀도·보상·다음 요청이 진행하지 않는다.
- `menuFacilityOperability()`는 craft 시설의 장착 ID를 시설 호환·현재 발견 상태로 함께
  정리한다. 유효 메뉴가 0개면 GuestStore 목적지뿐 아니라 WeekRunner의 공급·built 병목·
  입장 정원에서도 0이다. 스냅샷의 삭제 레시피는 복원 때 버리고 같은 판정에서 운영 불가다.

### 카드

- `delivery: ordinary | immediate`를 필수로 검증한다. `eligibleCards`는 일반만,
  `triggerCard`는 즉시 사고만 낸다. 일반 카드는 한 주 최대 하나다.
- 모달=선택/축하, 티커=비차단 뉴스, 토스트=방금 행동의 답이다. 한 사건을 복제 발화하지 않는다.
- 8개 테마 슬롯을 공유하고 선택 2~3개를 한 행에 두며 각 터치 대상은 44px 이상이다.

### 결산·UI

- 결산 순서는 **방문객/영업 손익/퇴장 만족 KPI → 행동 처방 하나 → 132px 히트맵 →
  요일 → 구성 → 수익/운영비/투자 → 콤보/메뉴/코스 기록**이다.
- `WeekReport` 밖에서 영업 손익을 재계산하지 않는다. `profit`을 그대로 표시하고,
  투자는 `WeekRunner.spend(..., kind)`가 건설/코스·개선·메뉴 개발로 분리한다.
- 헤더 버튼 0, 하단 상시 버튼 2(메뉴/건설), A/B/C 목표 정확히 3, 모든 행동 44px,
  터치 건설 레일 약 3장, 하드코딩 TS 색 0이 모바일 불변식이다.

## 경영 시트 IA

경영 시트의 표시 순서는 고정이다.

1. `오늘 할 일` 하나
2. 보조 경고 0~N개
3. 운영 / 성장 / 기록 그룹

| 그룹 | 동작(순서 고정) | 실제로 여는 표면 |
|---|---|---|
| 운영 | 가격 / 직원 / 코스 | 직원 가격 탭 / 직원 탭 / 코스 편집 |
| 성장 | 심사 / 단골 / 의뢰 / 도감 | 심사 / 단골 목록 / 의뢰 목록 / 도감 |
| 기록 | 결산 / 보기 / 인증 / 엔딩 | 지난 결산 / 리조트 보기 / 인증 목록 / 경력 이정표 |

`todayRecommendation()`은 반드시 하나만 반환한다. 미완료 온보딩을 먼저 안내하고, 완료
뒤에는 엔딩 준비 → 안 읽은 결산 → 직원 부족 → 심사 → 단골 → 의뢰 순으로 현재 상태에서
실행 가능한 행동을 고른다. 위험·인력·안 읽은 결산은 `managementWarnings()`의 보조 줄이며
오늘 할 일을 여러 개로 복제하지 않는다. 모든 동작 표면의 최소 터치 높이는 44px다.

## 비차단 실행형 온보딩

온보딩은 설명 팝업이 아니라 실제 생산 이벤트 다섯 개를 순서대로 관찰한다.

| 단계 | 완료 이벤트 | 오늘 할 일의 목적지 |
|---|---|---|
| 코스 열기 | `course-opened` | 코스 시트 |
| 루트 끌기 | `route-dragged` | 코스 핸들 편집 |
| 시험 운행 | `trial-started` | 시험 운행 버튼 |
| 코스 적용 | `course-applied` | 적용 버튼 |
| 음식 시설 짓기 | `food-built` | 건설 시트 |

`OnboardingStore.blocks()`는 어떤 동작에도 항상 `false`다. 플레이어가 순서를 벗어나 가격,
건설, 자동 시간 흐름을 사용해도 막지 않으며, 선행 단계보다 나중 이벤트를 먼저 했다고 중간 단계를
건너뛰지도 않는다. 상태는 운영 세이브 v8의 `onboarding`에 들어가 새로고침 뒤 다음 단계가
이어진다.

## 저장 경계와 migration

운영 세이브는 v8이다. v7 → v8 migration은 기존 필드의 뜻을 그대로 보존하고
`onboarding: { version: 1, step: 'open-course' }`만 추가한다. 이후 저장/복원은 현재 단계를
왕복한다.

v8의 선택 필드 `weekRngStreams`는 날씨·일반 손님·단골·사고 RNG 상태를 각각
왕복한다. 이 필드는 post-review 교정으로 추가됐으며 스키마 버전을 변경하지
않는다. v7 migration은 여전히 onboarding 한 필드만 추가하고, RNG 스트림 상태가
없으면 기존 `weekRngState`에서 네 스트림을 결정적으로 fork한다.

장기 경력은 운영 세이브와 별도 키 `ppaji.kairo.career.v1`에 저장한다. 키의 `.v1`은
기존 localStorage namespace를 보존하는 접미사이고, **현재 경력 스키마 버전은 2**다.
스키마는 다음 다섯 필드만 허용한다.

```ts
{
  version: 2,
  clearedMaps: string[],
  clearedScenarios: string[],
  endings: string[],
  courseRecords: Array<{
    mapId: string,
    scenarioId: string,
    presetId: string,
    equipmentId: string,
    thrill: number,
    week: number
  }>
}
```

현금, 시설, 직원, 현재 주차는 경력에 복사하지 않는다. 같은 맵·시나리오·프리셋·장비 기록은
가장 높은 스릴만 남긴다. 경력 v1 별칭(`maps`, `scenarios`, `endingIds`, `records`)은 v2로
결정적으로 옮기며 운영 필드는 버린다.

## 엔딩 이정표

첫 엔딩 조건은 `등급 >= 5`, `인증 >= 6`, `시나리오 상태 != lost`의 교집합이다. 시나리오가
진행 중이거나 승리했으면 실패하지 않은 것으로 인정한다. 조건을 채워도 시뮬레이션을 강제
종료하지 않고 다음 선택 세 가지를 제공한다.

- 계속 운영
- 새 지역
- 리조트 보기

같은 엔딩 ID는 경력에 한 번만 기록한다. 엔딩을 본 현재 맵은 완료 맵에 남고, 시나리오는
실제 `won`일 때만 완료 시나리오에 남는다. 코스 신기록은 별도 경력 기록으로 축적된다.
첫 달성은 티커 뉴스가 아니라 기존 `KairoUnlockView`의 blocking 축하 모달로 배달한다.
계속 운영/새 지역/리조트 감상 세 선택은 같은 모달 안에 있고, 같은 엔딩을 다시 검사해도
도착 큐나 티커에 복제하지 않는다. 기록 시트는 이후 다시 보는 비차단 경영 표면으로 남는다.

### 24 seed × 52주 분포

동일 규칙의 헤드리스 분포를 먼저 측정한 뒤 임계값을 정했다.

| 지표 | 결과 |
|---|---|
| 최종 등급 | 최소 3 / 중앙 3 / 최대 4 (3등급 14, 4등급 10) |
| 인증 수 | 최소 4 / 중앙 6 / 최대 9 |
| 인증 6개 이상 | 19/24 |
| 5등급 + 인증 6개 + 비실패 | 0/24 |

인증 6개는 1년 분포의 중앙값이라 성장 준비도를 구분하면서 과도하게 희귀하지 않다. 반면
5등급은 52주 안에 나오지 않아 첫 엔딩을 1년 자동 도달로 만들지 않고, 장기 목표라는 기존
등급 곡선을 보존한다. Phase 7은 이 관측 때문에 경제·승급·인증 산식을 역으로 바꾸지 않는다.

## 주변 장식과 성능 계약

주변 장식은 기존 `ground/surround` 합성 단계에서만 만든다. `deco/banner`,
`deco/planter_row`, `deco/sculpture` 슬롯 여섯 개를 결정적인 좌표로 배치하며 모든 좌표는
플레이 그리드 밖이다. 그림으로 칠한 배경막, 충돌체, 새 Phaser 게임 오브젝트는 만들지 않는다.

합성은 부팅 때 `bakeSurroundTexture()`가 지면 텍스처에 한 번 수행한다. 프레임별 갱신,
카메라 이동 시 재생성, 타이머 기반 새로고침이 없으므로 런타임 오브젝트 수와 갱신 부담은
증가하지 않는다. 에셋이 없거나 젖은 지면에서는 해당 장식을 건너뛴다.

## 검증 기록

초기 Phase 7 TDD에서는 경영 IA·온보딩·경력·주변 장식 모듈 부재를 RED로 확인하고,
