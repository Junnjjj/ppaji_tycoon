## 2. 고친 것 (G55)

- 독 탭 `white-space: nowrap` + 12px + `flex: 1 1 auto` (한 줄) · `.kchips[hidden]{display:none}` (타일 칩 새어 나옴).
- 미리보기 색 줄: 색이 안 붙으면 **「맑음 1/5 · 핑크까지 2개」** (`Game.itemsToColor` — 같은 아이템을 n개 넣는 가상 풀로 최대 6개까지 계산). 4칸 풀은 1개, 20칸 시작 풀은 2개 — 원작 「작은 풀이 아니면 농도 5 가 안 된다」의 우리 쪽 숫자.
- 이동 고스트 가격표 → **「이동 · 무료」** (`setGhost` 라벨 인자). 같은 자리는 `canMoveFacility` 단계에서 거절 → 독 첫 줄이 「같은 자리입니다 — 지도를 탭해 옮길 곳을 고르세요」.
- 칩 아이콘 16px · 도감 값은 오른쪽(`.krow-k + .krow-v { margin-left: auto }`).

## 3. 배운 것

- **하네스 초록 ≠ 눈 초록.** G52 절은 「미리보기 4줄 · 넣기」 를 값으로 재서 통과했지만, 20칸 풀에서 「맑음 → 맑음」 이 뜨는 것은 4칸 풀로 재는 절이 볼 수 없었다. 재플레이는 **시작 킷 그대로**(`kit` 기본) 여야 한다 — 하네스는 `kit=0` 으로 작은 풀을 파서 잰다.
- `hidden` 은 `display` 를 가진 클래스에 진다. 새 컨테이너에 `display:flex` 를 주면 `[hidden]` 규칙도 같이 준다 (S8 규칙은 `hidden =` 사용처만 세고 CSS 우선순위는 안 잰다).

## 6. 후반 성능 확인 (8년차 세이브, `tmp-shots/perf127.mts`)

3차 스크린샷의 디버그 띠가 8년차 홈에서 **FPS 46~48** 을 보여 재봤다. 같은 세이브를 dev 번들(5177)에서 열고 400tick 감은 뒤 프레임 300개 + CDP 프로파일 4초:

| 지표 | 값 |
|---|---|
| 손님 | 103 |
| 프레임 p50 / p95 | 16.7 / 16.7 ms (60fps) |
| CPU 프로파일 | idle 84.7% · Phaser batchSprite 2.2% · batchQuad 1.2% · `facility.ts ring` 0.5% · `water.ts update` 0.2% · `syncGuests` 0.2% |

→ 후반에도 프레임 예산 안이다. 스크린샷의 46fps 는 **캡처(3배 스케일 PNG 인코딩) 중 수치**였지 게임의 것이 아니다. 성능 goal 은 열지 않는다. 남는 관찰 하나: `ring`(시설 인접 계산)이 sim 쪽 최상위인데 풀 상태 재계산이 캐시를 타는지 후반 풀 8개 기준으로 확인할 가치는 있다 (지금 0.5% 라 급하지 않다).

확인(같은 날): `poolState` 는 `pools.version|facilities.version|계절|아이템 수|좋아요|날씨` 키로 캐시된다 — `ring` 0.5% 는 좋아요가 바뀔 때의 miss 와 손님의 `entryTiles`(목적지 결정) 몫이고 프레임마다 도는 것이 아니다. 손댈 것 없음.
