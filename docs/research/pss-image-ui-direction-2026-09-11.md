## 1. 배율 — 원작 기본 줌은 우리 S=1 의 두 배다 → 기본을 S=2 로 (2026-09-11 정정)

> ⚠ 첫 판정(「폰에서는 이미 같다」)은 **틀렸다.** 386px 축소 스크린샷 한 장(`water-park-story-hud.png`)으로 쟀는데, 그 장면은 핀치로
> 최대 축소한 상태였다. 사용자 지적(「우리 게 더 축소돼 있다」) 뒤 **플레이 영상 3편 + 실기 스크린샷**으로 다시 쟀다.

| 출처 | 화면 긴 변 타일 수 | 짧은 변 타일 수 | 손님 키 |
|---|---|---|---|
| 원작 실기 App Store 컷 (iPhone 1242×2688 = 414 CSS) | — | **≈ 7** | **≈ 45 CSS px** (128 device px) |
| 원작 PC/콘솔판 영상 1년차 (1920×1080, `1oQiLvmRr_E`) | ≈ 14.5 | — | ≈ 95 px |
| 원작 안드로이드 가로 영상 (1280×720, `M-FBoyR4UvI`) | ≈ 13.3 | — | ≈ 69 px |
| 원작 축소 스크린샷 (첫 판정의 근거 — 핀치 최소) | — | ≈ 13.5 | ≈ 22 px |
| 우리 S=1 (393×852) | — | 12.3 | 24 CSS px |
| **우리 S=2** (393×852) | — | **6.1** | **48 CSS px** |
| 우리 데스크톱 1904 S=1 / S=2 | 59.5 / 30 | — | 24 / 48 |

- 원작의 **기본 줌은 짧은 변에 ≈ 7 타일, 긴 변에 ≈ 14 타일**이다(세 출처가 일치). 우리 S=1(12.3)은 그 **절반 크기**였고, S=2(6.1)가 같은 눈금이다.
- **적용**: `UPSCALE_DEFAULT 1 → 2` (`src/render/upscale.ts`). 사다리 `[1, 2]` 는 그대로라 핀치로 S=1(전체 조망)로 내릴 수 있다.
  카메라 검사 5건은 S=1 눈금을 전제라 `setUpscale(1)` 을 붙였고, 「기본은 2」 검사를 하나 더했다. 하네스는 절마다 `setUpscale(1)` 을 직접 부른다.
- **첫 화면도 옮겼다**: 새 판 시작 칸 `(정문 −2, +9)` 은 S=2 에서 복도 안만 보였다(잔디 10%) → `(정문 +4, +12)` 로 광장 + 선착장 + 킷 빠지 수역이 한 화면에. 하네스 「마당 ≥ 20%」 행은 「물 ≥ 15% · 잔디 ≥ 2%」 로(강이 마당 아래이던 P43 기준이었다).
- 데스크톱(1904)은 S=2 로도 30 타일이라 원작 PC 판(≈ 14.5)의 두 배다 — 사다리에 3·4 를 더해야 맞는다. 폰이 1순위라 **미결**로 둔다.

## 2. 「전부 그림」 — 원작 vs 우리 (창 9장 실측)

원작은 **정의(definition)마다 그림이 하나씩** 있고 UI 는 그 그림을 격자로 깔 뿐이다. 우리는 **시설 148 종만** 그림(`kthumb` 스프라이트)이고
나머지 정의는 전부 **글자 칩·글자 행**이다.

| 화면 | 원작 | 우리 (2026-09-11 실측) | 차이 |
|---|---|---|---|
| 건설 | 시설 그림 카드 + 이름 + 가격 | 시설 그림 카드 + 이름 + 인기·유지 + 가격 | **같다** — 유일하게 그림인 창 |
| 요리 개발 | 재료 = 그림 아이콘 + **보유 수**(U1 재고), 슬롯에 그림이 든다, 결과는 요리 일러스트 카드 | 「빈 칸 1~5」 글자 칩 + 재료 글자 칩(계열 아이콘 9 종만) · 도감은 「얼음물 (음료) 맛 2 외관 1 인기 2 [설정]」 글자 행 | 재료 70·요리 180 이 **그림 0** |
| 기구 공방 / 개조 | (원작엔 없음 — 아이템 조합 창이 같은 문법) | 부품 글자 칩 · 도감 「???」 글자 행 · 개조 결과 「플로팅 슬라이드 → 스릴 2 정원 5」 글자 | 부품 13·기구 33 이 그림 0. 개조판 20 은 **시설 스프라이트가 이미 있다** — 안 쓰고 있다 |
| 장날 | 상품 그림 카드 격자, 잠금은 자물쇠, 입고 전에도 보인다 | 「진열이 비었다 — 17시」 빈 상태 글자 (B5) | 상점 43 항목의 대상은 시설·아이템·재료라 **그림 재사용 가능** |
| 빠지 심사 | 심사위원 셋이 **말풍선으로 각자 조건**, 참가상·합격 상품 그림 (U2) | 초상 + 조건 글자 줄 + 「충족/50%」 | P53-a 로 조건이 기구 조건이 됐으니 **기구 그림**이 조건 옆에 설 수 있다 |
| 지도 위 | 손님 머리 위 「🍦 ×2」 구매 팝 · 시설 위 「600G」 가격표 · HP 배터리 · ★ 만족 게이지 | 말풍선 글자(「자리가 …」) · 사고 토스트 글자 | 구매·팔찌 발급이 지도에서 **안 보인다** |
| SNS·소원 | 보상 아이콘(새 손님은 실루엣, R10) | 보상 글자 | 선물 18·부품 보상 그림 0 |
| 수역 소품 | 색상환·향·온도 **세 카드** + 강도 5칸 게이지 (U3) | 지표 글자 줄 | 아이템 24 그림 0 |

| 정의 | 수 | 그림 | 임시 폴백 |
|---|---|---|---|

| 재료 | 70 | 없음 | 계열 아이콘 9 (`icons.ts` G54) |
| 요리 | 180 | 없음 | 분류 아이콘(음료·간식·식사) |

| 선물 | 18 | 없음 | 선물 아이콘 1 |

`iconEl` 이 이미 「요소 자리」라 호출부는 안 바뀐다 — 등록부만 `data:` 도형에서 아틀라스 좌표로 간다(Phase G 와 같은 규칙: 없으면 폴백).

## 3. 개선 방향 (제안 · 순서)

| # | 무엇 | 크기 | 근거 |
|---|---|---|---|
| **A** | **아이콘 등록부 → 그림 등록부**: `data/icons.json`(id → 시트 좌표) + 시트 1장 + 없으면 계열 아이콘 폴백. `iconEl(name)` 이 정의 id 도 받는다 | 중 (코드) + **338장 생성** | 나머지 전부의 바탕. Phase G 「아틀라스는 픽셀만 준다」 그대로 |
| **B** | **조합 창 3개(요리·공방·개조) 한 문법으로**: 위 슬롯(그림이 들어간다) · 아래 **아이콘 카드 격자**(보유 수 배지·잠금 회색) · 결과 **그림 카드**(맛·외관·인기 / 스릴·정원·안전 아이콘 게이지 5칸) · 도감은 **그림 타일 격자**(미발견 실루엣) | 중 | 원작 아이템 조합 문법. B1·B2 |
| **C** | **장날 = 그림 카드 격자**, 입고 전엔 잠금 카드로 보인다(B5) · 가격표 배지 | 소 | U1·B5 |
| **D** | **지도 오버레이**: 구매 팝(아이콘 ×N, 손님 머리 위, FX 등록부) · 시설 가격표 배지(조준 중) · 팔찌 발급 아이콘 | 소~중 | 원작 App Store 컷 두 장의 핵심. 채널 규칙상 토스트가 아니라 **지도 위 FX** |
| **E** | 심사 창: 조건 옆 **기구/시설 그림** + 심사위원 대사 + 참가상·합격 상품 그림 | 소 | U2 · P53-a 조건이 전부 정의 id 를 갖는다 |
| **F** | ~~넓은 뷰포트 기본 S=2~~ → **폰 기본 S=2 적용(2026-09-11)** · 데스크톱은 사다리 3·4 추가가 남았다 | 아주 소 | §1 |

순서 제안: **F(즉시) → A(그림 생성은 별 세션) → B 요리부터 → C → D → E**. A 없이 B 를 하면 카드에 계열 아이콘만 남아 「글자 칩이 커진 것」이 된다 —
그래서 A 가 먼저다. 다만 **개조판 20·시설 카드는 그림이 이미 있으므로** B 의 개조 창 결과 카드와 E 는 A 없이도 바로 된다.
