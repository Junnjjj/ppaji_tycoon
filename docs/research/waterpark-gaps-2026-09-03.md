## A. 원작(PSS)에 있는데 우리에게 없거나 이름만 있는 것
1. **요리 레벨이 가격에만 붙는다** — 매뉴얼 「높은 레벨에서 더 좋은 스탯」. `cooking.mult` 는 가격(`game.ts:781`)뿐, 맛(HP)·인기·외관에는 안 닿는다 → 요리 축의 성장이 체감 0.
2. **강도(Intensity)를 요구하는 인증이 0건** — 매뉴얼 「일부 인증은 강도 필요」. `certs.json` 에 `intensityMin` 없음(소원 2건뿐). 나눗수도 계획(`4√size`)과 코드(`2√size`, `color.ts:41`)가 다르다.
3. **시설 계절 벡터가 죽은 데이터** — `season[4]` 94종 전부 있지만 읽는 곳 0. 매뉴얼 「야외 풀은 여름↑ 겨울↓」이 시설엔 안 적용된다. `indoorOnly` 도 읽는 곳 0(이글루·사우나가 야외 가능).
4. **AB 가 활강로 전체 인접으로 샌다** — 계획 「출구 칸이 풀이면」인데 `pool-state.ts:62` 는 발자국 링 전체. SE 는 제트풀·핫텁 2종뿐.
5. **인증 재수상 재료 1개**(계획·원작 3개, `game.ts:389`) · **근소 실패 위로(재료 1)** 미구현 · 인증 조건이 좋아요·인기·실내외·타일 종류를 한 번도 안 쓴다(배치 형태 압박이 인접 조건 1건뿐).
6. **NG+ 이월** — 티켓 보너스가 회차마다 누적 안 됨(`endgame.ts:52` 가 prev 무시), 시설 「종류당 1」이 아니라 전부 이월.
7. **랭크 보상이 ★1~4 전부 현금** — 원작은 랭크업 = 상점 신상·호화 상품. 랭크 문턱은 §2.6 플레이스홀더 그대로(스윕 0회).
8. **비상 자금(Emergency Fund 2,000G)** — 원작에 있는 파산 방지 장치가 없다(봇은 예비비로 피하고 있을 뿐).
9. **편의 시설 3종**(원작 8) · `cert` 출처 해금 시설 0.
10. **아이템 전표는 여전히 플레이스홀더**(`schema.ts:86`) — 24종 지속시간·온도가 추정값.

## B. 계획(§2.2/§2.3)에 적혔는데 배선 안 된 것
- 조건 DSL: `facilityOnPool` 없음 · `pool{tile}` 없음 · `item{active}` 없음(반대로 `facilityClass` 는 코드에만 있음).
- 유입식에 **좋아요 항**이 없다(`game.ts:696`) · 실내 비율 완화 없음 → 좋아요를 모아도 손님이 안 는다 = SNS 축의 보상 누락.
- `features.json` 5축 OFF(직원·시설 레벨·랜덤 이벤트·라이벌·일일 결산). 랜덤 이벤트는 선택 모달 렌더러조차 없어 켜도 죽은 코드.

## C. 손님·경제 깊이

## D. 원작 단점(리뷰·§1.10) 대응 상태
- 심사 실패 이유 불명 → **예상 점수·부족 조건 노출 ✅**. 재도전 「두 계절 대기」 → 우리도 봄·가을만(그대로).
- 소원이 풀을 부수게 함 → 프리셋 ✅ + R2 경고 ✅. 단 「입구 앞 1칸 풀」 악용은 sizeMin 으로만 막음.
- 팝업 과다 → 모달을 토스트로 흘려보내는 방식이라 **오히려 「모달 표면」이 없다**(심사 결과 창·도장 없음, `main.ts:347`).
