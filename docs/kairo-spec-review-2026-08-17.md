3팀(규격·수학 / 재미·체감 / 생산가능성)이 각자 렌즈로 스펙을 깨려 시도하고, 팀별 독립
회의론자가 각 발견을 반박했다. 마지막에 완전성 비평 1팀이 세 팀이 놓친 것을 찾았다.

## 0. 스케일 — 내가 두 번 틀렸다가 확정한 것

팀A 는 "카이로 손님이 타일 높이의 3.3배라 스펙 스케일이 2배 틀렸다"고 blocking 판정했다.
나는 처음에 그걸 "단위 혼용, 실제로는 1.78배"라고 정정했는데 **그 정정도 틀렸다** —
업스케일 배율을 2배로 가정했기 때문이다.

확정 절차와 값:

1. 아트 업스케일 배율을 도트 행 경계 간격으로 실측 → **2.5배** (세 영역 독립 측정
   2.52 · 2.54 · 2.56). 즉 `park.jpg` 1280×720 은 네이티브 **512×288** 의 2.5배본이다.
2. 타일이 정수 텍셀이려면 이미지 타일폭이 2.5의 배수여야 한다 →
   64px(25.6텍셀) ✗ · 72px(28.8) ✗ · **80px(32.0) ✓** · 96px(38.4) ✗
3. 따라서 타일 = 이미지 80×40 = **32×16 텍셀** — 스펙과 일치.
4. 손님 = 눈금으로 읽은 57 이미지px ÷ 2.5 = **22.8 텍셀**, 타일 높이의 **1.43배**
   — 스펙의 24텍셀·1.5배와 오차 5%.

**결론: 스펙의 스케일은 맞았다.** 팀A 1번은 REFUTED, 내 첫 정정("28텍셀")도 철회한다.

그런데 그 발견의 **부수 지적은 살아남는다**: 레퍼런스 손님은 머리 11텍셀에 눈 1텍셀·
입 1텍셀로 **표정이 또렷하게 그려져 있다**. 스펙 §2.3 이 "24텍셀에서 표정은 못 읽힌다 →
표정 스프라이트 안 만든다"고 결론지은 것은 사실과 다르다. 사용자가 카이로를 택한 이유가
"npc들의 표정을 보고"였으므로 이 결론은 뒤집어야 한다.
