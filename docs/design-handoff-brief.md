# 디자인 인계 브리프 — 화면 하나 만들 사람에게 던지는 문서

> **쓰임:** Claude Design(또는 다른 시각 디자인 세션)에 **이 파일 하나**를 던지면
> 저장소를 안 읽고도 화면을 그릴 수 있게 하는 것이 목적이다.
> **정본은 코드다** (`src/ui/style.css` 의 `:root`). 이 문서는 그 사본이므로,
> 값이 갈라지면 CSS 가 이긴다. 갈라진 것을 발견하면 이 문서를 고친다.
>
> `docs/` 의 다른 UI 문서들은 **왜 그렇게 정했나의 기록**이지 디자인 명세가 아니다.
> 인계에는 이 문서를 쓰고, 근거를 알고 싶을 때만 §10 의 목록을 연다.

---

## 1. 무엇을 만드나

한국 강변 수상레저 **「빠지」**를 짓고 운영하는 **모바일 타이쿤**.
RollerCoaster Tycoon 의 설계 깊이를 Kairosoft 급 접근성으로.

- **주 뷰포트: 393 × 852 (iPhone 세로).** 가로 852 × 393 도 **같은 한 레이아웃**으로 낸다.
  미디어 쿼리로 두 벌 만들지 말 것 — 안 본 쪽이 반드시 깨진다.
- 화면의 주인공은 **지도**다 (아이소메트릭 2:1 다이메트릭 픽셀아트).
  HUD 는 지도를 **가리지 않는 만큼만** 존재한다.
- 웹 기술(DOM + CSS)로 만든 HUD 가 Phaser 캔버스 위에 얹힌다. HUD 에 이미지 에셋은 **0장**이다 —
  전부 CSS 로 그린다 (선명하고, 다크모드가 공짜고, 에셋 파이프라인을 안 탄다).

## 2. 팔레트 — 그대로 복붙해서 쓸 것

**밝은 크림 + 진갈색 글씨 + 가죽색 주버튼.** 컨셉 시안에서 픽셀로 잰 값이 뿌리다.

```css
/* 표면 */
--panel:        linear-gradient(#fdeecb, #f8e0b4);  /* 패널·버튼 바탕 */
--panel-sunk:   linear-gradient(#e8c88f, #f0d5a4);  /* 가라앉은 면(입력·영수증) */
--panel-primary:linear-gradient(#8a5216, #66380a);  /* 주버튼 — 가죽 브라운 */
--bar-bg:       linear-gradient(rgb(242 205 143/96%), rgb(229 181 106/97%)); /* 트레이 */
--sheet-bg:     rgb(240 202 138);                   /* 바텀시트 */
--overlay-bg:   #f9efda;                            /* 불투명 전면 */
--panel-border: #b98d4f;

/* 글씨 */
--text:        #3a2412;   /* 본문 */
--text-dim:    #6b5128;   /* 보조 */
--text-mute:   #6f5626;   /* 더 흐림 */
--text-locked: #96793f;   /* 잠김 */
--text-on-solid:#fff;     /* 진한 칠 위 */

/* 의미색 */
--accent: #8f5007;  /* 강조(호박) */
--good:   #3e7d2c;
--warn:   #a8590a;
--bad:    #b93a24;

/* 선택 — 「선택됨은 채움이다」 */
--select-fill: linear-gradient(#fcd964, #f3c22f);  /* 메인 탭·버튼: 노랑 채움 + 진갈 글씨 */
--select-sub:  linear-gradient(#3f74c9, #2c56a8);  /* 2차 필터 칩: 파랑 채움 + 흰 글씨 */

/* 값 중의 값 — 헤더에서 유일하게 어둡다 */
--cash-bg:   linear-gradient(#452a0e, #331e06);
--cash-text: #f6ca3a;
--sky-chip:  linear-gradient(#5b9ada, #3f7ecb);   /* 날씨 칩 */

/* 위험도 4단 (진한 칠 + 흰 글씨) */
--risk-safe:#1c7a4d; --risk-watch:#8a6a12; --risk-caution:#b25d15; --risk-danger:#b52a1f;

/* 스크림 */
--scrim:      rgb(250 240 219 / 95%);  /* 반투명 전면(결산) — 밝다 */
--scrim-deep: rgb(48 30 10 / 55%);     /* 모달만 어둡다 */
```

### 색에 대한 세 가지 규칙

1. **밝은 표면 + 진한 글씨.** 어두운 UI 로 되돌리지 말 것.
2. **재질 그림자는 따뜻한 갈색이다.** 남색 그림자는 크림 위에서 물때로 보인다.
3. **선택은 채움**이지 외곽선 강조가 아니다. 외곽선으로 하면 선택으로 안 읽힌다(실측).
   층마다 색이 다른 것(노랑/파랑)은 위계 표현이지 "고름이 둘"이 아니다.

## 4. 재질 — 카이로 버튼의 픽셀 단면 3요소

「색만 바꾼 플랫 UI」로 보이지 않게 하는 것이 이 셋이다.

1. **요소보다 어두운 트레이 위에 뜬다** (`--bar-bg` 가 `--panel` 보다 어둡다) — 이것이 분리다.
2. **진갈색 아웃라인이 그라디언트**다 (위 `#c08c48` → 아래 `#7d5322`).
3. **아웃라인 안쪽에 또렷한 흰 하이라이트 선** (`#fff3d6` 2px). 흐릿한 소프트 섀도가 아니라
   **만화적 하드 엣지**다.

```css
--sk-inset: inset 0 2px 0 rgb(255 243 214/92%), inset 0 -2px 0 rgb(154 104 47/26%);
--sk-lift:  0 2px 0 rgb(128 86 38/32%), 0 3px 6px rgb(96 62 20/14%);
--sk-press: inset 0 3px 5px rgb(96 62 20/30%);
```

## 5. 화면 지도

### 5.1 홈 (평소 — 지도가 81.5%)

```
┌───────────────────────────────┐ 393
│ ☁ 3주 토 PM2:40   [₩1,284만]  │  헤더: 한 패널 2줄, 내용 폭(전폭 아님)
│ 만족72 · 방문318 · ★2 · 안전  │  버튼 0개 — 읽는 것만 산다
├───────────────────────────────┤
│                               │
│           지  도               │  ← 화면의 주인공
│                               │
│                               │
├───────────────────────────────┤
│▓▓▓▓░░  📰 구인·안전요원 D-2   │  티커 26px (bottom 74)
│ 👤 민지 · 다음 할 일    [MENU]│  하단 바 64px — 네이티브 버튼은 MENU 하나
└───────────────────────────────┘ 852
```

### 5.2 MENU 를 누르면 — 오른쪽 밴드 **일곱 칸**

순서는 **영구 고정**이다 (근육 기억이 자리에 붙는다):

| # | 칸 | 안에 |
|---|---|---|
| 1 | **건설** | 시설·바닥·건물·철거·이동 |
| 2 | **코스** | 프리셋·터닝포인트·장비·시험 운행 |
| 3 | **요리** | 조합·강화·도감·장착 |
| 4 | **상점** | 지금 산다 / 맡긴다(수배) |
| 5 | **경영** | 요금·직원·심사 |
| 6 | **목표** | 의뢰·소원·인증·단골 (네 섹션) |
| 7 | **정보** | 결산·도감·감상·엔딩·설정 |

- 밴드는 `position: fixed; right: 8px; bottom: 104px`, 칸 높이 44px, 폭은 **내용이 정한다**
  (고정 폭이면 한글 두 자가 `건/설`로 세로 쪼개진다 — 실측).
- **잠긴 칸은 숨기지 않고 `?` 로 남는다.** 가림막이 아니라 **예고**이고, 그것이 이 게임의
  튜토리얼이다. `disabled` 로 만들지 말 것 — 눌러서 **여는 방법**을 들을 수 있어야 한다.
- 접힌 밴드는 `visibility: hidden` 이다 (`opacity: 0` 만이면 rect 가 살아 감사에 잡힌다).

### 5.3 표면은 **넷**뿐이다

| 표면 | 클래스 | 성격 |
|---|---|---|
| **시트** | `.ksheet` | 아래에서 올라오는 목적지 화면. 머리 58px + 몸. 열면 시간이 멈춘다 |
| **전면** | `.kover` | 불투명 전체 화면 (새 판·도감) |
| **떠 있는 것** | `.kover.scrim` / `.dialog` / `.frame` | 결산·모달·감상 |
| **액션 독** | `.kcourse` | 코스 전용. 지표 1행 + 버튼 1행, **머리가 없다** (지도가 주인공이라) |

속은 한 벌이다: `.kitem.wide` · `.krow` · `.kstat` · `.kchips` · 버튼은 `.kbtn` / `.on` / `.primary`.
**새 패널을 만들 때 버튼 클래스를 새로 만들지 말 것** — 이 셋으로 충분했다.

### 5.4 시트 머리는 **한 값**이다 — `--sheet-head: 58px`

44px 터치 타깃 + 위아래 7px 패딩에서 유도했다.
⚠ 실측으로 넷이었다(건설·상점 58 · 도감 46 · 목표/경영 31). 화면마다 제목 줄 높이가 달라
사용자가 **"정형화되어 있지 않다"**고 지적한 것이 이 지점이다. 제목의 정본은 시트 머리 **하나**다.

### 5.5 결산 — 순서가 계약이다

**3 KPI 요약 → 행동 가능한 처방 하나 → 축소 히트맵(132px) → 요일 막대 → 손님 구성 →
수익/운영비/투자 → 콤보·메뉴·코스 기록.**
「히트맵부터」 순서는 393×852 에서 **돈의 결론을 첫 화면 아래로 밀어서** 의도적으로 바꿨다.

### 5.6 사건은 채널 셋이고 **겹치지 않는다**

| 채널 | 무엇 | 시간 |
|---|---|---|
| **모달** | 축하 — 해금·승급·새 도구·인물 등장·숨은 콤보 | 멈춘다 |
| **티커** | 뉴스 — 내가 안 했는데 일어난 일 | 안 멈춘다 |
| **토스트** | 내 행동의 대답 — 거절 이유·확정 −N | 안 멈춘다 |

한 사건을 두 채널에 넣지 말 것. 근거: 경쟁작 부정 리뷰 1위가 **팝업 과다**였고
처방이 "모달 대신 알림함 적재"였다.

## 6. 레이아웃 상수 — 손으로 다시 적지 말 것

| 값 | 토큰 | 왜 그 값인가 |
|---|---|---|
| 44px | `--tap` | 모바일 최소 터치 타깃. **하한**이지 고정 폭이 아니다 |
| 58px | `--sheet-head` | 44 + 7·7 패딩 |
| 100px | `--bottom-stack` | 바(64) + 티커(74 오프셋 + 26). 위에 얹히는 표면이 이걸 `bottom` 으로 쓴다 |
| 26px | 티커 높이 | 띠 자체. hit surface 는 44px 이고 위아래로 9px 씩 삐져나온다 |
| 74px | 티커 bottom | **바와 겹치면 목표 칩의 터치를 훔친다** (실측 3px 겹침). `z-index` 로 덮지 말고 기하로 풀 것 |
| 104px | 밴드 bottom | 티커 위 |
| 132px | `--course-dock-cap` | 코스 독 천장 |
| 46ms | `--stagger` | 요일 7칸 × 46 = 322ms. 더 길면 「기다린다」, 더 짧으면 순서가 안 읽힌다 |
| 160/220/260ms | `--dur-micro` / `--dur-ui` / `--dur-rise` | 마이크로 / 상태 변화 / 등장 |

### 화면 예산

- HUD 가 먹는 면적: **세로 ≤ 25% · 가로 ≤ 36%**
- **지도 가시 면적 ≥ 60%**
- 더 늘리지 말 것. 뭔가를 더하고 싶으면 **밴드 안**이 제자리인지 먼저 볼 것 —
  밴드는 접혀 있어 예산을 안 먹는다.

## 7. 절대 바꾸면 안 되는 것

1. **읽는 것은 위, 누르는 것은 아래.** 헤더에 버튼은 **0개**다 (폰 상단은 엄지 사각지대).
2. **하단 네이티브 버튼은 1개**(`MENU`)다. 홈의 상시 역할 제어는 셋 — `MENU` · 상태 밴드 · 티커.
   ⚠ **개수로 계약을 재지 말 것.** 이름으로 잰다 (`=== 6` 류가 IA 가 바뀔 때마다 죽었다).
3. **색은 CSS 가 소유한다.** TS 하드코딩 hex **0개**. 캔버스도 `cssVar()` 로 읽는다.
   진행바 폭·캔버스 크기 같은 **데이터**만 인라인으로 남는다.
4. **이모지 리터럴 금지.** 아이콘은 등록부를 지난다.
5. **전환은 `transform` / `opacity` 만.** 레이아웃 속성을 애니메이트하면 프레임이 떨어진다.
6. **`prefers-reduced-motion` 가드 필수** — 그리고 **기존 가드 블록 안**에 넣을 것
   (정적 검사가 첫 블록만 읽어서, 별도 블록에 쓰면 가드가 있는데도 빨간불이 된다 — 실측).
7. **세로 flex 안의 글자 줄에는 `flex: 0 0 auto`.** 기본 `flex-shrink: 1` 이면 공간이
   모자랄 때 **높이 0 으로 접히고** 글씨가 그냥 사라진다 (실측 3회).
   ⚠ 반대로 **부모가 가로면 `min-width: 0`** 이다 — 축을 안 보고 옮기면 스크롤러가 화면 밖으로 벌어진다.
8. **버튼 줄은 절대 안 잘린다.** 넘치면 지표·영수증이 양보하고 제목·이유·버튼은 안 준다.
   천장 값을 키워 맞추는 것은 답이 아니다 — 줄 수가 상태마다 달라 **어떤 천장도 언젠가 넘는다.**
9. **화면 전용 표면에는 그 화면의 접두사**를 줄 것. `.kband` 이름 충돌로 감상 화면의 두 띠가
   화면 바닥에 겹쳐 앉은 적이 있고, **어느 자동 검사도 안 걸렸다**.
10. **패널은 한 번에 하나**다 (`PanelHost`). 등록을 안 하면 배타가 기본이다.
11. **모달 스크림만 어둡다.** 밝은 스크림 위 밝은 상자는 안 떠 보인다.
12. **방향은 한 레이아웃으로.** 미디어 쿼리로 두 벌 만들지 말 것.

## 8. 디자인이 통과해야 하는 자동 게이트

새 화면은 아래를 **전부** 통과해야 머지된다. 디자인 단계에서 미리 알고 그리는 편이 싸다.

| 검사 | 무엇 | 도구 |
|---|---|---|
| **대비 27쌍** | 본문 4.5:1 · 보조·면끼리 3:1 | `node tools/check-ui-surface.mjs` |
| 하드코딩 hex | TS 에 0개 | 같은 도구 |
| 이모지 리터럴 | 0개 | 같은 도구 |
| 타이포 스케일 | 여섯 단 밖의 크기 0개 | `type-scale.test.ts` |
| reduced-motion | 가드 존재 | `check-ui-surface.mjs` |
| 터치 타깃 | 상시 컨트롤 전부 ≥ 44px | `npm run verify:kairo` |
| 터치 소유권 | `elementFromPoint` 로 **진짜 탭** | 같은 게이트 |
| 화면 밖 누출 | 스크롤 컨테이너 바깥 블록이 뷰포트 안 | 같은 게이트 |
| 화면 예산 | 세로 ≤25% · 가로 ≤36% | 같은 게이트 |

⚠ **같은 색을 표면마다 다시 재라.** `--accent` 는 패널 위(4.12)만 재고 바 위는 아무도 안 쟀는데
크림 바에서 **2.87:1** 로 미달이었다. 레퍼런스 실측값이라도 대비가 미달이면 보정한다.

⚠ **좌표만 재는 검사는 「보이는데 안 눌린다」를 못 잡는다.** 칩 줄이 높이 2px 로 납작해져
버튼은 44px 로 보이는데 `elementFromPoint` 가 아래를 집은 적이 있다. **진짜 터치로 볼 것.**

## 9. 지금 남아 있는 디자인 숙제

디자인 세션이 실제로 풀어 줬으면 하는 것 — 이미 고친 것 말고 **열려 있는 것**만 적는다.

1. **「화면 비율이 눈에 안 들어온다」** (사용자 지적, 2026-08-28, 미착수).
   경쟁작은 잘 읽히는데 우리는 안 읽힌다. 진단이 아직 없다 — 지도/HUD 비율인지,
   타일 스케일인지, 밀도인지. **이 브리프의 가장 큰 열린 문제다.**
2. **화면 밀도를 아직 다시 안 쟀다.** 옛 값은 상위 5색 43% vs 경쟁작 15%.
3. **티커 띠가 아이콘을 둘 그린다** (고정 `📰` + 항목 아이콘이 겹쳐 보임 — 순수 외양).
4. **아이콘 호출부 65곳이 아직 문자열**(`icon()`)이라 그림이 될 수 없다. `iconEl` 로 옮기는 것이 남았다.
5. **사람 확인 항목이 전부 미측정**이다 (목록은 `docs/human-check.md`) — 393×852 실기 터치,
   30초 무설명 과업, 무라벨 A/B, 첫인상. **자동 통과를 사람 승인으로 보고하지 않는다.**
