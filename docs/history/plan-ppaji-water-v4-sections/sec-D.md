## 1. 결정 (D251~D259)

### 밤 — 없는 함수 · 크기의 자 · 축을 옮긴 손잡이

- **D251 `syncNightSet` 은 **없는 함수다.** [54] 가 그 한 줄을 뽑아 만든다 (지시 1 의 **ⓑ**).**
  **실측**: `grep -rn syncNightSet src tools` **0건**. 지금 밤 집합을 만드는 것은
  **`recomputePassBy()`(`game.ts:2566~2583`)의 꼬리 한 줄 `:2582`** 이다:
  ```ts
  // game.ts:2582 — recomputePassBy() 의 마지막 대입. 함수 이름이 없다
  this.nightSet = new Set(this.facilities.all
    .filter((f) => { const d = this.facilities.defOf(f); return d.indoorOnly && d.class === 'attraction' && d.capacity > 0; })
    .map((f) => f.uid));
  ```
  · **[54] 가 그 한 줄을 `private syncNightSet(): void` 로 뽑고**(추출 직후엔 호출부가 `recomputePassBy` 꼬리 **한 곳** — 동작 0),
    **거기서 둘로 넓힌다**(§2.1). 추출과 확장은 **같은 커밋**이고, 확장이 **`EVENING_TICK` 래치 프레임 호출을 하나 더** 만들어
    커밋이 끝났을 때 호출부는 **정확히 두 곳**이다(§2.2 의 ⚠ — 안 부르면 밤 집합이 다음 배치까지 안 열린다).
  · **추출에 별도 자를 만들지 않는다** — P54 의 골든은 **해시 불변**이고 **54-8③** 이 그것을 잰다.
    대신 **정적 항 하나**(54-8⑤): `game.ts` 에 `syncNightSet` **정의 정확히 1개 · 호출부 정확히 2곳**.
  · **§5 `game.ts` 신설 목록에 `syncNightSet` 을 [54] 신설로 못 박는다** — 지금 통합본은
    §5(`:809`)·§3.6 표(「[50a] 는 그대로」)·§3.9 코드 블록·§6 P54 범위·§7-r4 B5 **다섯 자리**에서
    이 이름을 **이미 있는 것처럼** 부른다. 구현자가 P50-a 에서 찾다가 「없어졌다」로 읽는다.
  · ⚠ **문서 머리의 약속**(「그대로는 그 함수가 지금 존재할 때만」)을 §0.4 재확인 목록만 지키고
    본문 다섯 자리가 안 지켰다 — **이름을 지어 부르기 전에 `grep` 한 번**이 이 절의 교훈이다.
  **반영(r5): 지시 1.**

- **D252 밤이 **얼마나** 여는지를 밴드 `nightRevShare` 하나가 잰다 — 밴드 49 → **50**.**
  실측 시각(`clock.ts:11,15,19,36`): `TICKS_PER_DAY` **1,680** · `EVENING_TICK` **1,400** ·
  `CLOSING_TICK` **1,540** · `ARRIVAL_TO_TICK` **1,400**.
  · **저녁 창은 1,400~1,680 = 280 tick(하루의 16.7%)** 이고, 그중 **손님이 남아 있는 구간은
    1,400~1,540 = 140 tick(8.3%)** 이다 — `CLOSING_TICK` 부터 전원이 입구로 걸어 나간다(`clock.ts:18~19`).
    그리고 `ARRIVAL_TO_TICK === EVENING_TICK` 이라 **밤에 새 손님은 0명**이다.
  · 그래서 **하한을 8.3% 로 유도한다**: `nightRevShare > 0.083` 이 곧 **「밤이 시간 몫보다 많이 번다」**
    = **「다른 상품」의 정의**(카탈로그 §3-20)다. 배수만으로는 최대 **+3.3%**(= 0.4 × 0.083)이므로
    이 하한은 **배수가 아니라 밤 집합이 넓어져 이용이 몰리는가**를 잰다.
  · 상한 **0.34** — 저녁 이용 밀도가 낮 평균의 **4배**일 때의 값이다
    (`1.4·s·k / (1 + (1.4k−1)·s)`, `s = 0.083` · `k = 4` → 0.336). 넘으면 **밤이 낮을 먹은 것**이다.
    기대값은 `k = 1~2` 의 **0.11~0.20**.
  · **분자는 「빠지에 매인 밤 매출」 셋**(`nightPkg + nightFood + nightFee`)이고 **분모는 그 날 총 매출**이다 —
    저녁의 다른 매출(빠지 밖 자리·매점)은 분자에 안 든다. 그래서 이 밴드는 「저녁이 벌었나」가 아니라
    **「빠지의 밤이 벌었나」**를 잰다. 그것이 B5 가 물은 것이다.
  · 음성 대조군 **`--no-night`** — 밤이 안 열리므로 분모가 되는 날이 0 이고 밴드는 **✕** 로 뜬다(`nightNights` 와 같은 모양).
  · ⚠ **P54 착수 전에 선행 측정**한다(R15 와 같은 규율). 못 넘으면 손잡이는 **밴드가 아니라**
    `nightChance`(0.5, 이미 데이터) 와 **밤 집합의 폭**이다. **하한을 내려서 통과시키지 말 것** —
    8.3% 는 게임 눈금에서 나온 값이라 내리는 순간 이 밴드가 아무것도 안 재게 된다.
  **반영(r5): 지시 2 ①.**

### 하네스 · 세이브 · 실재

- **D254 목표 슬롯 고정 세터는 **`pinGoal(n)`** 이고 **P50-b 산출물**이다 (53b → **50b**).**

  ```ts

  setInterval(() => { goalSlot = (goalSlot + 1) % 3; refreshHud(); }, 6000);   // 6초마다 A→B→C
  ```
  · 50b-16ⓓ 가 「30초마다 6샘플 중 ≥5 가 「기구」를 포함」을 재려면 **회전을 멈춰야** 하는데,
    §5 UI 표(`:2110`)는 그 세터를 **53b** 산출물로 적어 두었다 — **P50-b 시점에는 없다.**

### 2.1 `syncNightSet` — 추출 한 번, 확장 둘 (D251, [54])

```ts
// ① 추출 — 동작 0. game.ts:2582 의 한 줄이 이 함수가 된다 (추출 직후 호출부 1곳 → 확장 뒤 2곳)
private syncNightSet(): void {
  const base = this.facilities.all.filter((f) => {
    const d = this.facilities.defOf(f);
    return d.indoorOnly && d.class === 'attraction' && d.capacity > 0;      // ← :2582 원문 그대로
  }).map((f) => f.uid);
  // ② 확장 — 밤이 열린 수역의 링/물 위 둘
  const ring = this.nightOn ? this.rigsOf(this.nightPoolId) : [];
  const lit  = ring.filter((r) => r.on && this.capacityOf(this.facilities.defOf(r), r) > 0).map((f) => f.uid);
  const shop = ring.filter((r) => this.facilities.defOf(r).menuSlots > 0).map((f) => f.uid);
  this.nightSet = new Set([...base, ...lit, ...shop]);
}
// recomputePassBy() 꼬리(:2582)는 `this.syncNightSet();` 한 줄이 된다
```
- ⚠ **둘째 줄(`shop`)이 없으면 손님이 기구에 가서 0원을 쓴다** — 그것이 B5 의 실물이다.
  기존 필터가 `class === 'attraction'` 이라 **`rig_float_bar`(§4.1 `class:'restaurant'`)가 구조적으로 안 들어간다.**
  ⚠ **`rig_float_bar` 는 `facilities.json` 에 **없다**(실측)** — §4.1 **신설 21종**의 한 행이다.
- ⚠ `nightOn` 이 거짓이면 **원문과 바이트 동일한 집합**이 나온다 — 그것이 골든 불변(54-8③)의 근거다.
- ⚠ **`recomputePassBy` 는 세계가 바뀔 때만 돈다.** `nightOn` 은 **하루 한 번 tick 에서** 바뀌므로
  래치 프레임에 **`syncNightSet()` 을 한 번 더** 불러야 한다(§2.2) — 안 부르면 밤 집합이 다음 배치까지 안 열린다.
  ⚠ 이것이 「추출을 안 하면 못 하는 일」이다: `recomputePassBy()` 전체를 부르면 `passBy` 재계산이
  **매일 저녁 공짜로 한 번 더** 돈다(시설 전수 × 링 훑기).
