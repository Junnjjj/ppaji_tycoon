### 0.3 [BLOCKER 3] 게이트 이름 식이 두 페이즈를 못 가른다 — **정수 100분의 1로 짠다** (D254)

> **반영(r5):** 지적이 맞고, **한 겹 더 있다 — 부동소수점이다.**
>
> **ⓐ 지금 코드**(`tools/gate.ts:10` · `tools/verify.ts:22`, **글자 그대로 같은 한 줄이 두 파일에**):
> `(g) => g.startsWith('p') ? 100 + (Number(g.slice(1)) || 0) : …` → `Number('48a')` 가 `NaN` 이라
> **`p48a`·`p48b1`·`p48b2`·`p48c`·`p49a1`·`p49a2`·`p49b`·`p52c` 가 전부 `100`** 이다(실측). `p47`·`p55` 만 맞는다.
>
> **ⓑ 통합본 §5(2143행)의 식은 접미 한 글자만 받는다** → `p48b1 === p48b2 === 148.2`. 그런데 게이트 48a-6 은
> `148.21`·`148.22` 를 요구한다 — **같은 커밋 안의 모순**이고, 값이 같으면 「이전 게이트 누적」이 b1/b2 사이에서 무너져
> `gate -- p48b1` 이 b2 절까지 돌린다.
>
> **ⓒ ⚠ 지시가 준 식을 그대로 쓰면 48a-6 이 빨간불이다 — 실측했다.**
> `100 + n + (letter−96)/10 + sub/100` 은 **`148 + 0.2 + 0.01 = 148.20999999999998`** 이라 `=== 148.21` 이 **거짓**이다
> (`p49a1` 도 `149.10999999999999`). **부동소수점 덧셈을 세 번 하면 안 된다** — 100분의 1을 **정수로 모아 한 번만 나눈다**:
>
> ```ts
> // tools/goal-num.ts  [48a] 신설 — gate.ts:10 과 verify.ts:22 가 이것을 import 한다 (사본 금지, D146 개정)
> /** `g13`=13 · `p47`=147 · `p48a`=148.1 · `p48b1`=148.21 · `p49a2`=149.12 · `p55`=155 */
> export function goalNum(g: string): number {
>   const m = /^([gp])(\d+)([a-z])?(\d+)?$/.exec(g);
>   if (!m) return 0;
>   const base = (m[1] === 'p' ? 100 : 0) + Number(m[2]);
>   const letter = m[3] ? (m[3].charCodeAt(0) - 96) * 10 : 0;   // a → 10 (= 0.10)
>   const sub = m[4] ? Number(m[4]) : 0;                        // 1 → 1  (= 0.01)
>   return base + (letter + sub) / 100;                          // ★ 나눗셈은 한 번 — 148.21 이 정확히 나온다
> }
> ```
> **실측(17 페이즈 전수)**: `p48a 148.1 · p48b1 148.21 · p48b2 148.22 · p48c 148.3 · p49a1 149.11 · p49a2 149.12 ·
> p49b 149.2 · p50a 150.1 · p50b 150.2 · p51 151 · p52a 152.1 · p52b 152.2 · p52c 152.3 · p53a 153.1 · p53b 153.2 ·
> p54 154 · p55 155` — **서로 다르고 오름차순** ✔ · **엄밀 등호 전수 통과** ✔ · `g13 = 13`·`p47 = 147` 회귀 ✔.
>
> → 48a-6 에 두 항을 더한다(§5). **식은 §5 한 곳에만 적고, 게이트는 그 파일을 import 한다.**
