# docs 색인

**이 저장소는 세션 사이의 기억이 문서뿐이다.** 그런데 `docs/` 는 색인 없이 쌓이기 쉬워서,
무엇이 지금 유효하고 무엇이 그때의 기록인지 열어 봐야만 알 수 있었다. 이 파일이 그 물음에
먼저 답한다.

## 읽는 순서

1. **`../CLAUDE.md`** — 불변식·계약·「되돌리지 말 것」. 언제나 여기부터.
2. 지금 하려는 일에 해당하는 **정본** 하나 (아래 표).
3. 필요하면 그 뒤의 **근거**(조사·감사).

> ⚠ **뒤집힌 판단을 지우지 않는다.** 폐기된 문서도 남는다 — 다음 사람이 같은 길을 다시
> 가지 않게 하는 것이 그 문서의 쓸모다. 그래서 여기서는 **지우는 대신 상태를 붙인다.**

## 새 문서를 둘 자리

- **에셋 관련이면 `docs/` 루트에 두지 않는다** — `docs/assets/` 의 역할별 하위 폴더로 간다.
  실행 보고서와 실패 회고는 `assets/history/`, 아직 채택되지 않은 제안은 `assets/operations/`.
- 그 밖의 문서는 `docs/` 루트에 두고 **여기 한 줄을 같이 넣는다.**
  색인에 없는 문서는 다음 세션에 안 읽힌다 — 실측으로 5개가 그렇게 떠 있었다.

## 2. 에셋 — `docs/assets/` 가 통째로 소유한다

그림은 이 머신에서 못 뽑을 때가 있어 **지시서와 게이트가 따로** 있고, 2026-08-27 에
역할별 폴더로 재편했다. **진입점은 하나다:**

> ### → [`assets/README.md`](assets/README.md)

```text
docs/assets/
├── README.md      # 유일한 진입점 — 「하려는 일 → 읽을 문서」 표
├── contracts/     # 카메라·축·물리 방향 불변식
├── pipelines/     # 시설·수상기구·지형·UI 아이콘·사건 삽화 제작 흐름
├── adoption/      # 사용자 승인과 메인 적용 결정
├── operations/    # 아직 채택되지 않은 운영 실험
├── maintenance/   # 코드가 참조하는 구형 V2 유지보수 문서 (신규 제작에 쓰지 말 것)
└── history/       # 실패 보고·삭제 기록 — **정본 아님**
```

- **정본 우선순위**는 `assets/README.md` 가 정한다 (라이브 데이터 → 계약 → 파이프라인 →
  채택 결정 → 산출물 해시 → 유지보수·이력).
- ⚠ **한 단계의 PASS 를 다음 단계의 승인으로 확대 해석하지 않는다** — 콘셉트 승인 ·
  물리 회전 PASS · 채색 검수 · 풋프린트 승인 · 라이브 채택은 **서로 다른 게이트**다.
- 옛 경로(`docs/asset-*.md`)는 전부 옮겨졌다. 매핑은
  `assets/history/path-migration-2026-08-27.json` — ⚠ **그 파일의 옛 경로는 자료다.
  일괄 치환에서 제외할 것** (고치면 이력이 사라진다).
- 현황과 다음 할 일은 `../CLAUDE.md` 「다음 할 일」 2번이 정본이다.
