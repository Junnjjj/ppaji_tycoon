# v5 구조 개정 초안 — 카이로라이크 전환 (2026-08-14)

> 상태: **초안 + 세로 슬라이스 검증 중** (이 워크트리). penguin 정본에 상정하기 전 단계.
> 계기: 유저 판정 — 현 아이소+주 단위 턴제 화면이 "아기자기하지 않고 메리트가 없다".
> 근거 조사: Pool Slide Story·Tropical Resort Story (카이로소프트) 실구조 서치로 검증.

## 한 줄

**빠지 타이쿤 = "물 위로 뻗어나가는 연결식 건설"을 심장으로 하는 카이로라이크.**
Pool Slide Story(수상파크 자유 배치)와 Tropical Resort Story(섬 리조트 + 길 연결 + 인접
콤보)의 빈 교집합 — 수상파크를 물 위 연결식 구조로 짓는 카이로라이크는 없다. 그게 차별점.

## 뒤집는 결정 2개 (v2 → v5)

| | v2 (현 penguin) | v5 | 근거 |
|---|---|---|---|
| 시간 | 주 단위 턴제 ("한 주 진행" 버튼 + 0.6초 계산 + 압축 연출) | **카이로식 연속 슬로우 틱** — 시간이 스스로 흐르고, 주말 결산·카드가 자동 팝업 인터럽트 | v2 논거("실시간은 폰 2분 세션에 안 맞다")는 RCT식 빠른 실시간을 상정한 전제 오류. 카이로식 = 느린 틱 + 앱 닫으면 정지(오프라인 무진행, 프리미엄 유료와 정합) + 아무 때나 끊는 세션. 카이로소프트 전작이 반례 실증 |
| 투영·맵 | 2:1 아이소(D-025) + 자유 벌판 | **정면 3/4 탑다운 + 해안 스트립 맵** (상단 산·숲 배경, 좁은 육지 띠, 넓은 물) | 레퍼런스(컨셉 팩)의 투영이 정면 3/4. 벌판은 소재와 불일치 — 빠지는 물이 주인공 |

**시간 페이싱**: 10Hz 틱 유지. 1일 ≈ 96틱(9.6초), 1주 ≈ 67초. 2분 세션 = 약 2주 + 결산
팝업 1~2회 + 카드 1회 + 배치 몇 번. 배속은 클리어 후 해금(카이로 문법).

## 공간 문법 — "구도를 지키는 건 고정이 아니라 규칙이다"

카이로소프트는 영역을 고정하지 않는다(서치로 확인 — Tropical Resort Story 리뷰:
"doesn't force you in any one direction"). 구도는 4장치로 지켜진다:
**① 지형 액자** (지리 고정, 콘텐츠 자유 — "지형을 깎지 않는다"는 기존 불변 그대로)
**② 연결 규칙** (건물⊂길 접면, 길⊂진입로, 데크⊂물가/데크, 부착물⊂데크 가장자리,
코스⊂부표 밖 — 배치가 자기조직화됨) **③ 청키 정면 타일아트 ④ 절차 밀도** (데코·손님).

```
[고정-연출]  산·하늘 배경 레이어 (assets/generated/backdrop — 이 워크트리 산출물)
[고정-지리]  해안 스트립: 도로 → 산·숲 → 좁은 평지 띠 → 백사장 → 물(맵의 ~55%)
[자유-육지]  건물 자유 배치 + 길 접면 필수
[자유-물]    데크·인플레이터블 — 허가 사각형(돈으로 못 삼) 안에서 확장. 게임의 심장
[반자유]     코스 프리셋+핸들 (외곽 수역), 마리나 계류
```

성장 3축이 한 화면: 본관 증축(위) · 해안선 해금(옆) · 허가 면적(물 쪽).
"완전 고정 2D 이미지 겜"이 아닌 이유: 화면의 70%가 플레이어 구축물이다.

## 3D 트랙 — sim 결합 증명 (2026-08-15)

**질문**: 픽셀화 3D 디오라마로 실제 게임(의도대로 배치 → NPC 가 이용)이 되는가?
**답**: 된다. `prototype-3d` 에 **2D 프로토와 같은 sim 을 그대로 물려** 증명했다 —
sim 코드는 한 줄도 복제·수정하지 않았다 (`import { Game } from '../../src/sim/index.js'`).

새로 쓴 것은 다리 3개뿐:
- `simworld.ts` — 디오라마 지오메트리(해안선 함수·잔디 띠·수심)를 **그대로 sim 타일맵으로 칠한다**.
  타일 6월드, 50×40. 보이는 잔디에서만 건물이 놓이고 보이는 물에서만 수상시설이 놓인다.
- `sim-view.ts` — 시설은 배치될 때 파라메트릭 메시 생성, 손님은 InstancedMesh 4벌에 sim
  좌표(타일 보간 `cx+(nx-cx)*p`)를 매 프레임 써넣는다.
- `placement.ts` — 터치 → 지면 레이캐스트 → 격자 스냅 → `canPlace` 로 고스트 색 → 확정.

**실측 (Playwright, 393×852)**: 게이트 배치 → 손님 자동 유입 58명 → 4초 관찰에서 16명이
타일 이동, 10명이 시설을 목표로 잡음, 2명 대기열 진입. 시설 8개 배치 후 54명·만족 71%·60fps.
증거: `prototype-3d/shots/sim-built.png` · `sim-proof.webm`.

**이 트랙의 장부**
- 얻은 것: 16방향·facing·아틀라스·이음새 QA 문제가 **구조적으로 소멸**(회전·크기·변형이 공짜),
  깊이 정렬 공짜, 저해상 렌더라 픽셀 부하가 오히려 작음.
- 치르는 것: 시설 1종 = 스프라이트가 아니라 **파라메트릭 빌더 함수 1개**. 60종이면 60개.
- 미검증: 폰 실기기(WebGL·발열), 손님 300~1200명 규모.

### UI/UX 고도화 (2026-08-15)

폰 조작을 실제로 편하게 만든 5가지. 전부 DOM HUD (`src/hud.ts`) — 캔버스가 아니라
어느 해상도에서도 선명하고 에셋이 0장이다 (quality-bar 의 UI 문법: 상단 다크 칩 + 하단 크림 버튼).

1. **카메라 조작** (`camera-ctl.ts`) — 한 손가락 드래그 팬 + 두 손가락 핀치 줌 + 휠.
   맵 경계 클램프. 이게 없으면 카메라가 보는 자리에만 지을 수 있었다.
2. **확정형 배치** — 고른다 → 고스트가 뜬다 → 끌어서 옮긴다 → [확정] 을 눌러야 지어진다.
   탭 즉시 배치는 손가락이 미끄러지면 되돌릴 방법이 없었다. 확정 후 고스트가 유지돼
   **연속 배치**가 된다.
3. **철거 + 환급** — 철거 모드에서 시설 탭 → 절반 환급.
4. **자금** — 시작 ₩3,000만, 시설 비용 차감, 살 수 없는 카드는 자동 비활성.
   (sim 에는 경제가 없어 뷰 계층이 들고 있는 프로토용 값이다.)
5. **속도 조절** — 일시정지/1×/2×/3× (`sim.clock.speed`, 고정 timestep 유지).

배치 규칙은 sim 이 판정한다 — 고스트 색과 거부 사유(“물 위에는 지을 수 없습니다” 등)가
`facilities.canPlace()` 의 결과 그대로다. 뷰가 규칙을 흉내내지 않는다.

**실측**: 게이트 1 + 매점 2 + 화장실 1 + 그늘막 2 배치 → 손님 81명·대기 6·만족 74%·60fps.
팬/줌/일시정지 전부 동작 확인 (Playwright). 증거 `shots/ux-built.png` · `ux-demo.webm`.

### 2라운드 — 게임이 읽히게 (2026-08-15)

1. **손님 욕구 말풍선** (`bubbles.ts`) — 머리 위에 욕구 색 판이 뜬다. 카이로 문법이고,
   "저 손님이 왜 저기로 가는가" 가 화면에 보여야 경영 게임이 읽힌다. 색 = 정보:
   허기 빨강 · 갈증 파랑 · 화장실 노랑 · 더위 주황 · 휴식 보라 · 재미 초록.
   - 함정 1: sim 의 `needs` 는 **0~1 스케일**이다. 임계값을 62 로 잡아 하나도 안 떴다 → 0.38.
   - 함정 2: "흰 판 + 색 알갱이" 로 만들었더니 3~4px 에서 **흰 판만 보였다** → 판 자체를
     욕구 색으로, 흰 점은 하이라이트로 뒤집었다. 저해상에서 정보를 나르는 건 색이다.
2. **시설 정보 시트** — 뷰 모드에서 시설을 탭하면 이용/정원·대기줄·해소 욕구·이용료·
   만족 기여·건설비가 뜨고 거기서 바로 철거할 수 있다. 대기 수는 매 프레임 갱신된다.
3. **길 드래그 긋기** — 1×1 인 길은 손가락으로 죽 그으면 칸마다 깔린다 (실측 한 번에 9칸).
   한 칸씩 확정하는 건 폰에서 고문이었다.
4. **매출 연동** — `Game` 에 `onSpend` 콜백을 열어(sim 의 유일한 변경) 손님이 시설에 쓴 돈이
   자금으로 들어온다. 상단에 누계 수입 칩. sim 은 여전히 바깥을 모른다 — 평문 콜백이다.

**실측**: 시설 10개(길 포함)·손님 86명·대기 4·만족 74%·수입 +26만·60fps·콘솔 에러 0.
본체 `npm run verify` 177/177 (sim 변경 회귀 없음). 증거 `shots/r2-*.png` · `r2-demo.webm`.

### 3라운드 — 데크 확장 + 에셋 제작 스킬화 (2026-08-15)

**데크 = 물 위의 길.** sim 규칙 두 곳만 고쳐 연결식 확장이 성립했다:
1. `navigation.walkable` — `layer:'path'` 시설 타일은 **지형과 무관하게 통행 가능**.
   (기존엔 지형이 먼저라 물 위 데크는 영원히 못 걸었다.)
2. `facility-store.touchesLand` — "육지 인접" 을 **"육지 또는 통행 구조물 인접"** 으로.
   데크가 데크에 붙어야 물 위로 뻗는다. 떨어진 섬은 여전히 못 짓는다.
데이터는 `deck`(1×1, layer path, 6만원) 한 항목. 드래그로 죽 깔린다.

**실측**: 물가에서 9칸 체인 → 끝에 트램폴린 → **손님 38명이 데크 위, 49명이 트램폴린으로 향함**.
주의: 수상시설이 데크와 **대각선**으로만 인접하면 entrance 가 안 생긴다 — 사양이지 버그가 아니다.

**UI**: 가로 스크롤이 폰에서 안 잡혀 팔레트를 **카테고리 탭**(육상/동선/수상)으로 나눴다.
스크롤을 고치는 대신 스크롤이 필요 없게 만든 것.

**스킬화**: `.claude/skills/ppaji-3d-asset/` — 룩 상수 표·추가 절차 4단계·함정 표·통과 기준.
그 스킬만 보고 새 에셋(카페)을 만들어 **정합성 8/8** 로 검증했고, 그 과정에서 발견한 2건
(확정 버튼 라벨이 상태마다 바뀌어 자동화·눈이 흔들림 / 파비콘 404 로 "에러 0" 게이트가 늘 실패)을
고쳐 스킬 함정 표에 넣었다. 검사기는 `prototype-3d/tools/skillcheck.mjs` 로 상주시켰다.

### 4라운드 — 견인 코스 3D 연결 (2026-08-15)

**기구는 두 시스템이다.** 고정 기구(트램폴린·풀·슬라이드)는 시설이고, 견인 튜브는 코스다.
sim 에는 코스 시스템(`CourseStore`·`EQUIPMENT_DEFS`·차량 상태머신)이 이미 완성돼 있었고
3D 에만 연결이 없었다. 붙인 것:

- `course-view.ts` — 경로를 주황 부표로, 차량을 진행도 `u`→좌표로, **실제 탑승 수만큼** 인형을
  배 위에 (정원이 아니라 탑승 수를 그려야 처리량이 눈에 보인다). 장비별 보트 메시 4종.
- `placement.ts` — 물 위에 **손가락으로 코스를 긋는다**. 궤적을 제어점 3~6개로 줄이고
  `validateCourse` 로 실시간 판정 → 초록/빨강 점 + 거부 사유(수심·선착장 미연결·시설 통과).
  v2 설계의 "프리셋+핸들"(탭 5회)보다 3D 에선 드래그가 자연스럽다.
- `hud.ts` — `🚤 코스` 카테고리는 EQUIPMENT_DEFS 를 읽어 **자동 생성**된다.

**실측 (바나나보트, 길이 48타일, 제어점 4)**: 차량 1대 → 누적 탑승 7·대기 19.
