# 2026-09-14 게임시스템·에셋 메인 통합

## 정본과 병합 순서

1. 기존 메인 `e1fe1d3`의 승인 에셋·보존용 게임을 유지한다.
2. 시스템 브랜치의 완료 지점 `6aa70b5`를 이어받는다. `6a85f1f`가 이미 메인을 병합했고, `d8ece0b`·`6aa70b5`가 시설·환경을 `ppaji/`에 연결했다. 동일 파일을 다시 선별 복사하거나 옛 시뮬레이션으로 교체하지 않는다.
3. 이 통합 브랜치에서 승인 NPC V8 렌더 어댑터와 단일 실행 진입점을 추가한다. 새 게임의 저장·이동·지형·실내 20×30 구조는 유지한다.
4. 별도 포트 5190에서 P57-b 전체 게이트를 실행한다. 진행 중인 시스템 개발 서버 5187로 잘못 검증하지 않는다 (`PJ_URL`).
5. 메인 작업 폴더가 깨끗한지 재확인하고 fast-forward 한다. 메인 `ppaji/`를 빌드한 뒤 5189 정적 서버를 메인 체크아웃에서 교체한다.
6. 메인 주소의 빌드 SHA·파일·실행 화면을 확인한다. 검증 수치는 아래 결과에 기록한다.

## 최종 소유권

| 대상 | 정본 |
|---|---|
| 실행 게임·시뮬레이션·세이브·UI | `ppaji/src/` |
| 게임에 실제 배포되는 에셋 | `ppaji/public/assets/` |
| 승인 에셋 원본 및 제작 기록 | 루트 `public/assets/`, `docs/assets/`, 기존 제작 도구 |
| 이전 게임 | 루트 `src/`, `legacy:*` 명령으로만 실행 |
| 사용자 확인 서버 | 메인 체크아웃의 `ppaji/dist`, Tailscale `http://100.114.231.15:5189` |
| 시스템 개발 서버 | 시스템 워크트리 5187 — 메인과 별개 |

루트 `dev/build/preview/test/lint/typecheck/verify/gate`는 새 게임으로 연결한다. `npm run setup`은 루트와 하위 프로젝트 의존성을 설치한다. 원본 에셋만 바꾸고 런타임 사본을 갱신하지 않으면 게임에 반영되지 않으므로 두 위치를 함께 검증한다.

## 이번 반영 범위

- 시설 아틀라스 344프레임, 지원 시설의 실제 옆면, 새 시스템 발자국 6종 동기화: 시스템 측 완료 커밋 그대로 승계.
- 환경 장식 29종, 배경 산·숲 2장, 버스 등 외부 장식: 시스템 측 완료 커밋 그대로 승계.
- 승인 NPC V8 PNG·아틀라스·포즈 접점 JSON을 변경 없이 반입. 성인 일반 손님의 정지·걷기·앉기·수영·눕기·슬라이드에 4방향 연결. 고유 ID로 54개 외형을 안정적으로 선택하고, 실제 시간 기준 5fps 걷기 4프레임을 사용한다.
- 방향 0/1/2/3 = 앞/앞반전/뒤반전/뒤. 이미 반전된 프레임을 다시 뒤집지 않고 포즈별 원본 접점을 사용한다. 이동 보간·깊이·경사 계산은 새 시스템 것을 유지한다.
- 어린이·노인 체형, 대여 튜브가 보이는 수영·탑승, 역할색 직원은 해당 V8 원본이 없으므로 기존 전용 표현을 유지한다. 성인의 표정은 승인 원본 그대로이며 기분 데이터·말풍선·게이지는 유지한다. `?npc=0`으로 렌더 대조가 가능하다.

## 별도 후속 범위

- 유리벽 32장: 시스템 통합 계획 M4의 화면 검토 후 도입 항목으로 유지. 이번에 새 게임의 회벽/자동 경계 규칙을 임의로 바꾸지 않는다.
- 어린이·노인·튜브·직원 전용 V8 원본 및 시설 접촉 세부 조정은 별도 에셋 작업이다.
- 루트 이전 게임의 세이브를 새 `ppaji/` 세이브로 변환하는 기능은 이번 범위가 아니다. 기존 브라우저 저장값을 삭제하지 않는다.
