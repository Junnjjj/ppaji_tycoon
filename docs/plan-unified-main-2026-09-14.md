# 2026-09-14 게임시스템·에셋 메인 통합

> ⚠ 2026-09-15 대체: 아래 3 의 「승인 초기 배치(실내 13×8·테라스)」와 하네스의 `layout=reference` 우회는 **P57-c 에서 사용자 결정으로 절충됐다** — 출입동은 옛 킷 20×13, 킷 시설·장식·첫 화면은 승인 배치, 하네스·봇·골든은 실제 판을 잰다. 정본은 `docs/plan-ppaji-main-merge.md` §3.1. 5189 교체 절차(5·6)는 그대로 유효하다.

## 정본과 병합 순서

1. 기존 메인 `e1fe1d3`의 승인 에셋·보존용 게임을 유지한다.
2. 시스템 브랜치의 완료 지점 `6aa70b5`를 이어받는다. `6a85f1f`가 이미 메인을 병합했고, `d8ece0b`·`6aa70b5`가 시설·환경을 `ppaji/`에 연결했다. 동일 파일을 다시 선별 복사하거나 옛 시뮬레이션으로 교체하지 않는다.
3. 이 통합 브랜치에서 승인 NPC V8 렌더 어댑터와 단일 실행 진입점을 추가한다. 새 게임의 저장·지형 규칙을 유지하고, 승인 초기 배치(실내 13×8·테라스·매표 통로)를 연결한다.
4. 별도 포트 5190에서 P57-b 전체 게이트를 실행한다. 진행 중인 시스템 개발 서버 5187로 잘못 검증하지 않는다 (`PJ_URL`).
5. 메인 작업 폴더가 깨끗한지 재확인하고 fast-forward 한다. 메인 `ppaji/`를 빌드한 뒤 5189 정적 서버를 메인 체크아웃에서 교체한다.
6. 메인 주소의 빌드 SHA·파일·실행 화면을 확인한다. 검증 수치는 아래 결과에 기록한다.

## 승인 초기 맵 — 누락 보완

에셋 파일만 통합하는 것으로는 초기 맵의 설계가 반영되지 않는다. `src/data/kairo-arrival-presentation.json`의 마지막 승인 revision 2를 `ppaji/src/data/arrival-presentation.json`으로 그대로 반입했다.

- 북쪽 정문 `(48,8)` → 매표소 `(46,9)`, 실제 통과 칸 `(48,9)·(48,10)` → 실내 북문 `(48,11)` → 실내 → 남문 `(48,18)` → 테라스 `(48,19~21)`.
- 실내 13×8(104칸), 테라스 깊이 3칸·좌우 보도 2칸·중앙 여유 폭 3칸. 문 2개는 새 시스템의 실내 바닥/복도 규칙으로 생성된다.
- 초기 평상 연립 2개 제거, 탁구대 없음. 매표소·실내 매점·화장실·자판기·선착장 5시설과 실외 벽 주변 장식 22개. 화단 뒤/앞에 벤치를 묶고 양쪽에 나무·관목·바위를 배치한다. 장식은 실제 칸을 점유한다.
- 도로 가로수와 바깥 숲도 승인 `env_*` 나무로 연결. 도로 옆 자동차 1대와 기존 움직이는 버스 사용. 기존 먼 산·숲 띠와 주변 마을 건물은 유지한다. 울타리는 추가하지 않는다.
- 초기 자연 지형·S자 강변·높이 배열·수역·선착장은 시스템 원본과 동일하다. 매표/실내/테라스 영역의 바닥과 시설 배치만 바뀐다.
- 입장/퇴장은 원본 통과 칸과 실내 중앙 동선을 순서대로 걷는다. 기존 이동 보간을 사용하며 순간 위치 이동을 추가하지 않는다. 출입 통로 위 건설과 정문 매표소 단독 이동은 거절한다.
- `Game(seed, ..., {arrival:true})`가 승인 시작 배치다. 앱의 첫 시작·새 게임·다음 회차는 이 생성 경로를 쓴다. 이전 시스템의 `new Game(seed)` 기준 맵은 헤드리스 골든 회귀용으로 남긴다. 브라우저 하네스의 과거 G/P 사례는 `layout=reference`, 신규 승인 배치 절은 **일반 기본 URL**로 따로 검증한다. 일반 사용자는 쿼리 없이 승인 배치로 시작한다.
- 저장본은 `arrivalRevision`·매표 통과 칸·손님의 입장/퇴장 진행 칸을 함께 보존한다. 기존 저장은 원래 시작 시설·바닥·높이가 그대로이고, 건설 지출/개선/활성 손님이 없는 경우에만 복제본을 검증해서 채택한다. 이미 편집했거나 손님이 있는 진행 맵은 그대로 유지하고, 승인 초기 맵은 새 게임에 적용된다. 저장 초기화나 사용자 시설 삭제는 하지 않는다.
