## G40 — 버스 · 지역 보상

### 원작 [B][J]
- 캠페인 「**버스 송영 서비스**」: **지역을 고르면** 그 지역에서 **2일간 매일 아침** 버스가 온다. 손님 수가 크게 늘고 **특정 지역 손님을 겨냥**할 수 있다(티켓이 비싼 지역 = 수입, 소원이 있는 지역 = 진행).
- **지역 좋아요가 문턱을 넘으면** 다음날 아침 그 지역에서 버스 1대가 **자동으로** 온다. 지역 선택 화면에 「몇 대 오는지」가 표시된다. 좋아요는 새 지역·버스·**아이템** 세 가지를 준다.
- 비 오는 날에도 버스에서는 손님이 많이 내린다. 이 게임 수입의 대부분은 입장료 + 매점이다.
- SNS 아이콘 배지는 **안 본 새 글 수**.

### 우리 현재
`campaigns.json` 의 `bus` 는 「2일 ×1.5 배수」일 뿐 — 지역 선택·버스 연출·좋아요 버스·아이템 보상이 없다. 배지는 열린 소원 + 안 읽은 알림.

### 데이터
- `campaigns.json`: `bus` → `{ id: 'bus', cost: 6000, days: 2, cooldown: 8, kind: 'bus', busPerDay: 1 }` (배수 삭제). 광고 `flyer`·`tv` 는 그대로(배수형).
- `areas.json` 각 지역에 **좋아요 문턱 사다리** `busAt: [300, 600, 1000]`(이 값을 넘긴 날 다음 아침 버스 1대), `likesToUnlockNext` 는 그대로 1000. 지역별 **아이템 보상** `likeRewards: [{ at: 300, grant: { kind: 'item', id } }, { at: 600, … }]` — 아이템은 그 지역 친구들의 취향 색에서 고른다(residential → strawberry·lemon 등, 10지역 × 2 = 20건).
- `balance.json`: `busSeats: 12`(한 대 손님 수) · `busArriveTick: 60`(08:26) · `busDropTicks: 4`(한 명씩 내리는 간격).

### sim
- `campaign.ts` `start(id, day, money, opts: { areaId? })` — `kind: 'bus'` 면 `areaId` 필수, 상태에 `busArea` 저장. `mul()` 은 버스에 0 영향.
- `game.ts` **아침 버스 큐**: 하루 시작(`tick === 0`)에 `busesToday: { areaId, seats }[]` 를 만든다 = 캠페인 버스(진행 중이면 1대) + 좋아요 버스(어제 `areaLikes` 가 `busAt` 사다리를 **처음** 넘긴 지역마다 1대, 넘긴 문턱은 `sns.busGiven` 에 저장). `tick === busArriveTick` 부터 `busDropTicks` 마다 한 명씩 `spawnFromArea(areaId)` — **그 지역 친구 우선**(오늘 안 온 친구 중 rng.spawn), 없으면 그 지역 `home` 의 일반 손님. 버스 손님은 `dailyTarget` 을 **안 먹는다**(추가분).
- 좋아요 아이템: 문턱을 넘긴 날 `closeDay` 에서 `grant(likeRewards)` → inbox(우선순위 inbox, 「○○ 주민들이 감사 선물」).
- `sns.ts`: `postsSeen: number`(플레이어가 타임라인을 마지막으로 본 글 수) — 배지 = `allPosts.length - postsSeen`. 세이브 필드 optional.
- RNG: 버스 손님 선택은 `spawn` 스트림, 추가 뽑기 횟수는 **좌석 수만큼 고정**(친구가 없어도 같은 횟수) — 스트림 밀림 방지.

### 렌더·UI
- **버스 스프라이트**(`fac/bus` 1종, 도트 DSL 32×24 + 3D 프리렌더 대상에 추가): 토지 아래 도로 띠(게이트 앞 3칸)에 **왼쪽에서 들어와 서고**, 손님이 한 명씩 내려 게이트로 걷고, 다 내리면 오른쪽으로 나간다. 위치는 sim 의 `busState { areaId, x: 0..1, phase }` 를 렌더가 보간(손님 보간과 같은 규칙).
- 캠페인 창의 버스 항목: 「지역 고르기」 서브 리스트(열린 지역만, 각 줄에 티켓 평균가 · 열린 소원 수 · **오늘 올 버스 대수**[B]).
- 도착 연출: 버스가 서면 `dust-puff` + 「○○에서 버스 도착 · N명」 토스트(모달 아님) · 좋아요 버스는 티커에 예고(「내일 아침 학교 지역에서 버스가 온다」).
- HUD SNS 배지 = 안 본 글 수. 타임라인을 열면 0.

### 검증
- 단위: 캠페인 버스 2일 × 12명 = 24명 추가 입장 · 좋아요 300/600/1000 문턱마다 정확히 1대(같은 문턱 두 번 없음) · 스냅샷 왕복 뒤 아침 버스 큐 동일 · 버스 손님이 `dailyTarget` 을 안 깎는다.
- 봇: `--bands` 에 `busGuestsShare ∈ [8%, 30%]`(128일 방문 중 버스 몫). 봇은 「소원이 열린 지역」으로 버스를 부른다(정책 훅 하나).
- verify: 캠페인 창에서 지역 행 터치 → 다음날 08:26 버스 스프라이트가 도로 띠에 있고 손님이 내린다(`scene.busForTest()`), 배지가 새 글 수와 같다.

### 리스크
버스 12명이 한꺼번에 오면 동시 손님 상한(40+랭크×12)에 걸린다 → 버스 손님은 상한을 **12 초과 허용**(PSS 도 버스 날은 붐빈다). 비 오는 날 유입 배수 0.6 이 버스에는 안 걸린다[B].

## G41 — 요리 = ★2 · 요리 키우기 · 실패 요리

### 원작 [J][B][S]
- 요리 개발은 **★2 랭크업**으로 열린다. ★2 가 되면 「돈 걱정이 끝난다」 — 초반 목표는 「빨리 ★2」.
- 레시피는 **재료 등급(클래스)** 로 적혀 있다: 「후르츠 크레이프 = 밀가루+달걀+**과일**」「디럭스 크레이프 = 밀가루+달걀+과일+과일+과일」「과일 샐러드 = 양배추+과일×3」. 같은 뼈대에 **재료를 더 넣으면 상위 요리**가 된다(메가 크레페·트리플 아이스).
- 레시피에 없는 조합은 **실패가 아니라 기본 요리**(도넛·쓰쿠네)가 나오고, 채소만 넣으면 **야채 찌꺼기**, 밀가루만이면 **탄 빵** — 「카이로봇 레시피」 항목[S].
- 요리 화면 「레시피 → **설정**」 버튼이 재료를 자동으로 채운다. 기본 메뉴는 자작보다 스탯이 낮아 중반부터 갈아 끼운다.
- 궁합 좋은 가게에 걸고 **가격을 올린다**(가격 = 스탯 합).

### 우리 현재
`COOK_UNLOCK_YEAR = 2` · 정확한 다중집합 키만 조회 · 실패 = 힌트 문장 · 도감에 설정 버튼 없음.

### 데이터
- `ingredients.json` 에 `class: 'fruit' | 'veg' | 'dairy' | 'grain' | 'meat' | 'seafood' | 'sweet' | 'base'` 추가(60종 전부).
- `recipes.json` 키를 **클래스 와일드카드** 허용: `key: "flour+egg+@fruit"`(`@class` = 그 클래스 아무거나). 140종 중 원작 표[S]에 와일드카드가 있는 것(후르츠 크레이프·디럭스 크레이프·과일 샐러드·믹스 주스·후르츠 아이스바 등 ~15종)만 바꾼다. 나머지는 정확 키 그대로.
- **강화 사슬** `upgradeOf: { base: 'crepe', add: ['@fruit'] }` → `fruit_crepe`, `{ base: 'fruit_crepe', add: ['@fruit','@fruit'] }` → `deluxe_crepe`. 검사: 사슬은 2단까지, 가격 ≤ 기본 +60%, 만족 ≤ +5 (빠지 타이쿤 `validateMenuData` ⑦ 와 같은 상한).
- **실패 요리 4종**(`cat: 'fail'`, 가격 50~80, 인기 1): 야채 찌꺼기(채소만) · 탄 빵(곡물만) · 도넛(그 외 곡물+설탕 포함) · 쓰쿠네(그 외 고기 포함) · 그 외 = 「수상한 주스」(음료). 실패 요리는 도감에 남고 메뉴에 걸 수 있다(원작 그대로 — 카이로 유머).
- `ranks.json` ★2 보상에 `{ kind: 'unlock', id: 'cooking' }` 추가, `COOK_UNLOCK_YEAR` 삭제. ★2 조건은 지금(인기 150 · 인증 2 · 친구 10) 유지 — 봇 실측 ★2 도달 Y2 봄~여름이라 「2년차」와 체감이 비슷하다.

### sim
- `cooking.ts` `match(ids)`: ① 정확 키 → ② 와일드카드 키(클래스 치환, 여러 개 맞으면 **재료 수가 많은 쪽**) → ③ 강화 사슬(기본 레시피 키 ⊂ ids 이고 남는 재료가 `add` 클래스와 맞으면 상위) → ④ 실패 요리 분류. `cook()` 은 **언제나 요리를 돌려준다**(`ok: false` 는 재료 부족·돈 부족뿐).
- EXP: 발견 30 · 실패 요리 8(지금 4) · 강화 발견 20.
- `game.ts` `canCook()`: `rank >= 2` (연차 조건 삭제). 스토리 `recipes10` 트리거는 그대로.
- 메뉴 인기 계산(`restaurant.ts`)은 안 바뀐다 — 요리 스탯이 데이터에 있으므로.

### UI
- 요리 창: 도감 행마다 **「설정」** 버튼(재료 칩을 그 레시피 키로 채운다, 와일드카드는 가진 재료 중 첫 것) · 실패 요리는 도감 아래 「실패작」 절 · 개발 결과 창에 「기본 → 강화」 화살표(카운트업은 빠지의 `CelebrationDelta` 규칙 그대로: 방향은 값에서 유도).
- 요리 칸 잠금 이유 「2년차」 → 「★2」. 목표 티커 초반 문장에 「★2 가 되면 요리 개발」.

### 검증
- 단위: 와일드카드 매칭(어떤 과일이든 후르츠 크레이프) · 강화 사슬 상한 · 실패 4분류 · 정확 키 우선 · 결정론(같은 재료 순서 무관).
- 데이터 검사: `@class` 가 실재 클래스 · 사슬 2단 · 실패 요리는 `unlock: 'auto'`.
- 봇: 요리 정책이 「기본 → +과일」 강화를 시도한다. 밴드 `recipes ≥ 40` 유지 · 새 밴드 `foodShare ∈ [25%, 55%]`(수입 중 매점 몫, [B]「수입 대부분은 입장료+매점」).
- verify: 밀가루+계란+과일 → 후르츠 크레이프 발견 · 과일 셋 더 → 디럭스 · 채소만 → 야채 찌꺼기 · 「설정」 터치로 칩이 찬다 · ★1 판에서 요리 칸이 잠겨 있고 ★2 로 올리면 열린다.

### 리스크
「실패해도 요리가 나온다」는 돈이 새는 길이 될 수 있다 → 실패 요리 가격 ≤ 재료비(300G 개발비 회수 불가). ★2 전엔 요리가 없으니 1년차 매점 수입이 기본 메뉴뿐 — 봇 1년차 말 현금(지금 12만) 밴드로 본다.

## G42 — 풀 상세 · 심사 만점 조건

### 원작 [B][J][S]
- 풀 정보에서 **색·향·온도를 탭하면 상세**: 색은 섞인 비율, **농도 5칸 막대**(경쟁하는 색·향이 있으면 내려간다, 작은 풀일수록 5칸이 쉽다), 향은 아이템 vs 인접 시설(동점이면 아이템 우선, 시설은 1칸 이내), 온도는 **최저 15 · 최고 40**, **계절별 이상 온도**가 표시되고 가까울수록 체류가 길다.
- 무지개·조건 풀을 만들 때 **부족한 요소**가 그 화면에 나온다.
- 아이템 효과 시간은 개수와 무관하게 **넣은 시점부터 2계절+1일(7일)**. 한꺼번에 많이 넣어도 안 늘어난다 → 반년에 한 번 갈아 넣는 리듬.
- 심사 만점: 색·향은 농도 100%, 시설 조건은 상위일수록 복수(더지 실측: 「미니 슬라이드 3개·유수풀 20개·인기 200」).

### 우리 현재
상태 줄 한 줄(색·향·온도·인기) · 강도(`intensity`)는 있지만 안 보임 · 아이템 지속은 종류별 2·3·4시간 · 심사 창은 예상 점수/부족 점수까지.

### 데이터
- `items.json` `hours` → **`days: 7` 공통**으로 바꾸고 `expiresTick = 넣은 날 + 7일의 폐장`(개수 무관 — 같은 풀에 또 넣으면 **만료가 안 늘어난다**: 풀의 `itemsUntilDay` 하나). ⚠ 이건 밸런스 변경이다(지금은 3시간이라 하루 두세 번 넣는다). 봇 아이템 정책을 「7일마다」로.
- `seasons.json` `idealTemp: [26, 30, 24, 36]`(봄·여름·가을·겨울, 실내는 28).

### sim
