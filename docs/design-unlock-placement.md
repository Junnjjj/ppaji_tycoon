# 설치·해금 시스템 재검토 — 우리는 벽이고, 카이로는 선물이다

> 2026-08-19. 시간 모델(design-time-model.md)에 이어 사용자 요청: "시간 말고도
> 설치하고 게임 해금하는 시스템들". 같은 방법 — 우리 실물 측정 + 1차 소스.
> **기획/설계만.** 코드 변경 없음. 결정 요청은 §6.

---

## 0. 우리 해금의 실물 (데이터에서 직접 측정)

| 축 | 실물 |
|---|---|
| **등급 1→5** | 유일한 해금 축. 조건 = 퇴장 만족도 이동평균 문턱 (55/65/75/85) |
| 등급이 여는 것 | 시설 **뭉텅이** (1등급 40개 → +15 → +12 → +2 → +4), 토지, 허가 면적, 정원 |
| **의뢰 16종** | 보상이 **16종 전부 현금** (30만~500만) |
| **콤보 70종** | 효율 보너스일 뿐 — 아무것도 해금하지 않는다 |
| **주간 카드 24종** | 일회성 손익 이벤트 — 해금과 무관 |
| **이동** | **없다.** 철거(환급)만 있다 (`main.ts:275`) |
| 건설 시트 | 73항목 전부 노출, 33개(45%) 잠김 표시 (UX 검수 §4) |

구조를 한 줄로: **수동 스탯이 기어 올라가길 기다리면 벽이 한 번에 열리고, 열리는 건
목록이다.** 만족도 55를 넘는 순간 15개가 쏟아지고, 그 전까지는 잠긴 15개가 시트에서
자리를 차지한다. 그 사이(같은 등급 안)에는 **아무것도 도착하지 않는다.**

## 1. 카이로의 해금 실물 (1차 소스 — wiki.gg 원문을 API 로 직접 읽음)

### Pool Slide Story — 해금 출처가 다섯 갈래다

> "They can be obtained or unlocked from **Pool Association Judge, Friends in SNS,
> Certification, Research, and Pool Rank Up**." (Facilities 페이지 첫 문단)

개별 항목의 Availability 열이 **전부 사건**이다:

| 항목 | 해금 방법 (원문) |
|---|---|
| Move (이동 도구) | "Gift from President on Y1 Aut. WKEND **after first certification**" |
| Floaty Tubes | "Gift from President on Y1 Spr. WKEND" |
| Showers | "**Reward for Helicopter Mom's Wish #1**" |
| Snazzy Swimwear | "Unlocked at 5pm on Y1 Sum. 1st WKDAY" (상점 입고) |
| Entrance | "First Expansion" |

- **소원 체인**: 손님 71명이 개별 인물. 만족도가 문턱을 넘으면 소원을 말하고(1인 3개),
  보상은 "**new visitors, rare consumables, shops and facilities**" — 돈이 아니라
  **콘텐츠**다. 새 손님이 새 소원을 부른다 — 해금이 해금을 부르는 사슬
- **구역 해금**: 손님들이 찍은 사진의 SNS 좋아요 1000개 = 다음 거주 구역 —
  **구경이 곧 진행**
- **랭크 업 = 시험**: 인증(Certification)에 응시한다. 봄·가을에 신청 → **준비 3일** →
  주말 3시에 심사. 요구조건 2~3개, 심사관 3인 각 10점, 커트라인은 만점(30)이 아니라
  최대 25 — **완벽을 요구하지 않는다**. 실패해도 두 계절 뒤 재응시.
  랭크 업은 인증 통과 **횟수**를 요구한다

### Mega Mall Story — 콤보가 해금의 재료다

> "Pumpkin Products will **sell the formulae** for all the combos … at varying points
> in your mall's progression; **the last eight … are not notified in any way until the
> player actually sets the components together.**" (Combos 페이지)

조합법은 진행에 따라 **팔리는 상품**이고, 마지막 8개는 **숨겨져 있어 직접 놓아 봐야
발견**된다. 배치 실험 자체가 해금 행위다.

## 2. 구조적 차이 — 다섯 가지

| | 우리 | 카이로 |
|---|---|---|
| 해금 축 | **1개** (등급) | **5개** (심사·소원·인증·연구·랭크) 가 서로 얽힘 |
| 도착 방식 | 뭉텅이 (한 번에 15개) | **낱개가 사건으로** (선물·보상·입고·발견) |
| 등급/랭크 | 수동 문턱 — 평균이 기어 오르길 기다림 | **능동 시험** — 내가 응시를 결정, 준비, 부분 점수, 재도전 |
| 의뢰 보상 | 현금 16/16 | **콘텐츠** (새 손님·시설·상점) |
| 다듬기 | 철거+재구매 = 벌금 | **Move 도구** (200G) — 그것조차 해금 선물 |

카이로 중독성의 정체가 "항상 무언가를 향해 가고 있다"(시간 모델 문서 §1)였는데,
그 공학적 실현이 바로 이것이다: **작은 해금이 여러 갈래에서 끊임없이 도착하게 만든다.**
우리는 갈래가 하나뿐이고, 그 하나도 몇 시간에 한 번 열리는 벽이다.

⚠ 우리 의뢰 16종은 이미 조건 충족형이고 v4 가 "조건 미달이 곧 다음 목표"라고 설계했다
— **방향은 맞았는데 보상이 전부 돈이라 사슬이 안 생긴다.** 돈은 다음 목표를 만들지
않는다. 시설이 다음 목표를 만든다 (새 시설 → 새 배치 → 새 콤보 → …).

## 3. 설치(배치) 검수

**유지할 것** — 탭 → 고스트 → 확정(+회전 예약)은 폰에 맞고, 블록 붓·건물 확장·문·코스
핸들도 검증됐다. 문제는 배치 그 자체가 아니라 **배치를 둘러싼 회로**다:

1. **이동이 없다.** RCT 분석(design-late-game-analysis.md §2)이 "되돌아와 다듬는다"를
   우리의 빈칸으로 지목했는데, 다듬기의 최소 도구가 이동이다. 철거+재구매는 다듬기가
   아니라 **벌금**이다. 카이로도 Move 를 준다 — 소액 과금(200G)으로 남발만 막는다
2. **배치 직후 피드백이 없다.** 놓은 시설이 좋은지 나쁜지는 다음 결산(주 단위)에나 온다.
   ⚠ 이 문제의 절반은 **시간 모델이 푼다** — 흐르는 낮에서는 놓자마자 손님이 몰리는 게
   보인다. 나머지 절반은 콤보 발동 순간의 연출(지금은 조용히 보너스만 붙는다)
3. **배치가 해금을 부르지 않는다.** MMS 는 "이 셋을 붙이면 뭐가 될까?"가 실험 동기다.
   우리 콤보 70종은 도감에 다 적혀 있고, 발견의 순간이 없다

## 4. 제안 — 해금을 다축 사건으로, 배치를 실험으로

시간 모델 하이브리드(흐르는 낮 + 주 마디)를 전제로 한다. 사건이 도착할 "낮"이 있어야
이 설계가 산다.

### 4-1. 등급을 시험으로 바꾼다

만족도 문턱을 넘으면 자동 승급 → **"심사를 신청할 수 있습니다"** 로 바꾼다:

```
만족도 조건 충족 = 응시 자격 (지금 문턱 재사용)
  → 심사 신청 (수수료) → 심사까지 N일 (준비 기간 — 요구조건 2~3개 공개)
  → 심사관 방문 (흐르는 낮에 걸어 들어온다 — 보인다)
  → 부분 점수 판정, 커트라인은 만점 아님. 실패 시 다음 철에 재응시
```

요구조건은 기존 의뢰 조건 풀에서 뽑는다 (위생 N개·경관 M·특정 시설 — 이미 데이터가 있다).
**"내가 응시를 결정했다"가 핵심이다** — 수동 대기가 목표 지향 행동으로 바뀐다.

### 4-2. 뭉텅이 해금을 낱개 사건으로 재배분한다

등급이 여는 시설 수를 줄이고(15개 → 골격 5~6개), 나머지를 다른 갈래로 나눈다:

| 갈래 | 무엇을 열까 | 기반 |
|---|---|---|
| 등급 심사 통과 | 골격 시설 (허가·토지·정원은 그대로 등급) | 지금 구조 |
| **의뢰 보상** | 현금 → **시설/장비 해금 + 소액 현금** 으로 교체 | 의뢰 16종이 이미 있다 |
| **손님 소원** | 손님 유형별 대표 인물의 소원 3단계 → 새 장비·시설·새 손님 유형 | PSS 소원 체인. 71명은 과하고 **유형별 2~3명 = 8~12명** |
| **콤보 발견** | 70종 중 20~30종은 도감에 `???` — 처음 발동시키면 보상(시설 1개 or 조합법 공개) | MMS 숨은 콤보. 콤보 감지는 이미 돌고 있다 |
| 상점 입고 | 계절 이벤트로 한정 장비 입고 ("여름 한정") | 주간 카드 확장 |

효과: 건설 시트의 잠김 45% 문제(UX 검수 §4)가 **구조적으로** 풀린다 — 잠긴 것을 접는
게 아니라, 애초에 낱개로 도착하므로 시트에는 **가진 것 + 다음에 올 것 한둘**만 보인다.

### 4-3. 이동 도구를 넣는다 — 해금 보상으로

- 기능: 시설 탭 → `이동` → 고스트로 옮김. 비용 = 건설비의 10% 안팎 (남발 방지)
- **첫 심사 통과 보상으로 준다** (PSS 그대로) — 도구 자체가 선물이 되는 경험
- 다듬기 루프가 열린다: 결산 히트맵에서 병목 확인 → 이동으로 실험 → 다음 날 바로 확인
  (흐르는 낮)

### 4-4. 발견의 연출

콤보 첫 발동: 흐르는 낮에서 반짝임 + 토스트 (`숨은 조합 발견! 바베큐 삼형제`) + 도감
기입. 시간 모델 문서 §5 규칙 5(사건은 일어날 때 보여 준다)와 같은 채널을 쓴다.

### 후반 공백(다음 할 일 3번)과의 관계

이 다축 구조가 그대로 후반의 답이 된다: **시험·소원·발견은 등급 5 이후에도 계속된다.**
- 소원 체인은 손님 인물이 남아 있는 한 마르지 않는다
- 숨은 콤보 20~30종은 배치 실험 동기를 후반까지 끌고 간다
- 등급 5 위에 "명예 인증" 티어(반복 응시, 요구조건 상향)를 열면 상한 축이 생긴다 —
  PSS 도 인증 재응시가 엔드게임 콘텐츠다

## 5. 아키텍처 적합성 (불변식 대조)

- **"시설·장비·연구는 데이터다"** — 해금 갈래는 `kairo-unlocks.json`/`kairo-quests.json`
  의 필드 확장이다 (`unlockBy: quest|combo|wish|shop`). 코드가 아니라 데이터가 는다
- 콤보 감지·의뢰 판정·카드 파이프라인 **전부 이미 있다** — 새 시뮬 시스템은
  손님 소원(인물 상태 + 문턱 트리거) 하나다
- 심사는 주간 카드의 특수형으로 시작할 수 있다 (조건 충족형 의뢰 16종과 판정 공유)
- 결정론: 소원 문턱·심사 판정 모두 기존 `rng.fork` 패턴. 사건 도착 시점은 tick 함수다

## 6. 결정 요청

1. **방향**: §4 다축 사건 해금으로 가나? (등급=시험 · 의뢰 보상=콘텐츠 · 소원 체인 ·
   숨은 콤보 · 이동 도구)
2. **순서 제안**: ① 의뢰 보상 교체 + 시트에서 잠김 숨기기 (데이터 작업, 가장 싸다) →
   ② 이동 도구 → ③ 등급 심사 → ④ 소원 체인 → ⑤ 숨은 콤보. 시간 모델(흐르는 낮)과
   병행 가능 — ①②는 독립이다
3. **손님 인물 수**: 유형별 2~3명 = 8~12명 제안 (PSS 71명은 에셋 비용이 우리 규모를 넘는다)
