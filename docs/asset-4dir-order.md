게이트 4·5 는 *한 장이 잘 그려졌는가*를 재고, 어느 것도 *두 장이 서로 다른 방향인가*를
안 쟀기 때문이다. 이 저장소가 열 번째로 밟은 「검사가 조용히 통과」다.

**그래서 게이트 6(회전)을 먼저 만들었다** (`tools/rotation-check.ts`). 다시 돌리기 전에
이 자가 있다는 것이 1차와의 유일한 차이다.

```bash
npx tsx tools/rotation-check.ts --selftest          # 대조군 9/9
npx tsx tools/rotation-check.ts --dir <방향 폴더>   # 감사 작업공간을 잰다
npx tsx tools/kairo-gate.ts                          # 게이트 6 이 요약에 들어 있다
```

4. **3회 리롤로는 모자란다** — 실패 대부분이 한도 소진이었다. 다만 **한도를 늘리기

§5 하면 안 되는 것. §6 은 이 상태의 실측이다.

⚠ 이 문서는 `docs/asset-regen-order.md`(접지 기하 재생성)와 **짝**이다. 스타일 블록·

## 2. 배선 — **그림과 데이터를 같은 변경에서 바꿔야 한다**

⚠ **이게 이 문서에서 제일 잘 틀리는 자리다.** `facings: 4` 한 줄은 계약 ID 를 갈아치운다:

```
facings 2 (지금)   facility/shop                    ← 파일 facility__shop.png
facings 4          facility/shop:d0 … :d3           ← 파일 facility__shop__d{0..3}.png
```

즉 `facings: 4` 를 켜는 순간 **`facility/shop` 이 계약에서 사라진다.** 그래서:

- **데이터만 먼저 바꾸면** → 게이트 3 이 `생성물누락`(계약 ID 4개에 그림이 없다) +
  `계약에 없는 산출물`(`facility__shop.png`) 을 낸다. 둘 다 **경고가 아니라 하드 실패**라
  `npm run gate` 가 죽는다
- **그림만 먼저 넣으면** → `facility__shop__d0.png` 가 `계약에 없는 산출물` 로 잡힌다.
  ⚠ 파일명 자체는 **문제가 없다** — `assetFileToId('facility__shop__d0.png')` 는
  `facility/shop:d0` 로 정확히 파싱된다 (실측. 변형 축 **하나**까지는 견딘다는 그
  함수의 주석 범위 안이다). 계약에 그 ID 가 아직 없을 뿐이다

**한 커밋에서 셋을 같이 한다:**

1. `src/data/kairo-facilities.json` 의 그 시설에 `"facings": 4` 한 줄
2. `assets/generated/kairo/facility__<id>__d{0,1,2,3}.png` 네 장 추가
3. `assets/generated/kairo/facility__<id>.png` **삭제**

⚠ **봇(`tools/kairo-sim.ts`)이 아직 방향 2개만 본다** — 첫 시설을 4로 켤 때 봇도 같이
옮겨야 헤드리스가 다른 세계를 재지 않는다 (CLAUDE.md 의 K36 규칙).

⚠ 아틀라스는 `npm run bake:atlas` 로 다시 굽는다. 장수가 144 → 147(1종) …
→ 222(26종 전부) 로 는다.

## 3. 어떻게 뽑나

### 3.1 체인 참조 — 한 캔버스에 넷을 그리지 않는다

스킬이 검증한 순서다:

```
d0  락 베이스            — 가이드 + 스타일 크롭으로 새로 그린다
d1  d0 을 참조           — "MIRRORED front" (앞면을 반대쪽에서)
d2  d0 을 참조           — "rear view"     (뒷면)
d3  d2 를 참조           — "MIRRORED rear"
```

⚠ **한 캔버스 4-up 스트립 금지.** 실측으로 두 가지가 깨졌다 — 셀당 해상도가 **1/4** 로
떨어지고, 차양의 빨강이 이웃 셀로 **주황으로 샜다**. 시트를 합치지 않는 이유
(`docs/asset-prompts.md` §시트 크기 산식)와 같은 사고다.

⚠ 체인 참조는 **모양을 잇는 장치이지 그림을 복사하는 장치가 아니다.** 참조를 그대로
좌우 반전해 오면 §5.5 의 광원 뒤집힘이 그대로 들어온다 — 지금 shop 표본이 정확히 그 상태다.

### 3.2 가이드 첨부 — d1·d3 은 **전치된 가이드**다

발자국은 **홀수 방향(1·3)에서 W↔D 가 맞바뀐다** (`PlacementGrid.sizeOf` — sim 정본).
캔버스는 안 변하지만 접지 다이아몬드의 **최하단 꼭짓점**이 옮겨간다:

```
ticket 3×2   d0·d2 → 꼭짓점 x/폭 0.600 (= 3/5)   가이드 facility__ticket.png
       2×3   d1·d3 → 꼭짓점 x/폭 0.400 (= 2/5)   가이드 facility__ticket__d1.png
```

⚠ **"(W+D) 가 불변이니 같은 가이드"는 절반만 맞다.** 캔버스 크기는 같지만 **다이아몬드가
다르다.** 정사각 발자국(17종)만 한 장으로 끝난다.

전치 가이드는 도구가 만든다 (정사각은 알아서 건너뛴다):

```bash
npx tsx tools/make-kairo-guide.ts --id ticket --transpose        # → facility__ticket__d1.png
npx tsx tools/make-kairo-guide.ts --id ticket --transpose --table # 규격 한 줄
```

⚠ **가이드 PNG 를 좌우 반전해서 쓰지 말 것.** 모양은 맞아 보이지만 가이드가 옆면에
칠해 둔 명암(`+J` 왼쪽 밝음 / `+I` 오른쪽 어두움)까지 뒤집혀서 — **게이트 5 가 잡는 바로
그 결함을 지시서가 시키는 꼴**이 된다. `--transpose` 는 뒤집는 게 아니라 **다시 그린다.**

⚠ 이것은 `docs/asset-regen-order.md` §4.1 「가이드를 뒤집지 마라」와 모순이 **아니다.**
저기서 금지한 것은 *같은 방향*의 그림이 축뒤집힘으로 나왔을 때 옳은 가이드를 뒤집는
것이고, 여기서는 **발자국이 실제로 전치된 다른 방향**이다.

### 3.3 프롬프트 조립

d0 의 프롬프트는 기존 도구가 그대로 만든다 (스타일 블록 축자 · 시트 본문 · 규격 줄 ·
크로마 · 참조 크롭 · 직전 실패 모드):

```bash
npx tsx tools/regen-facility.ts --id ticket --dry-run     # 프롬프트 + 첨부 순서
```

d1~d3 은 그 프롬프트에 **방향 문단 하나**를 더한다. 문단이 말해야 하는 것은 셋뿐이다:

1. **어느 면이 카메라 쪽인가** — `d1` 은 앞면이 반대쪽에서, `d2` 는 뒷면, `d3` 은 뒷면이
   반대쪽에서
2. **발자국** — 비정사각이면 전치된 수치를 규격 줄과 첨부 가이드 **둘 다** 로 준다
   (`--transpose --table` 출력을 축자로)
3. **광원은 안 따라 돈다** — 아래 문장을 축자로 넣는다:

```
LIGHT DOES NOT ROTATE WITH THE OBJECT. The single light stays at the UPPER LEFT of the
screen in every one of the four directions. The face that points toward the screen's
LOWER LEFT is always the lit one; the face that points toward the LOWER RIGHT is always
the shadow one. Do NOT mirror the shading when you mirror the shape — re-shade it.
```

## 4. 판정 — **다섯** 게이트를 **네 장 다** 통과해야 한다

```bash
npx tsx tools/kairo-gate.ts             # 요약 (계약·드로어·캔버스·접지·광원·회전)
npx tsx tools/kairo-gate.ts --geom      # 게이트 4 접지 기하 표 전체
npx tsx tools/kairo-gate.ts --light     # 게이트 5 광원 방향 표 전체
npx tsx tools/kairo-gate.ts --selftest  # 게이트들의 대조군만 자세히
npx tsx tools/rotation-check.ts --dir <폴더>  # 게이트 6 을 **팩 밖 작업공간**에 쓴다
npm run gate                            # 위 요약과 같다 (verify 가 부르는 것)
```

`facings: 4` 를 켜면 게이트 4·5 가 **네 장을 따로** 잰다 (`ticket:d0` … `ticket:d3`).
d1·d3 의 기대 꼭짓점은 전치값(0.400)이고, 게이트가 알아서 그렇게 잡는다 — 실측 확인함.

| 게이트 | 무엇을 | 네 방향에서 달라지는 것 |
|---|---|---|
| 3 캔버스 크기 | PNG 헤더 vs 계약 | 네 장이 **같은 크기**여야 한다 |
| 4 접지 기하 | 최하단 윤곽의 꼭짓점·기울기·모양 | d1·d3 의 기대 꼭짓점이 **전치**된다 |
| 5 **광원 방향** | 접지선 위 벽 띠, 왼쪽 − 오른쪽 | **네 장 다 뒤집히지 않아야** 한다 (§5.5) |
| 6 **회전** | 실루엣이 기준의 미러인가 | **이 게이트는 4방향에만 존재한다** |
| 팔레트 | 39색 밖 화소 0 | 없음 |

⚠ **게이트 5 의 통과 기준은 `뒤집힘 아님`이지 `좌상단`이 아니다.** 팩 자체가 `평탄`
16장이고 `arcade`·`slide_tube` 는 **d0 이 평탄**이다 — `좌상단` 만 통과로 치면 그 시설은
구조적으로 4방향을 못 켠다. 1차 시도가 이 규칙을 스스로 조여 8장을 버렸다 (§0-2).

⚠ **게이트 6 은 `d1`·`d3` 만 잰다.** `d2`(뒷면)는 180° 라 발자국 다이아몬드가 안 바뀌므로
실루엣이 앞면과 같아야 **정상**이다. 뒷면이 앞면의 **내용**을 되풀이하는 결함은
실루엣으로 못 잡으니 **눈으로** 본다 (§0-1, 1차에서 5장).

⚠ **`대칭(판정불가)` 은 통과가 아니다.** 자판기·정사각 건물처럼 실루엣이 자기 미러와
거의 같은 물체는 이 자로 방향을 말할 수 없다 (`infirmary` 자기미러 IoU **0.993**).
그런 시설은 **눈으로 확인하는 것 말고 방법이 없다** — 게이트가 초록이라고 넘기지 말 것.

팔레트·도트 경계율은 게이트 밖이라 한 줄로 잰다 (지금 시설 75종: 팔레트 밖 **0** 화소 ·
경계율 **51.1%**, 대상 26종은 **56.2%**):

```bash
python3 - <<'PY'
import json, glob
from PIL import Image
PAL={tuple(int(c[i:i+2],16) for i in (1,3,5))
     for cs in json.load(open('art-reference/palette-proposed-39.json')).values() for c in cs}
off=edges=tot=0
for p in sorted(glob.glob('assets/generated/kairo/facility__*.png')):
    im=Image.open(p).convert('RGBA'); w,h=im.size; px=im.load()
    for y in range(h):
        prev=None
        for x in range(w):
            r,g,b,a=px[x,y]
            if a<128: prev=None; continue
            if (r,g,b) not in PAL: off+=1
            tot+=1
            if prev is not None and (r,g,b)!=prev: edges+=1
            prev=(r,g,b)
print(f'팔레트 밖 {off} / {tot} 화소 · 도트 경계율 {edges/tot*100:.1f}%')
PY
```

⚠ **게이트 4·5·6 은 경고다** (`WARN_GATES` — 종료 코드에 안 들어간다. `--strict` 로 승격).
지금 팩이 이미 빨간 상태라 실패로 올리면 에셋과 무관한 작업까지 막힌다. 그동안 게이트는
**목록을 내는 일**을 한다. ⚠ 게이트 6 은 지금 **`회전 0짝 측정`** 이다 — 초록인 게 아니라
**잰 게 없다**. `facings: 4` 를 켤 때 `WARN_GATES` 에서 빼서 실패로 올릴 것.

⚠ **대조군 실패(`회전대조군`)는 경고가 아니다** — 그림이 아니라 자가 고장 난 것이므로
종료 코드를 바꾼다 (게이트 5 의 `광원대조군` 과 같은 결정). 실측으로 확인했다: 문턱을
0 으로 죽이면 `npm run gate` 가 **종료 코드 1** 로 죽고, 원복하면 0 이다.

## 5. ⚠ 하면 안 되는 것

§5.1~5.4 는 `docs/asset-regen-order.md` §4 를 그대로 이어받는다 (숫자와 근거는 거기에).
**§5.5 가 4방향에서 새로 생기는 것이다.**

### 5.1 가이드를 뒤집지 마라

축뒤집힘을 봤을 때 가장 먼저 떠오르는 수인데 **틀렸다.** 좌우 반전은 무손실인데도 실측
**통과 0종**(나아짐 4 · 나빠짐 5). 옳은 가이드를 붙이고 **프롬프트로 지목**할 것.
⚠ d1·d3 의 **전치** 가이드는 이것과 다른 얘기다 — §3.2.

### 5.2 후처리로 단색 채우기 — 아웃라인 계약을 깬다

접지 위반을 **56 → 0** 으로 만들었지만 사용자가 화면에서 회귀를 보고해 **26종을
되돌렸다.** 게이트를 만족시키는 가장 싼 방법이 그림을 망치는 방법이다.

### 5.3 후처리로 확대하지 마라

접지 폭이 계약과 맞는 것이 24/75 뿐이고 나머지 51종은 **비정수 배율**이다. 렌더 계약이
정수 스캔라인·AA 금지 기반이라 비정수 리샘플은 도트 경계를 뭉갠다.

### 5.4 통과한 것을 덮어쓰지 마라

채택은 **통과했거나 엄격하게 나아졌을 때만**, **동점은 안 바꾼다.**
⚠ 4방향에서는 **장마다** 따로 판정한다 — d0 이 나아졌다고 d2 를 같이 채택하지 말 것.

### 5.5 **광원을 물체와 같이 돌리지 마라** ← 4방향의 새 함정

스타일 계약은 *"Single light from the upper left"* 다. **광원은 화면에 고정**이지 물체에
붙어 있지 않다 — 물체를 90° 돌려도 **화면 왼쪽 면이 밝아야 한다.** 즉 게이트 5 의 점수는
**네 방향 다 양수**여야 한다.

⚠ **이미 실측으로 깨졌다.** 앞서 뽑아 둔 4방향 표본
`assets/generated/sprites/facility-shop-d{0,1,2,3}/final-quantized.png`:

| 장 | 게이트 5 점수 | 판정 |
|---|---|---|
| d0 | **+57.5** | 좌상단 ✅ |
| d1 | **−43.2** | 뒤집힘 ❌ |
| d2 | **−16.3** | 뒤집힘 ❌ |
| d3 | **+16.3** | 좌상단 ✅ |

부호가 **d0/d1 과 d2/d3 에서 짝지어 갈린다.** 화소로도 그 관계가 보인다 —
`d1` 은 `flipX(d0)` 와 **75.7%**, `d3` 은 `flipX(d2)` 와 **56.7%** 가 같은 화소다
(무관한 짝 `d2` vs `flipX(d0)` 는 29.1%). 즉 **모양을 뒤집으면서 명암까지 같이 뒤집혔다.**

⚠ **그런데 이 넷은 flipX 로 만든 게 아니라 진짜로 생성된 것이다.** 네 런의
`prompts/alt.txt` 를 다 읽어 보면 방향 지시가 **`Character: facility/shop 방향 N.` 한 줄과
참조 그림뿐**이고 mirror·rear·rotate·lighting 문단이 **하나도 없다** (실측). 모델이
"반대쪽에서 본 그림"을 만들라는 지시를 반전으로 해석했고, 반전이면 광원도 따라 도는 것이
당연하다. **처방은 리롤이 아니라 §3.3 의 영어 문단을 프롬프트에 축자로 넣는 것**이다.

⚠ **스킬 문서가 틀렸다.** `.claude/skills/ppaji-pixel-asset/SKILL.md` 는 *"광원은 네 방향
모두 좌상단 유지(생성이 **지켜줌** — flipX 근사는 광원이 뒤집히는 결함이 있다)"* 라고
적어 두었다. **flipX 가 광원을 뒤집는다는 앞부분은 맞고, 생성이 지켜 준다는 뒷부분이
이 표본에서 성립하지 않는다.** 생성이 지켜 주지 않으므로 **게이트로 잰다.**
(그 문서는 이 작업의 금지 파일이라 여기 적어 둔다.)

### 5.6 결함이 있는 d0 에서 체인을 시작하지 마라

체인 참조는 d0 의 성질을 d1·d2 로, d2 의 성질을 d3 으로 나른다. 지금 표 §1 에서
접지가 빨간 4종과 광원이 뒤집힌 4종은 **d0 부터 고치고** 시작한다 — 안 그러면 결함
하나가 **네 장으로 복제**되고, 게이트 출력에서 원인이 한 장인지 네 장인지 안 보인다.
