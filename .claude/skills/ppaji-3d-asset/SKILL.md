# 빠지 타이쿤 3D 픽셀화 에셋

**목표는 하나: 무엇을 추가해도 `art-reference/quality-bar.png` 와 같은 화면으로 보인다.**
개별 에셋이 정교한 것보다 전체가 한 게임으로 읽히는 것이 우선이다.

2D 스프라이트 파이프라인(sprite-gen)은 별도다 → `ppaji-pixel-asset` 스킬.
이 스킬은 **3D 지오메트리를 코드로 짜서 픽셀화 렌더러에 태우는** 경로다.

## 왜 3D 인가 (되돌리지 말 것)

16방향·facing f0/f1·아틀라스 패킹·타일 이음새 QA 가 **구조적으로 소멸**한다 —
회전·크기·색 변형이 공짜다. 대신 시설 1종 = 스프라이트 1장이 아니라 **빌더 함수 1개**다.
근거·장부: `docs/design-v5-draft.md` §3D 트랙.

## 룩 파이프라인 — 손대지 말 것 (전부 실측으로 얻은 값)

렌더 경로: 씬 → 저해상 렌더타깃 → 깊이 외곽선 → **정렬 디더** → 팔레트 양자화 → NEAREST **정수배** 확대.

### ⚠ 도트감 = 정수 배율. 이게 1순위다

논리 해상도를 먼저 정하면 배율이 소수가 되고(논리 320 → 캔버스 393 = ×1.228),
논리픽셀 하나가 어떤 곳은 1px 어떤 곳은 2px 로 찍혀 **격자가 사라진다**.
실측: 216(×1.82)에서 320(×1.23)으로 올렸더니 "도트 느낌이 전혀 안 난다"는 판정을 받았다.
해상도를 올린 게 문제가 아니라 **배율이 더 나쁜 소수가 된 게** 문제였다.

순서를 뒤집는다 — **도트 크기를 먼저 고정하고 논리 해상도를 계산한다**:

```
논리폭 = ceil(CSS폭 / DOT)
캔버스 버퍼 = 논리폭 × DOT × DPR      CSS 크기 = 논리폭 × DOT
```

`DOT` = 논리픽셀 1개가 차지하는 CSS 픽셀 수. 이러면 논리픽셀이 **항상 정확히
DOT×DPR 개의 디바이스 픽셀**이 된다. 예외 없음. DPR 은 정수로 반올림한다(2.75 방지).

- `index.html` 의 캔버스 CSS 를 `width:100vw` 로 두지 마라 — 늘어나면서 정수 배율이 깨진다.
  크기는 `main.ts layout()` 이 px 로 직접 박는다.
- 화면보다 최대 DOT-1 px 넘칠 수 있는데 안 보인다 (`overflow:hidden`).

| 상수 | 값 | 위치 | 내리면/바꾸면 |
|---|---|---|---|
| 도트 크기 | **2 CSS px** (`DOT`) | `pixelate.ts` | `?dot=1~6` 로 실험. 393pt 폰에서 DOT 2 = 논리폭 197. 3 은 확실히 굵지만 창·문이 뭉개진다 |
| 논리 해상도 | **계산값** (`ceil(CSS폭/DOT)`) | `pixelate.ts logicalSize()` | 직접 고정하지 마라 — 소수 배율이 된다 |
| 디더 | **Bayer 4×4 정렬** ±5.5% | `pixelate.ts bayer4()` | 랜덤 해시로 바꾸지 마라. 잔디가 노이즈로 지글거린다 |
| 디테일 하한 | **2 논리픽셀** (`MIN_DETAIL`) | `detail.ts` | DOT 2 에서 ≈1.44 월드. 이보다 작은 건 디테일이 아니라 노이즈다 |
| 툰 램프 | **0.635**/0.808/0.949/1.0 | `main.ts GRADIENT` | 그림자 밴드 0.62 미만 → 폰툰 탁해지고 라임이 올리브로 죽는다 |
| 페이스 셰이딩 | 상면 1.14 · 어두운 면 **0.64 이상** | `shade.ts FACE_SHADE` | 툰 램프와 곱해지므로 0.66 쓰면 최종 0.42 가 되어 색이 죽는다 |
| 외곽선 | 실루엣(깊이 1차) + 크리즈(2차) | `pixelate.ts` | **작은 오브젝트에 전방향 외곽선 금지** — 손님(3px)이 통째로 먹혔다 |
| 채도 | +8%, 감마 0.97 | `pixelate.ts` | |

**색은 네 번 눌린다**: 재질 → 툰 램프 → 페이스 셰이드 → 양자화.
그래서 **팔레트에 밝은 끝 색이 없으면** 아무리 재질을 밝혀도 양자화가 어두운 이웃으로 도로 스냅한다.
새 색을 쓰려면 `palette.ts` 에 **밝은 톤까지 함께** 넣어라.

## 씬 구조 — 무대(디오라마) 모델 (2026-08-17 확정)

**기울어진 해안 실험(SHORE_SLOPE 1.5~1.8)은 폐기됐다. 되돌리지 말 것.**
격자·지형·검사 전부가 해안 거리 좌표계에 끌려 들어가며 복잡도가 폭발했고,
가로 화면에서 땅이 리본처럼 잘리는 사고까지 냈다. 레퍼런스의 실제 구조는
기울어진 세계가 아니라 **무대**다:

```
하늘 + 원경 산     ← 카메라 부착 배경막 (backdrop.ts)
숲 · 잔디 · 본관    ← 장식 밴드 (수평, z < Z0. 본관 = lodge-sprite 빌보드)
잔교 (LAND_ROWS 4줄) ← 육상 시설이 서는 물 위 나무 무대 (stage.ts, 상판 PIER_TOP)
폰툰 링            ← 수면 허가 구역 = 수상 플레이 영역 (permit.ts, 타일 사각형)
바깥 물            ← 계류 보트 장식 (marina.ts)
```

- 격자 32×24 (`simworld.ts`), 지형은 **행 번호**로 판정 (행 0..3 잔교 · 4 물가 · 5..9 얕음 · 10.. 깊음)
- 링은 얕은+깊은 물을 **둘 다 걸쳐야** 한다 — 깊은 물에만 두면 얕은 물 전용 시설이 못 들어간다
- **화면 x = (x+z)·cos45** — 장식을 뒤(z−)로 보내면 화면에선 왼쪽으로 밀린다. x 로 보상할 것
- waterfront 시설(선착장·슬라이드)은 잔교에 인접해야 놓인다
- 옛 장식 모듈(park·buildings·lodge-routes·lodge-b·앰비언트 makeGuests)은 삭제됨.
  손님 상수만 `guests.ts` 에 남아 있다 (course-view 탑승객용)

## 새 에셋 추가 절차

### 1. 시설이면 — 데이터 먼저 (sim 계약)

`../src/data/facilities.json` 에 항목을 넣는다. 이게 없으면 배치도 시뮬도 안 된다.

```jsonc
{
  "id": "cafe", "name": "카페", "layer": "land",   // land|waterfront|water|path|deco
  "size": [2, 3],                                   // 타일 발자국 (1타일 = 6 월드)
  "sprite": "facility/cafe",                        // 2D 트랙 호환용 ID (3D 는 안 씀)
  "cost": 1400000, "upkeep": 60000,
  "capacity": 6, "serviceTicks": 40, "fee": 9000,
  "thrill": 0, "satisfaction": 10, "staff": 1,
  "needs": ["thirst", "rest"],                      // 해소하는 욕구 (말풍선 색과 연결)
  "placement": { "terrain": ["plain", "sand"] },    // 지형 이름 (Terrain 키의 소문자)
  "desc": "한 줄 설명 — 정보 시트에 그대로 뜬다."
}
```

- **`layer: "path"` 는 특별하다** — 그 타일은 지형과 무관하게 **통행 가능**해진다(`navigation.ts`).
  길·데크가 이 값을 쓴다. 물 위로 뻗는 구조물은 전부 이 계약을 따른다.
- `placement.requiresLandAdjacent` 는 "육지 **또는 통행 구조물(길·데크)** 인접"으로 판정된다
  (`facility-store.ts touchesLand`). 이래야 데크가 데크에 붙어 연결식 확장이 성립한다.
- 데이터만 넣으면 팔레트에 자동으로 뜨지 않는다 → 3번의 카테고리에 ID 를 추가할 것.

### 1-b. ⚠ 파라메트릭보다 **스프라이트 빌보드**가 먼저다 (2026-08-17 판정)

본관 한 채를 네 방식(현행 3D · 부품 확장 3D · img2threejs · 픽셀 스프라이트)으로 만들어
비교한 결과 **스프라이트가 압도적**이었다. 지금 씬은 건물·손님·나무·계류보트가 전부
2D 픽셀 스프라이트이고, 지형·물·데크·항적만 3D 다. three.js 를 버린 게 아니다 —
진짜 갈림길은 "3D vs 2D" 가 아니라 **모델링 vs 미리 렌더**였다.

스프라이트는 `assets/generated/` 에 이미 123장 있다. **새로 뽑기 전에 거기부터 볼 것.**
로지컬 PNG 로 내보내는 법: `frames/alt/frame-0.png` 를 scale(보통 8)로 NEAREST 축소 후
`getbbox()` 크롭. `final-quantized-39.png` 는 쓰지 마라 (아래 함정표).

#### 크기 계약 — 1 텍셀 = 타일의 1/16

```ts
export const TEXEL_WORLD = TILE / 16;   // sprite-facility.ts
```

기존 스프라이트가 전부 2D 트랙의 16px 타일 격자로 그려졌으므로 **화면이 아니라 타일에
묶는다.** 화면 기준(`WORLD_PER_PX`)으로 잡으면 에셋마다 배율이 달라진다 —
본관만 1.9배 커져 한 세트로 안 보였다 (실측).

#### 빌보드 3계약

| 계약 | 이유 |
|---|---|
| `quad.quaternion.copy(camera.quaternion)` | Y만 돌린 쿼드는 피치 있는 카메라에 비스듬해 **그림이 찌그러진다**. 스프라이트는 이미 3/4 투영이라 3D 로 다시 눕히면 이중 투영 |
| `transparent: false` + `alphaTest: 0.5` | 이래야 깊이 실루엣 외곽선이 쿼드 사각형이 아니라 **스프라이트 알파 모양**을 딴다 |
| `SRGBColorSpace` + `NearestFilter` | 안 주면 씻겨 나가고 뭉갠다 |

여러 칸을 쓰는 아틀라스는 `sprite-instances.ts` 의 `makeSpriteInstances()` 로
**인스턴스별 UV 사각형**을 준다 (손님 120칸·나무 3칸·계류보트 4칸이 각각 메시 한 벌).

### 2. 빌더 함수 — `prototype-3d/src/sim-view.ts` 의 `buildFacility`

스프라이트가 있으면 빌보드, 없으면 파라메트릭으로 자동 분기한다
(`makeFacilitySprite(defId, camera) ?? buildFacility(...)`). 아래는 **스프라이트가 없는
지면 구조물**(게이트·선착장·길·데크)을 만들 때의 규칙이다.

**먼저 `detail.ts` 의 공용 부품을 본다. 새로 그리기 전에 조합부터.**

레퍼런스가 통일감 있어 보이는 이유는 손맛이 아니라 **같은 모티프의 반복**이다 —
같은 창, 같은 난간, 같은 기와줄이 건물마다 되풀이된다. 그래서 에셋별로 루프를 돌리지
말고 **부품 단위로 루프를 돌려라**. 부품 하나를 고치면 전 건물이 같이 좋아진다.

| 부품 | 쓰는 곳 |
|---|---|
| `plinth(W, D)` | 모든 건물 밑. 3/4 부감에서 건물이 잔디에 떠 보이는 걸 이거 하나가 잡는다 |
| `cornice(W, D)` | 벽↔지붕 경계 띠. "지어진" 느낌의 최소 단위 |
| `gableRoofDetail(rw, rh, rd, color)` | 용마루 + 처마 + 경사면 기와줄. **지붕 프리즘과 같은 인자**를 줘야 한다 |
| `windowRow(w, h, n, lit)` | 유리 + 멀리언 + 창턱. 벽 하나에 한 줄이면 "건물"로 읽힌다 |
| `door(w, h, color)` / `railing(len, axis, h)` / `steps(w, n)` | 출입·테라스 |
| `planter(seed)` / `awning(w, d)` / `signboard(w, color)` / `roofProp(kind)` | 정체성·색 악센트 |

`hut(roof, wallH)` 이 **기단·벽·코니스·박공지붕·지붕디테일까지 다 붙인다**.
개별 `case` 는 그 위에 그 시설만의 정체성(창·문·차양·간판)만 얹는다.
모든 부품은 내부에서 `atLeast()` 로 `MIN_DETAIL` 을 강제하므로 크기를 작게 줘도 안전하다.

```ts
case 'cafe': {
  hut('#4a90b8');                                    // 벽+박공지붕 헬퍼 (W·D 는 발자국에서 계산됨)
  const window = shadedBox(W * 0.5, 3, 0.6, '#38628d');
  window.position.set(0, 3.4, D * 0.5);
  g.add(window);
  break;
}
```

규칙:
- **`shadedBox(w, h, d, color)` 를 써라** (`shade.ts`). 맨 `THREE.Mesh + BoxGeometry` 는
  페이스 셰이딩이 없어 옆 건물과 입체감이 다르게 보인다.
- 크기는 `W = w * TILE * 0.86`, `D = h * TILE * 0.86` 에서 파생 — 하드코딩 금지.
  발자국이 바뀌면 메시도 따라가야 한다.
- 색은 `palette.ts` 에 있는 값 또는 그 계열. 새 색은 밝은 톤과 함께 추가.
- **1논리픽셀(≈0.65 월드)보다 작은 디테일은 노이즈다.** 문고리·나사는 그리지 마라.
- 재질은 `MeshLambertMaterial` 로 만든다 — `applyToon()` 이 툰으로 바꿔준다.
  런타임에 씬에 붙는 오브젝트는 **반드시 `applyToon(mesh)` 를 호출**할 것.

### 3. 팔레트 등록 — `prototype-3d/src/hud.ts`

`ICONS` 에 이모지, `CATS` 의 알맞은 카테고리 `ids` 에 ID 를 넣는다.
카테고리는 육상 / 동선 / 수상 셋이고 **각 5개 이하**로 유지한다 —
가로 스크롤은 폰에서 안 잡혀서 탭으로 나눈 구조다. 넘치면 카테고리를 늘려라.

### 3-b. 견인 장비(코스)를 추가하려면 — **시설과 다른 시스템이다**

코스는 발자국이 아니라 **경로 + 차량**이고, 손님은 `using` 이 아니라 `riding` 상태가 된다.
필요한 것 2개뿐이며 팔레트의 `🚤 코스` 카테고리에는 **자동으로 뜬다**(EQUIPMENT_DEFS 를 읽는다).

1. `../src/data/equipment.json` 에 항목:

```jsonc
{
  "id": "peanut", "name": "땅콩튜브", "sprite": "vehicle/peanut",
  "speed": 0.26,            // 타일/tick — 주행 시간 = 코스 길이 ÷ speed
  "capacity": 3,            // 한 번에 태우는 수 (처리량의 절반을 결정)
  "boardTicks": 40,         // 승선 대기. 만석이면 즉시 출발, 빈 배로는 안 나간다
  "minDepth": 1,            // 이 수심 미만은 코스가 못 지나간다
  "fee": 15000, "vehicleCost": 900000, "upkeep": 30000,
  "thrillBase": 30, "safeCurvature": 0.24,
  "minPoints": 3, "maxPoints": 6,   // 드래그 궤적이 이 개수로 줄어든다
  "desc": "한 줄 설명"
}
```

2. `prototype-3d/src/course-view.ts` 의 `buildVehicle` 에 `case 'peanut':` 추가.
   보트는 **+X 를 진행 방향**으로 만든다 (뷰가 `yaw = -heading` 으로 돌린다).

**설계 손잡이**: 처리량 = `정원 × (주행시간 + 승하선)⁻¹ × 차량 수`.
코스를 길게 뽑으면 스릴·만족은 오르고 회전율은 떨어진다 — 대기줄로 즉시 드러난다.
실측: 같은 코스에서 차량 1→3대에 누적 탑승 7→47, 대기 19→10.

| 색이 두 번 튐 (크림 벽 → 갈색) | `final-quantized-39.png` 를 썼다 | 씬에서 106색으로 **한 번 더** 스냅된다. 3D 트랙엔 **양자화 전 로지컬 PNG** |

| 계류 보트가 주황 덩어리로 보임 | `hexa`·`twinpang`·`wagon` 은 6인승 대형 튜브 | 계류장엔 **소형 선박만** (jetski·banana·waterski·peanut) |

| 잔디에 회색 얼룩·검은 줄이 번짐 | 흰 기반 결 텍스처(×0.82 급)가 초록과 곱해져 **채도 빠진 색** → 양자화가 회색 계열로 스냅 | 곱하기 결의 진폭은 **×0.94 이내** (같은 색 버킷에 머물게). 원인 못 찾으면 **오브젝트 그룹을 하나씩 꺼서 이분 탐색** (bisect 스크린샷 — 나무/언덕/simView) |

| 겹친 손님이 갈색 덩어리로 뭉갬 | 픽셀화 외곽선은 **깊이 불연속**에만 그려진다 — 대기줄은 앞뒤 깊이차가 없어 선이 안 생긴다 | 스프라이트에 **1px 윤곽을 구워** 넣는다 (`bakeOutline`). 셀 경계를 넘기지 말 것 |
| 뒤통수가 갈색 슬랩 | 머리칼을 통짜로 칠했다 | 정수리 하이라이트 + 목덜미 1px 로 쪼갠다 |
| 재질 검사가 갑자기 실패 | `toon > 0` 은 파라메트릭 전용 가정 | 빌보드 씬에선 **모든 재질이 허용 종류인가 + 빌보드 3계약**을 본다 (skillcheck 갱신됨) |
| 배경과 땅 경계가 칼로 자른 실루엣 + 이중 하늘 띠 | **화면 부착(수평) 배경막**은 월드 대각(30°) 땅끝과 구조적으로 못 만난다 | 배경을 **월드 지오메트리로**: 땅끝 → 뒷강 띠 → 건너편 벽(수직 빌보드, farbank.ts). 같은 아이소 기하라 경계가 이어지고 시차는 깊이에서 공짜로 나온다 |
