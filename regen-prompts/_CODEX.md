빠지 타이쿤 저장소에서 **시설 스프라이트 28종을 재생성**해 줘.
접지 기하 게이트가 빨간불인 것들이고, 그림을 다시 뽑는 것 말고는 고칠 방법이 없다.

## 먼저 읽을 것

`docs/asset-regen-order.md` — 대상 표(§1) · 방법(§2) · 판정(§3) · **하면 안 되는 것(§4)** ·
왜 이 상태인지(§5). §4 를 안 읽으면 이미 한 번 실패한 길을 그대로 반복하게 된다.

## 하는 법

```bash
npx tsx tools/regen-facility.ts --severe --tries 3    # 심각 4종 먼저
npx tsx tools/regen-facility.ts --all --tries 3       # 잘 되면 28종 전부
```

이 도구가 프롬프트 조립 → 가이드 첨부 → 생성 → 후처리 → 게이트 판정 → 실패면 **직전 실측을
프롬프트에 넣어 리롤**까지 한다. 새로 만들지 말고 이걸 써.
`--dry-run --print` 로 프롬프트만 볼 수 있고, 도구가 못 도는 환경이면 `regen-prompts/<id>.txt`
를 손으로 붙여넣어도 된다 (그 파일 3번째 줄이 첨부할 이미지 3장, `────` 사이가 프롬프트).

## ⚠ 하면 안 되는 것 — 넷 다 실측으로 닫았다

1. **가이드를 뒤집지 마라.** `art-reference/guides/kairo/facility__<id>.png` 는 엔진 정본
   마스크에서 파생돼 **구조적으로 옳다**. 축뒤집힘 그림은 가이드를 그대로 붙이고
   **프롬프트로 "지난번엔 두 축이 바뀌었다"를 지목**해서 고친다.
   근거: 좌우 반전을 75종에 다 적용해 재봤더니 **통과 0종**이었다.

2. **후처리로 접지 다이아몬드를 색으로 채우지 마라.** 게이트는 실루엣 최하단 윤곽만 보므로
   "다이아몬드를 칠하기"가 언제나 최단 경로다. 그런데 그 판은 **아웃라인 계약을 깨고**
   화면에서 **"물체가 가라앉아 보인다"** 를 만든다. 실제로 그렇게 위반 0 을 만들었다가
   사용자 보고로 **26종을 되돌렸다** (`tools/repair-kairo-footprint.py` 머리말 참조).
   부속(다리·기둥·바퀴·개찰구)이 잘리는 사고도 3종에서 났다.

3. **후처리로 확대·전단·리샘플하지 마라.** 접지 폭을 계약에 맞추려면 **51종이 비정수
   배율**(1.2~1.6×)이 필요하고, 이 프로젝트는 **정수 스캔라인·AA 금지**가 렌더 계약의
   기반이다. 각도를 고치려다 화면 밀도를 잃는다.

4. **통과 47종과 지면 33장을 건드리지 마라.** 목록은 `docs/asset-regen-order.md` §1 끝에 있다.

즉 **고치는 방법은 "다시 뽑기" 하나**다. 후처리 도구를 새로 만들지 마라.

## 판정 — 게이트만 믿지 마라

```bash
npx tsx tools/kairo-gate.ts --geom       # 접지 기하 (지금 위반 28 · 심각 4)
npm run bake:atlas                        # 통과분 반입 후
npm run verify:kairo                      # 화면 305/305 (dev 서버 필요)
npx vitest run && npx tsc --noEmit && npm run lint
```

⚠ **게이트는 접지 기하만 본다.** 위반이 줄었어도 아래 셋을 같이 재서 보고해:
- **팔레트 밖 색** — 시설 75종에서 0 이어야 한다 (39색 고정, `art-reference/palette-proposed-39.json`)
- **도트 경계율** — 지금 시설 평균 약 51.8%. 크게 떨어지면 뭉갠 것이다
- **눈으로** — 전/후 확대 이미지를 만들어 다리·기둥·아웃라인이 살아 있는지 봐라.
  숫자만 보고 "완료"라고 하지 마라. 지난번 회귀가 정확히 그렇게 통과했다
