## 확인한 낭비 후보

- 메인 누적 처리량이 제작자보다 크다. 오래된 대화 문맥을 유지하며 원화 확인, 스킬 읽기, 비교 웹페이지 제작과 브라우저 QA, 기록을 수행했다. 역할별 집계이며 각 작업의 정확한 토큰 기여도 분해는 아니다.
- 제작자는 build.py 약8.4KB 외에도 qa.py 약7.5KB, render_saved.py 약2.3KB와 투영 검사 스크립트를 새로 작성했다. 반복 검증을 코드로 재사용할 여지가 있다. 바이트 수를 토큰 수로 환산하지 않는다.
- 메인은 매표소 HTML을 읽고 다시 편집하고, 보고/인수인계를 반복 작성했다. 기존 페이지를 데이터 기반으로 만들면 출력과 왕복을 줄일 수 있다.
- 캐시는 이미 높다. 캐시만 개선하는 것보다 읽을 자료, 출력량, 모델 왕복 수를 줄이는 편이 우선이다.
- 이번 시험의 Blender 렌더는 로컬 작업이며 ImageGen/provider 호출0회다. 이미지 검토 입력과 이를 제어하는 모델 요청은 토큰을 사용한다.

## 권장 개선 순서

1. 공통 실행 도구: 카메라 설정/4방향 렌더/저장본 재열기/픽셀 비교/알파·수량·치수 체크/검토 페이지 생성을 재사용 가능한 명령으로 묶는다. 시설별 모델링과 재질 선택은 유지한다. 자동 검증은 축소하지 않고 JSON 요약과 실패 항목만 모델에 돌려준다.
2. 짧은 제작 진입 문서: authored 시설에 필요한 핵심 계약과 선택할 상세 참조만 읽게 한다. 카메라/수치 계약은 기계가 읽는 설정으로 제공한다. 관련 없는 NPC/provider/과거 작업 기록을 매번 읽지 않는다.
3. 일상 제작과 스킬 시험 구분: 일상에는 제작자1명+고정 검증 도구를 기본으로 하고, 독립 블랙박스는 스킬 변경 또는 새 재질 계열의 대표시설에서 수행한다. 사용자 요청 시에는 항상 수행한다. 기존 그림을 정답으로 전달해 독립성을 훼손하지 않는다.
4. 모델에 보여주는 그림은 d0 원화 비교와 네 방향 요약 중심. 필요하면 상세 확대한다. 작은 세부 판정에 필요한 해상도까지 줄이지 않는다.
5. 모델 변경은 위 구조 개선 후 별도 비교한다. 가벼운 모델로 정형 문서·집계를 처리하는 후보는 있지만 미술 판단 품질을 확인하기 전 자동 전환하지 않는다.
