## 0. 요약 — 한 문장

지금 게임은 **화면이 14개인데 길이 2개**다. 하단 `메뉴` 하나가 경영·목표·의뢰·소원·인증·설정·새 게임을
**393px 폭 · 361px 높이 창에 쌓인 1,893px 스크롤 한 장**으로 떠안고 있고, 그 안에서 위계는 색과 글자
크기로만 표현된다. 해법은 새 시스템을 더하는 것이 아니라 **그 한 장을 라우터 + 5개 하위 화면으로 쪼개고,
어떤 순간에도 화면 주인이 정확히 하나가 되도록 표면 소유권을 확장하는 것**이다.
시뮬·저장·게임플레이 계약은 **전혀 건드리지 않는다** (세이브 v8 유지, 경력 v2 유지, 온보딩 snapshot v2 유지).

## 1. 실측 — 지금 화면이 실제로 무엇인가

측정은 전부 실제 브라우저에서 했다. 재현 방법은 §14 부록 A.

### 1.1 메뉴 시트가 화면의 전부를 떠안고 있다 ★ 최대 문제

| 항목 | 세로 393×852 | 가로 852×393 |
|---|---|---|
| `.ksheet` 높이 | **420px** (뷰포트의 49%) | **220px** (56%) |
| `.ksheet-body` 보이는 높이 | **361px** | **161px** |
| `scrollHeight` | **1,893px** | **1,893px** |
| 필요한 스크롤 | **5.2 화면** | **11.8 화면** |

그 1,893px 안의 실제 배치 (`offsetTop`, 세로 기준):

| 구간 | top | 높이 |
|---|---|---|
| 판 설정 줄 (`북한강형 · 물려받은 빠지`) | 0 | ~30 |
| `Today` 추천 | 514 | 117 |
| 보조 경고 | ~640 | ~24 |
| `운영` (가격·직원·코스) | 664 | 138 |
| `성장` (목표 절 + 심사·단골·의뢰·도감) | 808 | 286 |
| `기록` (결산·감상·인증·엔딩) | 1,100 | 138 |
| **`설정` (배속 · 새 게임 시작)** | **1,244** | 188 |
| 의뢰 목록 (`#kairo-quests-list`) | 1,468 | — |
| 인증 목록 (`#kairo-cert-list`) | **1,791** | — |

- 버튼 수: `.kmanage-action` **16개** + 의뢰/소원/인증 행 **18개** = 한 창에 **34개 항목**.
- `새 게임 시작`은 전체 스크롤의 **66% 지점**에 있고, 그 **아래로 649px가 더 있다.**
  "설정이 맨 아래"라는 기대와 어긋나 실제로 못 찾는다 (캡처 `ia-13-settings.png` — 바닥까지
  스크롤하면 설정이 아니라 **인증 12행**이 나온다).
- 가로에서는 161px 창에 `Today` 카드(117px) 하나가 첫 폴드를 다 먹는다 (`ia-21-menu-land.png`).
  852px 폭을 한 열로만 쓴다.

**진단:** `메뉴`는 화면이 아니라 **미분류 수납장**이다. 성격이 다른 넷(추천 · 경영 행동 격자 ·
진행 목록 · 파괴적 설정)이 위계 없이 한 스크롤에 직렬로 붙어 있다.

### 1.2 만든 화면이 DOM에 도달하지 않는다 ★ 조용한 회귀

`src/main.ts`가 메뉴용 버튼 넷을 만들어 `hud.menuSlot`에 붙인다:

- `examBtn` (`kitem wide span`, 2645~2700행) · `catalogBtn` (2895) · `showcaseBtn` (2902) · `staffBtn` (2964)

그런데 `new KairoManagementMenu(hud.menuSlot, …)` (3067행)의 생성자가 **`host.replaceChildren()`**
를 호출한다. 실측: 메뉴를 연 상태에서 `#kairo-sheet .kitem.wide` 개수 = **0**. 넷 다 detach다.

결과 두 가지:

1. **K48이 만든 심사 상태 줄이 화면에서 사라졌다.** `paintExamItem(examBtn, examItemView(...))`은
   "지금 몇 점 / 무엇이 모자란지"를 쓰는데, 그 노드가 DOM 밖이라 아무도 못 본다. 실제로 화면에 뜨는
   `#kairo-exam-open`은 경영 메뉴가 다시 만든 버튼이고 부제는 **`현재 1등급`** 이라는 정적 문자열뿐이다
   (`ia-02-menu.png` 아래쪽, probe 실측 `"심사현재 1등급"`).
   K48 주석이 "자격이 없을수록 더 보여야 한다"고 못 박은 규칙이 **구현은 남고 표시만 죽은** 상태다.
2. `refreshExamBtn`이 1.5초 폴링마다 detach된 노드에 대고 `examGate()`를 평가한다 — 낭비.

`main.ts`에 이미 "여기 있던 레거시 `코스` 버튼을 걷어냈다"는 주석이 있다 (2903~2912행).
**같은 종류의 잔해가 넷 더 남아 있다.**

### 1.3 표면 이름이 세 벌이다

같은 장소를 부르는 이름이 화면마다 다르다.

| 실제 화면 | 메뉴 버튼 이름 | 그룹 이름 | 시트 제목 |
|---|---|---|---|
| 요금 슬라이더 | `가격` | `운영` | **`경영`** |
| 직원 고용 | `직원` | `운영` | **`경영`** |
| 시설 개선 | *(메뉴에 없음)* | — | `경영` 안의 `개선` 탭 |

`경영`이라는 단어가 (a) 하단 `메뉴` 시트 전체의 별칭, (b) `가격/직원/개선` 시트의 제목,
(c) 문서상 `S8 경영` 세 곳에서 서로 다른 것을 가리킨다. `개선` 탭은 **메뉴 어디에서도 진입점이 없다**
(시설 정보 시트나 `가격`/`직원`을 연 뒤 탭으로만 도달).

### 1.4 결산이 헤더와 겹치고, 닫기가 화면 밖이다

`#kairo-report` = `.kover.scrim`, 실측:

- 배경 `rgba(250, 240, 219, 0.95)` — 거의 불투명한 크림.
- 그런데 `#kairo-top`(헤더)이 **여전히 표시 중**이고 rect가 겹친다:
  제목 `[14, 14, 365×28]` vs 헤더 `[8, 6, 307×78]` → **겹침 true**.
  캡처(`ia-07-report.png`)에서 `1주차 결산` 글자 뒤로 `여름 · 09:00 ◎ 628만`이 비쳐 읽힌다.
- `scrollHeight` **1,223px** / 뷰포트 852px, `#kairo-report-close`의 top = **1,161px**.
  → **닫기 버튼이 첫 화면에서 371px 아래.** 결산을 닫으려면 반드시 스크롤해야 한다.
  결산에는 다른 종료 경로가 없다 (스크림 탭 없음, 상단 X 없음).

이 둘은 UI v3 계획의 "viewport 밖에 반쯤 보이는 버튼 0" 규칙과 정면으로 어긋나는데,
그 계획의 게이트가 **메뉴 시트만** 검사해서 안 걸렸다.

### 1.5 티커가 존재하지 않는 UI를 가리킨다

`src/ui/kairo-ticker.ts:56`

```ts
export function tickerFallbackText(action: string): string {
  return `다음: ${action} — 목표 A를 탭하세요`;
}
```

UI v3가 홈의 A/B/C 세 칸을 **현재 행동 한 줄**로 바꿨다 (`kairo-hud.ts` `homeGoalChips`/`currentActionView`).
화면에는 `A`라는 글자가 **어디에도 없다.** 실기 캡처(`ia-01-home.png`) 하단:

- 밴드: `다음 할 일 / 물려받은 코스 시험 운행 / 물려받은 코스를 열어 보세요 〉`
- 티커: `📰 다음: 물려받은 코스 시험 운행 — 목표 A를 탭하세요`

**같은 문장이 두 줄에 걸쳐 두 번**, 그중 하나는 없는 UI를 지목한다.
CLAUDE.md의 채널 계약("한 사건을 두 채널에 넣지 말 것")을 홈이 스스로 어기고 있다.

### 1.6 알림함 진입이 보이지 않는다

`.kticker`는 26px 띠 + 중앙에만 44×44 투명 `role="button"`(`.kticker-hit`)이다. 띠 위 어디를 눌러도
열리는 게 아니라 **가운데 44px만** 열리며, 그 사실을 말하는 시각 신호가 없다 (`📰` 아이콘은 좌측 고정이고
hit은 중앙). 실측으로 `#kairo-ticker`를 프로그램적으로 클릭했을 때 알림함이 안 열렸다(`ia-15-inbox.png`가
홈 그대로다) — 사람 손가락은 우연히 맞출 뿐이다.
겸해서 CLAUDE.md 「다음 할 일」 15번이 적어 둔 "아이콘 둘" 문제도 그대로다.

UI v3 §1.3이 "12px 미만 금지"를 세웠지만 적용은 **메뉴에만** 됐다. `src/ui/style.css` 전체:

### 1.8 나머지 실측 결함 (작지만 실재)

- **코스 독 제목 잘림** — `ia-05-course.png`: `안분 · 딸콤톱보 1대`가 세로로 절반 잘려 렌더된다.
  독은 `지표 1행 + 버튼 1행 ≤112px` 계약인데 제목 줄 높이가 예산에 안 잡혀 있다.
- **건설 시트의 `닫기`가 탭 줄 안에 있다** — `시설 | 건물 | 바닥 | 코스 | 닫기` 다섯이 한 줄이라
  `닫기`가 다섯 번째 탭으로 읽힌다 (`ia-04-build.png`).
- **`코스` 탭은 탭이 아니다** — 누르면 목록을 바꾸는 게 아니라 시트를 닫고 다른 화면으로 텔레포트한다
  (`kairo-hud.ts` `renderBuild`). 탭 문법과 동작이 다르다.
- **`Today`가 영문**이다 — 전면 한국어 UI에서 유일한 영어 헤딩 (`kairo-management.ts`).
- **`새 판` vs `새 게임 시작`** — 메뉴 버튼은 `새 게임 시작`, 열리는 화면 제목은 `새 판`
  (`ia-14-newgame.png`). 파괴 확인은 브라우저 `window.confirm`이라 게임 밖 표면이다.
- **첫 화면이 빈 잔디다** — 새 판 부팅 시 카메라가 물려받은 빠지를 안 잡는다. 시작 시설 7채 중
  화면에 보이는 것은 잔교 하나뿐이고 나머지는 화면 밖이다 (`ia-01-home.png`). 헤더는 `😊 0% · 👥 0명`.
  "물려받은 작은 빠지를 5분 안에 만난다"(design.md §1)가 첫 화면에서 시각적으로 성립하지 않는다.
- **결산 히트맵이 비어 있다** — 132px 박스의 95%가 빈 크림이다 (`ia-07-report.png`).
- **요일 막대의 라벨 형식이 섞여 있다** — `2`, `13/13`, `4/13`, `0/13`, `13`, `11/21`, `0/21`.
- **시설 정보를 열어도 카메라가 대상을 안 잡는다** — `ia-06-facility.png`에서 탭한 매표소가 화면 밖이다.
  이 시트가 전면(`.kover`)이 아니라 시트인 이유가 "탭한 시설이 어디 있는지 보여야 한다"인데
  (`kairo-facility.ts` 머리말) 그 이유가 성립하지 않는 경로가 있다.
- **`.kover.dialog` 스크림은 실제로 있다** — 카드 배경 `rgba(48,30,10,0.55)` 실측. (문제 아님, 기록용)

### 1.9 [v3 해결] 다시 계획하지 않는 것

UI v3 워킹트리 diff가 이미 고쳤고 실측으로 확인했다 — 이 문서는 손대지 않는다.

- 메뉴 버튼의 실제 터치 소유권 (`homeInputOwnership`가 목표·티커·바를 함께 내린다).
- 메뉴 9~10px 글자 (`.kmanage-*`는 12/13/15px, probe 실측 폰트 분포 `15px×15, 13px×22, 12px×45`).
- 1회 설치 기본 (`BuildSession`, `repeat` 기본 false).
- 코스 `applied` 영수증과 `변경 없음` 잠금 (`courseDockActions`).
- 홈 B/C 아이콘-only 문제 (메뉴 `성장 › 목표` 절로 이동).

## 2. 진단 — 구조적 원인 6개

1. **라우터가 없다.** `메뉴`가 인덱스이면서 동시에 목적지다. 하위 화면이라는 개념 자체가 없어서
   새 기능은 언제나 "같은 스크롤에 한 절 더"로 착지한다 (인증 12행이 그렇게 들어왔다 — P3-E 주석이
   "새 패널도 새 상시 컨트롤도 만들지 않았다"고 스스로 밝힌다).
2. **표면 소유권이 홈에만 있다.** `InputSurface`는 홈의 세 요소(목표·티커·바)만 내린다.
   전면 패널(`.kover`)이 헤더를 안 내려서 §1.4의 겹침이 난다.
3. **화면과 이름이 1:1이 아니다.** `경영`이 셋을 가리키고(§1.3), `코스`가 탭이면서 이동이고(§1.8),
   `새 판`/`새 게임 시작`이 둘이다.
4. **조립 순서가 계약이다.** `menuSlot`에 붙이고 나서 `replaceChildren`으로 지우는 구조라
   (§1.2) 새 항목이 조용히 사라져도 아무 게이트가 못 잡는다.
5. **문구 정본이 흩어져 있다.** 티커 fallback(§1.5), 심사 detail(§1.2), 새 게임 제목(§1.8)이
   각자 자기 문장을 갖는다 — 한 곳을 고쳐도 다른 곳이 옛말을 한다.
6. **타이포 규격이 화면 단위로만 적용됐다.** 규칙은 전역인데 검사가 메뉴만 본다(§1.7).

## 3. 새 IA의 원칙 (설계 판단의 근거)

**P1 — 깊이는 최대 3이다.** `홈 → 허브 → 상세`. 4단계가 필요하면 그 상세는 잘못된 자리에 있다.

**P2 — 한 화면은 한 질문에 답한다.** `Today`는 "지금 뭐하지", `성장`은 "무엇이 다음 목표인가",
`기록`은 "지난주에 무슨 일이 있었나", `설정`은 "판을 어떻게 다루나". 한 화면에 두 질문이 있으면 쪼갠다.

**P3 — 목적지는 이름으로 예고한다.** 버튼 라벨이 열릴 화면의 제목과 **같아야** 한다.
`가격`을 눌렀는데 `경영`이 열리면 안 된다 (§1.3).

**P4 — 화면 주인은 언제나 정확히 하나다.** `InputSurface`를 홈 3요소에서 **헤더까지** 확장하고,
전면 표면은 자기 상태줄을 갖는다.

**P5 — 진행 목록은 화면이지 부록이 아니다.** 의뢰 16 · 소원 8 · 인증 12는 게임의 중기/장기 목표
전체다. 메뉴 스크롤 꼬리가 아니라 `성장` 아래 자기 화면을 갖는다.

**P6 — 새 상태를 만들지 않는다.** 모든 화면은 기존 sim 상태에서 파생한다. 세이브 스키마 변경 0.

## 4. 화면 지도 (navigation hierarchy)

```text
L0  홈 (지도 · 흐르는 낮)
    ├ 헤더 2줄            읽기 전용 · 버튼 0
    ├ 다음 할 일 밴드      role=button 1  ────────────► 온보딩/추천의 목적지 (동적)
    ├ 소식 띠              role=button 1  ────────────► L1 소식
    └ 하단 바              button 2 (메뉴 · 건설)
        │
        ├─ L1 [메뉴]  ── 시트 · 인덱스 화면 ─────────────────────────┐
        │     · 오늘 할 일 (1)                                      │
        │     · 보조 경고 (0~N, 읽기)                                │
        │     · 운영    〉  ──► L2 운영                              │
        │     · 성장    〉  ──► L2 성장                              │
        │     · 기록    〉  ──► L2 기록                              │
        │     · 설정    〉  ──► L2 설정                              │
        │                                                          │
        │     L2 운영    가격 / 직원 / 시설 개선 / 코스              │
        │       └ 가격·직원·개선 ──► L3 `.ksheet` (기존 kairo-staff) │
        │       └ 코스           ──► L3 코스 화면 (기존 kairo-course)│
        │     L2 성장    목표(B·C) / 의뢰 / 소원 / 인증 / 심사 / 단골 / 도감
        │       └ 각각 ──► L3 목록·상세                              │
        │     L2 기록    지난 결산 / 리조트 보기 / 엔딩 이정표        │
        │     L2 설정    진행(배속) / 소리 / 저장 및 새 게임          │
        │       └ 새 게임 ──► L3 새 게임 (파괴 확인 2단)             │
        └─ L1 [건설]  ── 시트 · 탭 4 ──────────────────────────────┘
              시설 / 건물 / 바닥 / 코스
              └ 카드 선택 ──► **배치 모드** (시트 없음 · 확정 바 소유)

  독립 표면 (L0에서 직접, 메뉴 경유 아님)
    · 지도 탭(붓 없음)   ──► 시설 정보 시트
    · 주 경계 자동       ──► 주간 결산 (전면) ──► 주간 카드 (모달)
    · 사건 발생          ──► 축하 모달 (해금·승급·엔딩) / 티커 / 토스트
```

### 4.1 무엇이 어디로 옮겨 가는가 (현재 → 제안)

| 현재 위치 | 제안 위치 | 왜 |
|---|---|---|
| 메뉴 스크롤의 `운영/성장/기록` 격자 16개 | **L1 인덱스의 4행 + L2 4화면** | 34항목 한 스크롤 → 4항목 첫 폴드 (§1.1) |
| 메뉴 꼬리의 의뢰 6행 | **L2 성장 › 의뢰** (전량 16, 필터 `진행/완료`) | 6개 잘림이 P3-C③에서 이미 지적됐다 |
| 메뉴 꼬리의 소원 N행 | **L2 성장 › 소원** | 인물 8명이 이름으로 읽혀야 한다 |
| 메뉴 꼬리의 인증 12행 | **L2 성장 › 인증** | 1,791px 지점 → 자기 화면 |
| 메뉴 중간의 `설정` 188px | **L2 설정** (L1 인덱스의 마지막 행) | 66% 지점 → 예측 가능한 자리 (§1.1) |
| `기록 › 인증`(scrollIntoView) | **성장 › 인증**으로 통합 | 인증은 "딴 것"이 아니라 "따는 중"인 목표다 |
| 건설 시트의 `코스` 탭(텔레포트) | **건설 › 코스 탭 = 코스 목록 화면** | 탭 문법 보존 (§1.8) |
| 시설 개선(진입점 없음) | **L2 운영 › 시설 개선** | 화면이 있는데 문이 없었다 (§1.3) |
| 티커 fallback = A 목표 복창 | **삭제.** 뉴스 없으면 `📰 소식 없음 · 탭하면 알림함` | 채널 중복 제거 (§1.5) |
| 결산의 유일한 닫기(하단) | **머리 고정 `닫기` + 하단 `닫기`** | 스크롤 없이 나갈 수 있어야 한다 (§1.4) |

### 4.2 L1 메뉴 인덱스 — 첫 폴드 예산

세로 361px 안에 다음이 **전부** 들어간다 (계산은 현행 CSS 값 기준):

| 요소 | 높이 |
|---|---|
| 판 설정 줄 (`북한강형 · 물려받은 빠지`) | 26 |
| 오늘 할 일 카드 | 96 (현행 117에서 kicker/label/detail 3줄 유지, 패딩 −21) |
| 보조 경고 (있을 때만, 최대 2줄) | 0~44 |
| `운영` 행 | 56 |
| `성장` 행 | 56 |
| `기록` 행 | 56 |
| `설정` 행 | 56 |
| **합계 (경고 0)** | **402** |

402 > 361이므로 **경고가 없을 때도 마지막 행이 살짝 잘린다.** 두 가지 중 하나를 고른다:

- **(A) 시트 높이 420 → 480px** (세로 56%). 하단 바를 시트가 대체하므로 홈 예산과 무관하다.
- **(B) 오늘 할 일 카드를 2줄(76px)로 줄이고 행을 48px로.** 합계 350px, 현행 420px 유지.

**권고: (A)+(B) 절충 — 시트 456px, 카드 96px, 행 52px → 합계 386px, 경고 1줄까지 첫 폴드.**
가로(852×393)에서는 인덱스 4행을 **2열**로 두어 161px 창에 오늘 할 일 + 4행이 다 들어간다.
같은 DOM·같은 CSS로 낸다 (`grid-template-columns` 하나가 방향에 따라 갈리는 것은 미디어 쿼리
두 벌이 아니라 `auto-fit`으로 낸다 — CLAUDE.md "방향은 한 레이아웃으로").

## 5. 화면 소유권 계약 (확장)

### 5.1 `InputSurface` 확장

현행 `panels.ts`:

```ts
export type InputSurface = 'home' | 'menu' | 'build' | 'panel' | 'course' | 'aiming';
export interface HomeInputOwnership { goals: boolean; ticker: boolean; bar: boolean; }
```

제안 — **`header`를 소유권 축에 추가**하고 `panel`을 두 종류로 나눈다:

```ts
export type InputSurface =
  | 'home' | 'menu' | 'build' | 'aiming' | 'course'
  | 'sheet'      // 하단 시트 (.ksheet) — 지도 위 절반이 보인다
  | 'overlay'    // 전면 (.kover full-bleed) — 지도를 덮는다
  | 'dialog';    // 가운데 상자 (.kover.dialog) — 스크림 위 결정

export interface HomeInputOwnership {
  goals: boolean;
  ticker: boolean;
  bar: boolean;
  header: boolean;   // ← 신규
}
```

| surface | goals | ticker | bar | **header** | 지도 입력 | 시간 |
|---|---|---|---|---|---|---|
| `home` | ✅ | ✅ | ✅ | ✅ | 탭=정보 | 흐름 |
| `menu` / `build` / `sheet` | ✕ | ✕ | ✕ | ✅ | ✕ | 정지 |
| `aiming` | ✕ | ✕ | ✕ | ✅ | 팬=조준 | **정지** (K47-③ 보존) |
| `course` | ✕ | ✕ | ✕ | ✅ | 핸들 드래그 | 정지 |
| **`overlay`** | ✕ | ✕ | ✕ | **✕** | ✕ | 정지 |
| **`dialog`** | ✕ | ✕ | ✕ | ✅ | ✕ | 정지 |

**핵심 변경 하나:** `overlay`(결산 · 도감 · 새 게임)만 헤더를 내린다. §1.4의 겹침이 사라진다.

### 5.2 「위험도 상시 표시」 불변식 보전

CLAUDE.md: *"위험도는 **상시 표시** (K47-② 부터 헤더 2줄째)"*.
헤더를 내리면 이 문장과 충돌한다. **불변식을 깨지 않고 지키는 방법**:

> `overlay` 표면은 자기 머리에 **`.kover-head`** 를 갖는다.
> 필수 3항목: `주 N · 계절` · `◎ 현금` · `위험도 <단계>`.
> 즉 위험도는 여전히 **모든 순간 화면에 있다** — 그리는 주체만 헤더에서 그 표면으로 넘어간다.

`.kover-head`는 새 표면이 아니라 `.ksheet-head`와 같은 층의 **머리 컴포넌트 하나**다
(표면 셋 규칙 유지: 시트 · 전면 · 떠 있는 것).
`.kover-head`에는 `닫기`가 **고정**으로 들어간다 → §1.4의 "닫기가 1,161px 아래" 문제도 같이 닫힌다.

### 5.3 시트 스택 (하위 화면의 구현 형태)

L2/L3는 **새 패널이 아니다.** `PanelHost`의 "한 번에 하나"를 깨지 않기 위해,
`kairo-hud`의 시트 하나가 **스택**을 갖는다.

```ts
interface SheetScreen { id: string; title: string; render(host: HTMLElement): void; }
class SheetStack {
  push(screen: SheetScreen): void;   // head 에 `‹` 가 생긴다
  pop(): void;                        // 한 단계 뒤로
  reset(): void;                      // 인덱스로
}
```

- 시트 머리 = `[‹ 뒤로]? [제목] [닫기]` — `닫기`는 **언제나** 오른쪽 끝, 스택 깊이와 무관.
- 스택 깊이 상한 **2** (인덱스 → L2). L3는 별도 패널(`.ksheet`/`.kover`)이고 그때는 `PanelHost`가 전환한다.
- `PanelHost` API는 그대로다. 시트 하나가 여전히 패널 하나다.

### 5.4 뒤로/닫기 규칙 (전 화면 공통)

| 상황 | `‹ 뒤로` | `닫기` | Esc / Android Back | 스크림 탭 |
|---|---|---|---|---|
| L1 인덱스 | 없음 | 홈 | 홈 | — |
| L2 (시트 스택) | L1 인덱스 | 홈 | `‹`와 같다 | — |
| L3 시트 (`.ksheet`) | 없음 | 홈 | 홈 | — |
| `overlay` (결산·도감·새 게임) | 없음 | 홈 | 홈 | ✕ (오조작 방지) |
| `dialog` — 카드 | 없음 | **없음** (선택 필수) | **무시** | ✕ |
| `dialog` — 축하(해금·엔딩) | 없음 | 있음 | 닫기 | ✕ |
| `aiming` 확정 바 | 없음 | `취소` | `취소` | — |
| 코스 `edit`/`trial` | — | `취소` | `취소` | — |
| 코스 `review`/`applied` | `다시 조정` | `닫기` | `닫기` | — |

**규칙:** `닫기`는 **항상 홈으로** 간다 (중간 단계로 안 돌아간다). 단계 되돌리기는 `‹ 뒤로`/`취소`만.
지금은 이 둘이 섞여 있다 (메뉴에서 도감을 열면 `닫기`가 홈으로 가지만, 의뢰는 시트 안에 남는다).

## 6. 화면별 명세

각 화면은 **목적 / 진입 / 내용 순서 / 주행동 / 보조행동 / 뒤로·닫기 / 빈·잠김·오류**를 갖는다.
문구는 §7 사전이 정본이고 여기서는 배치만 정한다.

### 6.1 홈 (L0)

- **목적:** "내 리조트가 지금 어떤가"와 "다음에 뭘 하지" 두 가지만.
- **진입:** 기본.
- **내용 순서 (위→아래):**
  1. 헤더 1줄 — 날씨칩 · `주 N 요일 · 계절 · 날씨 · HH:MM` · `◎ 현금`
  2. 헤더 2줄 — `😊 만족` · `👥 방문` · `⭐ 등급` · `위험도 <단계>`
  3. 지도 (전체)
  4. **다음 할 일 밴드** — kicker `다음 할 일` + 라벨 + 상세 + `〉`
  5. **소식 띠** (26px)
  6. 하단 바 — `메뉴` · `건설`
- **주행동:** 다음 할 일 밴드 (동적 목적지).
- **보조행동:** 메뉴 · 건설 · 소식.
- **상시 role 제어:** 정확히 **4개** (밴드 1 + 띠 1 + 바 2). *현행 6개에서 B/C 두 칩이 빠진 결과.*
- **화면 예산:** 세로 ≤24% · 가로 ≤36% (CLAUDE.md 그대로). 밴드가 64px 한 행이므로 v3 예산 안에 든다.
- **부팅 시 카메라:** `frameStartKit()` — 물려받은 시설 전체 bbox를 화면에 맞춘다.
  (`frameCourse`가 이미 같은 일을 코스에 대해 한다. 같은 함수 계열을 하나 더 쓴다.)
- **빈 상태:** 없음 (홈은 항상 값이 있다). 단 `👥 0명 · 😊 0%`는 **첫 주에는 `—`**로 낸다 —
  0%는 실패로 읽히고 실제로는 "아직 안 잼"이다.
- **오류:** 부팅 실패는 `.boot-error` (기존).

**변경 요약:** 티커 fallback 문구 교체(§1.5), 부팅 카메라 프레이밍, `0%→—`. 나머지는 v3 그대로.

### 6.2 L1 메뉴 인덱스

- **목적:** "어디로 갈지 고른다". **여기서 끝나는 행동은 하나도 없다** (오늘 할 일 제외).
- **진입:** 하단 `메뉴`.
- **내용 순서:**
  1. 판 설정 줄 (읽기) — `북한강형 · 물려받은 빠지`
  2. **오늘 할 일** — 아이콘 + 근거(`첫 운영 안내`/`운영 점검`/…) + 라벨 + 상세. 주버튼.
  3. 보조 경고 0~3 (읽기, `⚠` 접두)
  4. `운영 〉` — 부제 = 지금 값 (`요금 100% · 직원 4역할 부족`)
  5. `성장 〉` — 부제 = `의뢰 0/16 · 인증 0/12`
  6. `기록 〉` — 부제 = `3주차 결산 · 콤보 5/73`
  7. `설정 〉` — 부제 = `배속 1× · 저장 자동`
- **주행동:** 오늘 할 일.
- **보조행동:** 4개 그룹 행.
- **뒤로/닫기:** `닫기` → 홈.
- **빈 상태:** 없음.
- **잠김:** 없음 (그룹은 항상 열린다. 잠김은 그 안에서 말한다).

> **왜 그룹을 4개로 유지하나:** `MANAGEMENT_GROUPS`(운영/성장/기록)는 sim 상수이고
> `todayRecommendation`이 그 `ManagementAction`만 고른다. **`설정`을 그 배열에 넣지 않는다** —
> 넣으면 오늘 할 일이 "새 게임을 시작하세요"를 추천할 수 있다 (`kairo-management.ts`가 이미
> 같은 이유로 설정을 분리해 뒀다). 설정은 표현 계층의 네 번째 행이다.

### 6.3 L2 운영

- **목적:** "지금 돌아가는 것을 조정한다."
- **진입:** 메뉴 › 운영.
- **행 4개** (각 56px, 부제 = 현재값):

| 라벨 | 부제 예 | 여는 곳 |
|---|---|---|
| `가격` | `요금 100% · 정가 대비 만족 영향 없음` | `.ksheet` 경영 → **제목 `가격`**, 탭 없음 |
| `직원` | `4개 역할 부족 · 주급 0` | `.ksheet` → 제목 `직원` |
| `시설 개선` | `개선 가능 12채 · 최고 단계 0채` | `.ksheet` → 제목 `시설 개선` |
| `코스` | `운행 1개 · 이번 주 탑승 0명` | 코스 화면 (§6.7) |

- **§1.3 해결:** `kairo-staff.ts`의 시트 제목이 **탭 선택에 따라 바뀐다** (`경영` 고정 폐기).
  탭 줄은 그대로 두되 (탭 이동은 유용하다) 제목이 현재 탭을 말한다 → 라벨과 제목이 일치(P3).
- **뒤로/닫기:** `‹ 뒤로` → 메뉴 인덱스, `닫기` → 홈.
- **빈:** `시설 개선`에 대상이 없으면 → `전부 최고 단계입니다` (기존 문구 재사용).
- **잠김:** 코스에 선착장이 없으면 행 부제가 `선착장이 없습니다 — 잔교 옆에 선착장을 지으세요`
  이고 탭하면 **건설 시트의 해당 카드**로 간다 (막다른 처방 금지, K37 규칙).

### 6.4 L2 성장 ★ 신설의 핵심

- **목적:** "내 다음 목표가 무엇이고 얼마나 왔나."
- **진입:** 메뉴 › 성장. (그리고 홈 밴드가 B/C 목표를 가리킬 때의 목적지.)
- **내용 순서:**
  1. **중기 목표(B)** 한 행 — 아이콘 + `중기` 배지 + 라벨 + 상세 + 진행 막대
  2. **장기 목표(C)** 한 행 — 같은 모양, `장기` 배지
  3. 구분선
  4. `심사 〉` — 부제 = **`examItemView`의 실문장** (§1.2가 죽인 그것을 여기서 되살린다)
     예: `2등급 등록 빠지 — 예상 0/30 · 커트 23점 · 평판 55 필요(지금 0)`
  5. `의뢰 〉` — `0/16 진행 중` · **`16종 전량`** 목록으로
  6. `소원 〉` — `열린 소원 3 · 인물 8명`
  7. `인증 〉` — `0/12 · 정원 +0`
  8. `단골 〉` — `민지 1단계 · 수연 대기`
  9. `도감 〉` — `콤보 5/73 · 시설 7/75 · 장비 0/19`
- **주행동:** 없음 (전부 동등한 목적지). **오늘 할 일이 주행동을 이미 가졌다.**
- **뒤로/닫기:** `‹ 뒤로` / `닫기`.
- **L3 목록 화면 공통 규칙** (의뢰·소원·인증):
  - 머리에 **필터 칩** `진행 중 | 완료` (기본 `진행 중`), 오른쪽에 `N/M`.
  - 행 = `아이콘 · 이름` / 진행 막대 / `조건 → 보상` 한 줄.
  - **잘라내지 않는다** — 현행 의뢰 `slice(0, 6)` 폐기 (P3-C③이 지적한 것과 같은 종류).
  - `완료` 필터에서만 완료분을 보여 준다. `인증`은 예외로 완료분을 **아래에 ✓로 남긴다**
    (CLAUDE.md: "정원 +N이 어디서 왔는지 화면에 남아야 한다").
  - **빈 상태:** `진행 중`이 0이면 → 아이콘 + `지금 열린 의뢰가 없습니다` + `다음 의뢰는 2등급에서 열립니다`
    + 버튼 `심사 보기`.
  - **잠김:** 조건 미달 항목은 회색이 아니라 **정상 밝기 + `· ` 미충족 마커**. (심사 화면의 성공 패턴 이식.)
- **⚠ DOM 손잡이 보존:** `#kairo-quests-list` · `#kairo-regular-list` · `#kairo-cert-list` ·
  `#kairo-quests` 는 **id를 그대로 옮긴다**. `tools/verify-kairo.ts`가 시트가 닫힌 채로
  `#kairo-quests`의 textContent를 읽는다 (`main.ts` P3-E 주석이 명시). §11-T5 참조.

### 6.5 L2 기록

- **목적:** "지난 일과 성취를 다시 본다."
- **행 3개:**

| 라벨 | 부제 | 여는 곳 |
|---|---|---|

### 6.6 L2 설정 ★ 위치 이동

- **목적:** "판 자체를 다룬다."
- **진입:** 메뉴 › 설정 (인덱스 **마지막 행**, 예측 가능한 자리).
- **소절 3개:**

| 소절 | 항목 | 형태 |
|---|---|---|
| `진행` | `배속` | 토글 버튼, 부제 `현재 1× · 탭하면 2×` (현행 유지) |
| `소리` | `효과음` · `음악` | **자리표시** — `준비 중입니다` disabled. (`SilentAudio` 슬롯이 이미 있다) |
| `저장 및 새 게임` | `자동 저장` (읽기) · **`새 게임 시작`** | 후자는 `danger` |

- **`새 게임 시작` 파괴 확인 2단** (현행: 맵/시나리오 선택 → `window.confirm`):
  1. L3 `새 게임` 화면 — **제목을 `새 게임`으로 통일** (현행 `새 판`, §1.8).

  2. 주버튼을 누르면 같은 화면 안에서 **확인 상태**로 바뀐다 (`window.confirm` 폐기):
     - 제목 `지금 판을 지웁니다`
     - 본문 `주 3 · 시설 12채 · 현금 684만 — 되돌릴 수 없습니다`  ← **지워지는 것을 숫자로 말한다**
     - `취소` (기본 강조) / `지우고 시작` (danger)
  - 브라우저 네이티브 다이얼로그를 쓰지 않는 이유: 게임 밖 표면이라 크림 팔레트·44px·
    한국어 문구 계약이 전부 안 걸린다. 또 iOS 홈 화면 PWA에서 모양이 다르다.
- **뒤로/닫기:** `‹ 뒤로` / `닫기`. 확인 상태에서 `‹`는 **선택 화면으로만** 돌아간다.

### 6.7 코스 (L3, 화면 주인공)

기존 4단계(`create/info/edit/trial/review/applied`)와 `courseDockActions` **정체를 그대로 쓴다.**

## 8. 빈 / 잠김 / 오류 상태 규격

**하나의 레시피를 전 화면이 공유한다. 새 컴포넌트 클래스를 만들지 않는다** — 기존
`.kcaption` + `.kitem.wide` + `.kbtn` 조합으로 낸다.

### 8.1 빈 (Empty)

```text
[아이콘 32px]
<사실 한 줄>            15px / 800   — "무엇이 없다"
<방법 한 줄>            13px / 700   — "무엇을 하면 생긴다" (수치 포함)
[그 방법으로 가는 버튼]  44px         — 있으면. 막다른 길이면 만들지 않는다
```

- **금지:** `없음` 한 단어. `—`. 빈 상자.
- **근거:** 결산 처방(K37)·건설 카드(K40)·심사(K48)가 이미 "이유 + 방법"을 쓴다. 규칙을 전역화하는 것뿐.

### 8.2 잠김 (Locked)

```text
<이름>                  정상 밝기 (회색으로 죽이지 않는다)
막힘 · <이유>            13px
해제 · <방법>            13px
```

- 버튼은 `disabled` + `aria-disabled` 둘 다.
- **회색으로 죽이지 않는 이유:** K48이 심사에서 검증한 것 — "자격이 없을수록 더 보여야 한다."
  회색은 "지금 볼 필요 없다"로 읽혀 다음 목표를 숨긴다.
- **예외:** 티저(`teaser`)는 회색 유지 (아직 존재하지 않는 것과 지금 못 하는 것은 다르다).

### 8.3 오류 (Error)

| 종류 | 표면 | 문구 규격 | 예 |
|---|---|---|---|
| 행동 거절 (되돌릴 수 있음) | **토스트** | `<대상> — <이유>` | `석재 보도 — 현금이 부족합니다 (필요 1만)` |
| 배치 거절 | **확정 바 `.place-label`** | `<이유> — <방법>` | `길이 닿은 쪽이 없습니다 — 건물 옆에 길을 까세요` |
| 결제 거절 (코스) | **코스 `.kcourse-why`** | `변경비 N만 — 현금이 부족합니다` | 기존 |
| 저장 실패 | **토스트** (신설) | `저장하지 못했습니다 — 저장 공간을 확인하세요` | localStorage quota |
| 캔버스 캡처 실패 | 감상 띠 | 기존 (`?px=1 로 띄우면 저장됩니다`) | 유지 |
| 부팅 실패 | `.boot-error` | 제목 + `<pre>` 스택 | `<pre>` 11.5px → 13px |

- **토스트는 절대 유일한 증거가 아니다** (v3 규칙 계승). 상태가 바뀌었으면 그 화면이 새 값을 보인다.
- **오류가 사라진 뒤 화면이 옛 상태로 남지 않는다** — 거절된 행동은 상태를 안 바꾼다
  (`confirmEdit`의 stale/invalid 계약과 같은 원리).

### 9.3 CLAUDE.md와의 **명시적 충돌 3건** — 문서를 고쳐야 한다

이 셋은 지금 CLAUDE.md 문장과 어긋난다. **몰래 어기지 말고 문서를 같이 고친다.**

1. **「목표는 A·B·C 정확히 세 칸」 / 「홈의 상시 역할 제어는 6개」**
   → UI v3가 이미 홈을 `다음 할 일` 한 줄로 바꿨다. 이 문서는 그것을 따르고
   **B/C는 `성장` 화면이 소유**한다. 목표 **파생 3개**는 그대로다(새 상태 없음).
   CLAUDE.md 문장을 `홈은 즉시 목표 1 · 중장기는 메뉴 성장 절 · 상시 역할 제어 4개`로 고친다.
2. **「위험도는 상시 표시 (헤더 2줄째)」**
   → `overlay`가 헤더를 내리므로 §5.2의 `.kover-head` 규칙을 CLAUDE.md에 추가한다:
   *"헤더를 내리는 표면은 자기 머리에 주차·현금·위험도를 싣는다."*
3. **「뉴스가 없을 때 티커는 현재 A 목표를 힌트로 보여 준다」**
   → A 밴드가 이미 같은 문장을 말하므로 **채널 중복**이다. `소식 없음 · 탭하면 알림함`으로 고친다.
   CLAUDE.md의 그 줄을 대체한다.

| **오늘 할 일이 설정을 추천한다** | `MANAGEMENT_GROUPS`에 `settings`를 넣으면 발생 | 넣지 않는다. §6.2 근거 |

## 15. 완료 정의

**자동으로 증명할 것 (에이전트가 판정)**

1. `npm run typecheck` · `lint` · `test` · `gate` · `build` 통과.
2. `npm run verify:kairo` 4절 통과 + 신규 게이트 G1~G14 통과, **각 게이트의 음성 대조군이 실제로 빨간불**.
3. 393×852와 852×393 둘 다에서:
   - 보이는 enabled control 전부 5점 `elementFromPoint` 자기 소유
   - 뷰포트 밖에 반쯤 걸친 버튼 **0**
   - 어떤 시트도 `scrollHeight / clientHeight ≤ 3.0`
   - 열린 모든 표면에서 종료 컨트롤이 스크롤 없이 도달
   - production `font-size` 12px 미만 **0**
   - 콘솔 오류 **0** · 요청 실패 **0**
4. `npm run sim:kairo -- --seeds 12 --weeks 26` 현금 5분위가 **변경 전과 동일**.
5. 세이브: 기존 v8 세이브를 불러도 버전·필드·온보딩 커서·경력이 그대로.

**사람이 승인할 것 (에이전트가 대신 판정하지 않는다)**

1. 무라벨 A/B — 현재 메뉴 vs 새 인덱스, 세로·가로 각 1장.
2. 설명 없이 **30초 안에** `새 게임 시작`을 찾는다.
3. 설명 없이 **의뢰 진행 상황**과 **인증 몇 개 남았는지**를 찾는다.
4. 설명 없이 건설 1회 → 종료, 코스 조정 → 시험 → 적용 확인.
5. 결산을 열고 **스크롤 없이** 닫는다.
6. 외부 Quick Tunnel에서 첫 화면·메뉴·성장·건설·결산 승인.

**이 여섯 중 하나라도 미실행이면 「UI 전면 개편 완료」라고 쓰지 않는다** —
`docs/ui-shell-v2-validation.md`가 세운 규칙 그대로다.
