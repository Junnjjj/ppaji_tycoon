## 1. 제품 결정

### 1.1 빌려올 것과 우리 것

- **카이로소프트에서 최대한 그대로 가져올 진행 엔진**
  - 1~2분짜리 즉시 목표
  - 5~10분짜리 이름 있는 단골 요청·발견 사슬
  - 등급·인증·엔딩의 장기 진행률
  - 작은 비차단 보상과 드문 큰 축하
  - 이미 지은 시설을 다시 만지는 메뉴 슬롯·외형 성장
- **빠지 타이쿤의 고유 핵심 장난감**
  - 견인기구 루트 핸들
  - 타는 장비와 견인 보트 조합
  - 스릴·안전·처리량·실제 탑승객의 인과
  - 3~5초 시험 운행과 손님 반응

### 1.2 30초 핵심 루프

> 운행 중 코스를 탭한다 → 핸들 또는 보트를 하나 바꾼다 → 예상 변화량을 본다 → 3~5초 시험 운행을 본다 → 손님 반응·기록·단골 진행을 받는다 → 저장하거나 다시 조정한다.

**합격 기준:** 이 흐름이 결산이나 메뉴 표 없이도 화면에서 이해되어야 한다. 코스 수치만 바뀌고 운행 장면이 같으면 실패다.

### 1.3 장기 반복 루프

> 단골 요청 → 재료 힌트 → 메뉴 발견 → 음식 시설 슬롯에 장착 → 단골이 실제 방문·소비 → 친밀도·새 재료·장비 해금 → 시설/코스 재조정.

일반 손님 1,200명은 수요·대기·공간 인과를 증명하고, 지속되는 개인 서사는 기존 이름 있는 인물 8명이 담당한다.

### P0 — 핵심 코스가 첫 화면에서 발견되지 않는다

- 홈의 상시 행동은 `메뉴`와 `건설` 둘뿐이다.
- 운행 중 코스는 `메뉴 → 코스 1` 안에 묻혀 있다.
- 건설 시트의 `코스` 탭은 새 코스 편집으로 연결되지만 기존 코스를 다시 조정하는 경로가 없다.
- 현재 코스 화면은 “새 코스 생성”으로 열려 시작 킷 코스가 있는 선착장을 보고 `이미 코스가 있습니다`라고 거절한다.

**결정:** 상시 버튼은 기존 2개를 유지한다. 대신 **지도 위 기존 코스 탭**과 **첫 즉시 목표 카드**가 코스 편집의 직접 입구가 된다. 버튼을 늘려 HUD를 덮지 않는다.

### P0 — 코스 화면은 핵심 장난감의 결과를 보여주지 않는다

- 경로와 두 핸들은 보이므로 직접 조작의 기반은 좋다.
- 그러나 접힌 하단 바에는 현재값만 있고 이전값 대비 변화가 없다.
- 프리셋·장비는 의미 없는 `▲` 뒤에 숨는다.
- 확정 뒤 실제 운행·탑승 반응 없이 저장되므로 설계 보상이 결산까지 지연된다.
- 경로 방향, 위험 구간, 출발/귀환이 시각적으로 구분되지 않는다.

**결정:** `▲`를 `설정`으로 바꾸고, 기본 바는 `현재 → 예상 delta`를 보여준다. 주버튼은 처음에는 `시험 운행`, 시험 후에는 `적용`이 된다.

### P1 — 홈 화면은 목표가 많지만 다음 손동작이 없다

- 상단 트레이는 날짜·현금·만족·방문·등급·위험을 한 덩어리로 잘 묶었다. 유지한다.
- 펼친 목표 3장은 좌상단을 길게 차지하지만 모두 진행률 문장이다.
- `첫 손님`, `먹거리를 갖추자`, `2등급까지` 중 무엇을 지금 눌러야 하는지 알 수 없다.
- 티커는 초기 상태에서 `소식이 여기 흐릅니다`라는 자리표시자라 화면의 중요한 26px가 죽어 있다.

**결정:** 목표는 “할 일 A / 단골·운영 B / 성장 C”의 역할이 명확해야 한다. A는 반드시 탭하면 관련 지도 위치 또는 패널로 이동한다. 초기 A는 `물려받은 코스 시험 운행`이다. 뉴스가 없으면 티커는 다음 행동 힌트 또는 현재 붓 상태를 보여주고 자리표시자를 금지한다.

### P1 — 건설 시트는 선택지가 보이지만 결정 정보가 부족하다

- 393px에서 탭 4개 + 닫기, 필터 4개, 양쪽 화살표가 세로·가로 예산을 많이 쓴다.
- 좌우 화살표가 88px를 차지해 실제 카드는 약 2.5장만 보인다.
- 카드 이름이 `코인락커 열…`처럼 잘리고, 크기·가격 외에 “왜 짓는가”가 없다.
- 카드를 탭하면 즉시 시트가 닫혀 고스트로 넘어가므로 기본 조준 흐름은 적절하다.

**결정:** 터치 환경에서는 화살표를 제거하고 스와이프+스크롤 스냅으로 3장 가까이 보이게 한다. 카드에는 `이름 / 가격 / 역할 한 줄 / 제약 또는 효과 아이콘`만 둔다. 상세 스탯을 카드에 우겨넣지 않는다. 선택 후 확정 바에 썸네일·이름·비용·배치 판정 이유를 표시한다.

### P1 — 경영 메뉴가 동일한 버튼 격자라 우선순위가 없다

- 배속, 심사, 새 판, 도감, 감상, 코스, 경영이 같은 버튼 문법으로 나열된다.
- `경영 ⚠4`만 강조되어 핵심 코스보다 오류 처리 메뉴가 주인공처럼 보인다.
- 코스 수와 의뢰 수는 보이지만 “지금 코스를 고쳐야 하는 이유”는 없다.

**결정:** 메뉴 첫 줄에 기존 시스템에서 파생한 **오늘의 추천 1개**를 둔다. 그 아래를 `운영`, `성장`, `기록` 세 묶음으로 나눈다. 코스는 운행 상태·최고 기록·개선 가능 표시가 있는 넓은 항목으로 올린다. 새 독립 목표 시스템은 만들지 않는다.

### P0 — 결산 첫 화면이 사용자의 핵심 질문을 가린다

- 96×72 히트맵이 거의 한 화면을 차지한다.
- 매출·유지비·손익은 아래로 스크롤해야 보인다.
- 매출과 비용의 시각적 그룹이 없고 `입장료`만 매출 하위로 보인다.
- 전주 대비 방문객·매출·손익 변화가 없다.
- 현재 설계 문서의 `히트맵 → 요일 → 구성 → 숫자 → 콤보` 순서는 “숫자표만 보여주지 않는다”는 목적에는 맞지만, 실측 화면에서는 핵심 결과를 첫 화면 밖으로 밀었다.

**결정(의도적 설계 변경):** 순서를 `3 KPI 요약 → 한 줄 처방 → 축소 히트맵 → 요일 → 손님 구성 → 수익/비용 → 콤보`로 바꾼다. 이는 `CLAUDE.md`의 기존 결산 순서를 수정하는 변경이므로 구현 PR에서 문서·테스트를 함께 갱신한다. 히트맵을 없애지 않고 첫 화면 아래쪽에 120~140px 높이로 유지한다.

### P1 — 사건 카드는 읽히지만 매주 보기에는 무겁다

- 현재 전면 모달과 세로 3선택은 오독은 적다.
- 하지만 이미지가 없고, 세 선택지가 같은 흰 직사각형이라 사건의 성격과 결과가 기억되지 않는다.
- 한 번 등장할 때 화면 대부분을 막으므로 매주 1~2장은 흐름을 끊는다.

**결정:** 강제 사건 빈도를 2~4주로 낮추고, 2~3개 선택을 그림 포함 한 행 카드로 바꾼다. 각 선택은 `짧은 동사 / 대표 결과 아이콘·수치`만 표시하고 장문 설명은 사건 본문 한 번으로 끝낸다.

- Modify: existing quests/wishes/exam/certs status adapter
- Test: `src/ui/kairo-goals.test.ts`

**구현 계약**

1. 목표 표시 모델을 UI 파생값으로 만든다.
   - A `immediate`: 관련 행동 callback 필수
   - B `mid`: 기존 quest/wish/course record 중 하나
   - C `long`: exam/cert/ending 진행률
2. 새 저장 상태를 만들지 않는다. 기존 시스템 상태에서 매 프레임이 아니라 상태 변경 시 파생한다.
3. 초기 A는 `물려받은 코스 시험 운행`이며 탭하면 시작 코스를 frame하고 편집한다.
4. 목표는 전체 기둥이 아니라 각 항목이 자신의 목적지로 이동한다. 접기 머리의 stopPropagation 계약 유지.
5. 뉴스가 없을 때 `소식이 여기 흐릅니다`를 금지하고 다음 중 하나를 표시한다.
   - 현재 붓/조준 상태
   - 단골 방문 예정
   - 다음 즉시 목표 힌트
6. 코스·시설 편집 중 목표 기둥은 자동 접고, 종료 시 사용자의 이전 접힘 상태로 복원한다.

**브라우저 검증**

- 초기 A 목표를 진짜 터치 → 기존 시작 코스 편집 화면 진입
- 목표를 접고 지도 팬 가능
- 헤더 버튼 0개, 하단 상시 버튼 2개 유지
- 뉴스 빈 문자열/자리표시자 없음

   - 실제 탑승 ≤ 코스 처리량
   - 코스 수요 0이면 코스 매출 0
2. 기존 코스 편집 API를 추가한다.
   - 자기 자신은 overlap/dock-taken 비교에서 제외
   - 취소는 원본 snapshot을 바이트 단위로 보존
   - 확정은 변경 차액만 지불
3. facing·dock·handles·equipId·vehicles의 기존 뜻을 바꾸지 않는다.
4. 새 optional 필드만 필요하면 v7 유지. 기존 필드 의미 변경이 필요하면 v8 migration을 먼저 작성한다.

즉, 먼저 만드는 것은 예쁜 새 메뉴나 카드가 아니라:

1. 첫 화면에서 시작 코스를 탭할 수 있음
2. 기존 코스를 편집할 수 있음
3. 핸들·보트 변화가 예상 delta로 보임
4. 3~5초 시험 운행이 나옴
5. 손님 반응과 기록이 남음
6. 저장하거나 다시 조정할 수 있음

이 여섯 단계가 빠지 타이쿤의 핵심 재미를 증명한 뒤 메뉴·단골·결산·카드·주변 아트를 확장한다.
