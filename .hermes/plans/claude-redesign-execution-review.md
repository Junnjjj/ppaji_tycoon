### 1.2 왜 "전면 개편"이 아닌가 — 구조적 이유 6가지

#### ① 메뉴는 **더 깊어졌다.** 컨테이너를 안 건드리고 내용만 키웠다

`.ksheet { max-height: min(56vh, 420px) }` (`src/ui/style.css:1198`)는 그대로다.
그 안에 들어가는 내용만 늘었다.

| | 세로 393×852 | 가로 852×393 |
|---|---|---|
| 시트 본문 뷰포트 | **361px** | **161px** |
| 본문 내용 높이 | **1,893px** | **1,893px** |
| 스크롤 화면 수 | **5.2 화면** | **11.8 화면** |
| `.kmanage-action` 총 개수 | 16 | 16 |
| 첫 폴드에 **온전히** 보이는 행동 | **4 / 16** | **1 / 16** |

같은 페이지에서 v2 근사(4열 격자 · 목표 절 없음 · 설정 그룹 없음 · 옛 글자 크기)를
CSS 로 되돌려 재보면 **1,361px** 이다. 즉 이번 변경이 **+532px (+39%)** 를 더했다.
2열 강제(`repeat(2, minmax(0,1fr))`)에는 폭 조건이 없어서 **852px 가로에서도 폰 2열**이
그대로 서고, 결과적으로 가로가 세로보다 **두 배 이상 나쁘다**.

> 계획서 §1.4 는 "393px 에서 4열을 금지하고 최대 2열"만 적었고 **세로 예산을 안 적었다.**
> 열을 반으로 줄이면 행이 두 배가 된다 — 그 산수가 계획에 없다.

#### ② 메뉴 내용의 **48%가 아직 정리 안 된 원문 덤프**다

`#kairo-quests`(의뢰 6 + 소원 + 인증 12) 블록 하나가 **900px** — 본문 1,893px 의 48%.
이 블록은 이번 변경에서 **글자 크기 두 줄**만 바뀌었다 (`.kquests` 11→12px ·
`.kquest-detail` 10→12px). 구조·문구는 그대로다. 실측 문자열:

```
🏅 수상레저 인증
· 1 / 3개  · 5 / 8개 → 정원 +6 · 허가 +40
🏅 종합 인증
· 5 / 32종  · 아직 한 주를 안 돌렸다 → 정원 +18 · 허가 +50
```

**무엇이 1/3개인지 화면 어디에도 없다.** 원인은 `src/sim/kairo/progress.ts:331-408`
(`evaluateCondition`)이 조건의 **주어를 버리고 수량만** 문자열로 만들기 때문이다
(`detail = `${cur} / ${goal}개``). `kind`·`need` 는 그 자리에 살아 있고,
한글 표(`NEED_NAME`)는 이미 `src/ui/kairo-report.ts:33` 에 있다 — **연결이 안 돼 있을 뿐이다.**
같은 줄에 `아직 한 주를 안 돌렸다`(반말 서술)와 `0 / 40칸`(수량)이 섞여 문체도 갈린다.

그리고 메뉴 버튼 `의뢰`·`인증`·`단골` 셋은 **같은 시트를 아래로 스크롤할 뿐이다**
(`src/main.ts:3020` `scrollMenuTo`). 즉 "화면을 연다"는 기대와 실제 동작이 다르고,
같은 정보가 버튼(요약)과 덤프(원문) 두 곳에 서로 다른 문법으로 존재한다.

#### ③ 타이포 계약이 **홈·메뉴·코스 독에만** 적용됐다

계획 §1.3 은 "12px 미만 금지 (디버그/법적 각주 외)"였다. 실제로는 6~7개 선택자만 올랐다.
지금 화면에 살아 있는 12px 미만 (실측, 393×852):

|---|---|---|---|
| 건설 시트 | `.kcard-block` | **9.5px** | `막힘 · 아직 잠김` |
| 건설 시트 | `.kcard-unlock` | **9.5px** | `해제 · 의뢰 「먹거리를 갖추자」 보상` |

#### ④ 삭제된 개념의 문구가 화면에 남아 있다

`src/ui/kairo-ticker.ts:57` 이 여전히 이렇게 낸다:

```
다음: 물려받은 코스 시험 운행 — 목표 A를 탭하세요
```

**`목표 A` 는 이번 변경이 없앤 것이다.** 홈에는 `A` 배지도, B/C 도 없다. 첫 프레임의
상시 띠가 존재하지 않는 UI 요소를 가리킨다 (실측 스크린샷 확인).

같은 종류: 확정 바의 `연속 설치 끔`. `끔`은 **현재 상태(off)** 로도 **명령(꺼라)** 으로도
읽힌다. 켜면 `연속 설치 켬` 이 되므로 라벨만 봐서는 어느 쪽인지 결정 불가다
(`aria-pressed` 는 화면에 안 보인다).

#### ⑤ "무엇을 눌러야 하는가"가 아직 이름으로 안 읽히는 자리

메뉴 실측 라벨/상세 쌍: `감상 / 북한강형` · `엔딩 / 성장 마일스톤` · `의뢰 / 첫 운영 진행 중` ·
`단골 / 메뉴 요청 진행 중`. `기록` 그룹 안에 `엔딩` 이 들어 있다 (엔딩은 기록이 아니다).
계획 §1.4 는 그룹 이름만 정하고 **항목 배치와 문구는 v2 그대로 이식**했다.

#### ⑥ 배치 확정 바가 같은 문장을 두 번 쓴다

`src/main.ts:580` 이 실패 사유를 1번 인자(`label`)로 넘기고,
`src/ui/kairo-hud.ts:584` 가 `view?.result ?? label` 로 같은 문자열을 한 번 더 그린다.
실측(첫 조준):

```
아직 내 땅이 아닙니다 — 등급을 올리면 넓어집니다      ← .kconfirm-check
아직 내 땅이 아닙니다 — 등급을 올리면 넓어집니다      ← .place-label
```

240px 짜리 확정 바(세로의 28%)에서 두 줄이 중복이다. 이 결함은 이번 변경 이전부터
있었고, "전면 개편"이 지나간 화면인데 안 잡혔다.

> 덧붙임(같은 화면): 건설 시트에서 첫 시설을 고르면 레티클이 카메라 초기 위치를 그대로
> 받아 **내 땅 밖**에 선다. 새 판의 첫 건설 시도가 언제나 빨간 거절로 시작한다.

### 2.5 외부 정체 다이제스트는 **구조적으로 못 맞는다**

* 서버를 다시 안 띄우면 **항상 거짓 실패**, 그리고
* 서버를 다시 띄우면 통과하지만 **터널 반대편 폰이 옛 모듈을 들고 있을 수 있다**
  (메모리 노트 `stale-vite-verify-mobile` 과 같은 함정).

**외부 승인 절차는 "서버 재기동 → 하드 리로드 → `--identity` → 캡처" 순서로 고정해야
의미가 있다.**
